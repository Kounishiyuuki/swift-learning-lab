## 01. Xcode：Project・Target・Scheme・Build Configuration [Beginner]

概要: Xcodeの設定単位を区別し、どこを変更しているのか理解する。
考え方: Projectは入れ物、Targetは製品、Schemeは実行/テストの組み合わせ、ConfigurationはDebug/Release等の設定set。

重要ポイント:
- Projectは複数Targetを含められる。
- TargetごとにBundle ID/Build Settings/Capabilities。
- SchemeでRun/Test/Profileを構成。
- Debug/Releaseで設定や最適化を分ける。

コード:
```swift
// Project -> Target -> Build Settings
// Scheme -> Run / Test / Profile -> Configuration
```

なぜ重要か: Xcode errorの多くは『どのTarget/Schemeか』を理解すると追いやすい。
注意: ProjectとTargetを混同すると変更が反映されない原因になる。

確認問題:

```swift

```
A. Target
B. Git branch
C. Function
D. Array
正解: A
解説: app Targetごとに製品設定を持つ。

Q2. Schemeが主に決めるものは？ [Beginner]
```swift
Run / Test / Profile
```
A. どのTarget/Configurationで実行するか
B. JSON key
C. 継承
D. HTTP status
正解: A
解説: Run/Test/Profile等のactionを構成する。

- Package.swiftにproduct/target/dependency。
- Library/Executable等product。
- Target間依存を明示。

なぜ重要か: library導入、自作共通層、test可能なModule分割で必須。

## 20. Architecture・Git・Security・API Design [Intermediate]

概要: 責務分離、変更管理、安全性を実装と同じレベルで扱う。
考え方: 良い開発は『動くcode』だけでなく、変更可能・検証可能・安全な境界を作る。

- View→ViewModel→Repository等で責務分離。
- git status/diff/小さなcommit/PR。
- secret/tokenをcommitしない。

コード:
```swift

git status
git diff
// Never commit secrets
```

なぜ重要か: 個人開発でも規模が増えるほど差が出る。
注意: pattern名を守ることより、責務・依存方向・安全境界が明確かを見る。
