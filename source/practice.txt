### practice-starter-001 let・var・= の役割を対応づける [対応づけ / Lv1 ガイド]
対象レッスン: starter-let-var
シリーズ: starter-letvar (1段階目)
スキル: syntax, types
問題: Swiftの「値を置いておく箱」に関する用語と、その意味を対応させてください。
対応:
- let → 一度決めたら値を変えられない名前を作る
- var → あとから値を変えられる名前を作る
- = → 右側の値を左の名前に入れる
- score → プログラマが決めた名前そのもの
ヒント1: まず「変えられるか / 変えられないか」で2つに分けて考えます。
ヒント2: `=` は数学のイコール（等しい）ではありません。右で計算した結果を左に入れる指示です。
ヒント3: `let score = 10` の4つの部分は「変えない宣言」「名前」「入れる指示」「値」に分かれます。`score` は言語のキーワードではありません。
解説: letは値を変えない名前、varは変えられる名前を作ります。=は「等しい」ではなく「右の値を左の名前に入れる」代入の指示です。scoreはSwiftが決めたキーワードではなく、書く人が自由に決めた名前です。
- 使っている考え方: 変数宣言は『変えられるかどうか(let/var)』『名前』『代入(=)』『値』の4つの部品でできています。この分解ができると、あとで出てくるほぼすべてのコードが読めるようになります。
- 手順: `let score = 10` を左から読むと、まず `let` が「これから作る名前は変更しない」と宣言している。
- 手順: 次の `score` は名前。Swiftが用意した単語ではなく、書く人が付けた識別子。
- 手順: `=` は代入。右側 `10` を評価してから、その結果を `score` に入れる。
- 手順: 結果として、以降 `score` と書けば `10` が取り出せる。
- 動く理由: letは再代入を禁止する宣言、varは許可する宣言で、両者の違いは「あとで値を入れ替えられるか」だけです。=は左右が等しいという主張ではなく、右から左へ値を移す動作なので、`score = score + 1` のような一見おかしい式も成り立ちます。
- よくある間違い: `=` を数学の等号だと思い込むと、`x = x + 1` が矛盾に見えて読めなくなります。実際は「今のxに1を足した値を、新しくxに入れる」動作です。
- よくある間違い: `let` を「変数」と覚えると、あとで再代入しようとして 'Cannot assign to value' のコンパイルエラーになります。
- 関連例:
```swift
var score = 10
score = score + 5
print(score)
```
- 関連例の出力: 15
- 関連例の説明: varなので再代入できます。右辺 score + 5 が先に計算されて15になり、その15がscoreに入ります。
- 覚えておくこと: let/varは「変えられるか」、=は「右の値を左に入れる」。この2点だけで代入の行はすべて読めます。

### practice-starter-002 変わる値と変わらない値を書き分ける [穴埋め / Lv1 ガイド]
対象レッスン: starter-let-var
シリーズ: starter-letvar (2段階目)
スキル: syntax
問題: 税率は途中で変わらず、合計金額は計算のたびに変わります。それぞれに合うキーワードを選んでください。
埋めたあと:
```swift
let taxRate = 0.1
var total = 1000
total = total + 200
print(total)
```
ヒント1: あとの行で値が書き換えられているのはどちらの名前かを探してください。
ヒント2: 書き換えられる名前は「変更を許可する宣言」で作る必要があります。書き換えない名前は変更を禁止したままにします。
ヒント3: 3行目に `total = total + 200` があります。この行が成立するには、totalが変更可能な宣言でなければなりません。taxRateは一度も書き換えられていません。
解説: taxRateはこのコードの中で一度も書き換えられないのでletが適切です。totalは3行目で再代入されるため、変更を許可するvarでなければコンパイルエラーになります。迷ったらまずletで書き、書き換えが必要になったときだけvarに変えるのがSwiftの基本方針です。
- 使っている考え方: let（定数）とvar（変数）の使い分けは、コードを読む人に「この値はあとで変わるのか」を伝えるための情報でもあります。Swiftはlet優先で書くのが標準です。
- 手順: 1行目のtaxRateは、以降どこにも代入がない。つまり変更されない値。
- 手順: 2行目のtotalは、3行目で `total = total + 200` と再代入されている。
- 手順: 再代入がある名前をletで宣言すると、コンパイル時に 'Cannot assign to value: total is a let constant' となる。
- 手順: したがって taxRate は let、total は var。
- 動く理由: letは再代入を禁止するため、書き換えのないtaxRateに使えば「この値は固定」と保証できます。totalは加算した結果を入れ直す必要があるので、再代入を許可するvarでなければ3行目が通りません。
- よくある間違い: すべてvarで書いてしまうと、本来変わらないはずの値がどこかで書き換わってもコンパイラが警告してくれません。
- よくある間違い: letにしたまま再代入すると、実行以前にビルドが失敗します。エラーメッセージは 'Cannot assign to value' です。
- 関連例:
```swift
let taxRate = 0.1
var total = 1000
total = total + 200
print(Double(total) * taxRate)
```
- 関連例の出力: 120.0
- 関連例の説明: letのtaxRateは読み出すだけ、varのtotalは書き換えられます。役割の違いが宣言に表れています。
- 覚えておくこと: まずletで書き、再代入が必要になった行が出てきたときだけvarに変える。

### practice-starter-003 letなのに書き換えている行を見つける [バグ発見 / Lv1 ガイド]
対象レッスン: starter-assignment
シリーズ: starter-letvar (3段階目)
スキル: syntax, debugging
問題: このコードはビルドできません。原因になっている行を選んでください。
問題のある行: count = count + 1
ヒント1: エラーは「値を入れ替えている行」で起きています。宣言のしかたと見比べてください。
ヒント2: letで作った名前には、あとから別の値を入れられません。letで宣言された名前がどれかを先に確認します。
ヒント3: 1行目は `let count`、2行目は `var message` です。書き換えている行は3行目と4行目の2つあります。そのうちletの名前を書き換えているのはどちらでしょうか。
解説: 4行目の `count = count + 1` が原因です。countは1行目でletとして宣言されているため再代入できず、コンパイラは 'Cannot assign to value: count is a let constant' を出します。3行目のmessageはvar宣言なので書き換えても問題ありません。
- 使っている考え方: letは「この名前には最初に入れた値しか入らない」という約束です。約束を破る行があると、実行前のコンパイル段階でエラーになります。実行時エラー（クラッシュ）ではない点が重要です。
- 手順: 1行目: `let count = 3` で、countは変更不可として作られる。
- 手順: 2行目: `var message = "start"` で、messageは変更可として作られる。
- 手順: 3行目: messageへの再代入。varなので許される。
- 手順: 4行目: countへの再代入。letなので許されず、ここでビルドが止まる。
- 動く理由: エラーは「宣言のしかた」と「使い方」が食い違っている場所で起きます。4行目だけがletの名前を書き換えているので、そこが原因です。
- よくある間違い: 3行目も代入なので同じエラーだと考えてしまう間違いがあります。messageはvarなので合法です。代入の有無ではなく、宣言がletかvarかで決まります。
- よくある間違い: countをvarに変えずに `let count = count + 1` と書き足すと、同じスコープで同じ名前を2回宣言する別のエラー（Invalid redeclaration）になります。
- 関連例:
```swift
var count = 3
count = count + 1
print(count)
```
- 関連例の出力: 4
- 関連例の説明: 宣言をvarに変えれば4行目は通ります。カウンタのように増えていく値はvarで宣言します。
- 覚えておくこと: コンパイルエラーは実行前に出る。letへの再代入はその典型で、直す場所は代入行かもしれないし宣言行かもしれない。

### practice-starter-004 letへの再代入を直す [修正 / Lv2 基本]
対象レッスン: starter-assignment
シリーズ: starter-letvar (4段階目)
スキル: syntax, debugging
問題: 1行目を書き換えて、このコードがビルドできるようにします。適切な修正を選んでください。
正解: var total = 0
ヒント1: ループの中でtotalの中身が増えていきます。その動きを許す宣言に変える必要があります。
ヒント2: 型を変えても再代入の可否は変わりません。変えるべきはletかvarかの部分です。
ヒント3: 合計は Int のまま、宣言だけを「変更可能」にします。`var total = 0` と書けば 0 から始まる整数のカウンタになります。
解説: letは再代入を禁止するので、ループで合計を足し込む書き方と両立しません。`var total = 0` に変えると再代入が許可され、120と80が順に足されて200が出力されます。型を Double や String に変えても再代入の禁止は解けず、むしろ Int との計算でエラーが増えます。
- 使っている考え方: 「値をためていく変数」はアキュムレータと呼ばれ、初期値を入れてから繰り返しの中で更新します。更新が前提なのでvarで宣言します。
- 手順: totalを0で初期化する。ここが合計の出発点。
- 手順: forで配列の要素を1つずつpriceに取り出す。
- 手順: `total = total + price` で、今のtotalにpriceを足した結果を改めてtotalに入れる。letだとこの再代入ができない。
- 手順: ループが終わるとtotalは120+80=200になり、printで200が出る。
- 動く理由: var total = 0 は「Intの0から始まり、あとで書き換えられる名前」を作ります。ループ内の再代入が合法になり、他の行を一切変えずに動くようになります。
- よくある間違い: `let total: Int = 0` のように型注釈を足す修正は、エラー原因が型だと誤解した結果です。エラーは型ではなく再代入の可否なので直りません。
- よくある間違い: `var total: String = "0"` にすると再代入はできますが、`"0" + price` はStringとIntの加算になり別のコンパイルエラーになります。
- 関連例:
```swift
var total = 0
for price in [120, 80] {
    total += price
}
print(total)
```
- 関連例の出力: 200
- 関連例の説明: `total = total + price` は `total += price` と短く書けます。意味は同じで、varでなければ使えない点も同じです。
- 覚えておくこと: エラーメッセージが 'Cannot assign to value' なら、直すのは代入行ではなく宣言のlet/varであることが多い。

### practice-starter-005 代入のあと、値はどうなっているか [実行追跡 / Lv1 ガイド]
対象レッスン: starter-values
シリーズ: starter-values (1段階目)
スキル: syntax, controlFlow
問題: 上から順に実行したとき、最後のprintで表示される内容を選んでください。
正解: 8 3
ヒント1: `a = b` を実行した時点でのbの値が、そのままaに入ります。
ヒント2: 代入はコピーです。`a = b` のあとにbを変えても、aは巻き込まれません。
ヒント3: 3行目でaは8になります。4行目でbだけが3に変わります。aは8のままです。
解説: `a = b` は「その瞬間のbの値をaにコピーする」動作です。3行目でaは8になり、4行目のbへの代入はaに影響しません。したがって最後の状態は a=8、b=3 で、「8 3」が表示されます。
- 使っている考え方: Int のような値型の代入は、名前どうしを結びつけるのではなく、値そのものを複製します。片方を変えてももう片方は変わりません。
- 手順: 1行目: aに5が入る（a=5）。
- 手順: 2行目: bに8が入る（a=5、b=8）。
- 手順: 3行目: `a = b` によって、bの現在値8がaにコピーされる。a=8、b=8。
- 手順: 4行目: `b = 3` でbだけが3になる。a=8、b=3。
- 手順: 5行目: print(a, b) は値をスペース区切りで出力するので「8 3」。
- 動く理由: 3行目でコピーされるのは「bという名前」ではなく「その時点の値8」です。そのため4行目のbの変更はaに伝わらず、a=8、b=3のまま出力されます。
- よくある間違い: `a = b` を「aとbが同じものを指す」と読むと、4行目のあとaも3になると誤解します。Intではリンクは作られません。
- よくある間違い: print(a, b) をカンマ区切りの文字列だと思うと「8,3」と答えてしまいます。実際の区切りは半角スペースです。
- 関連例:
```swift
var a = 5
var b = 8
a = b
b = 3
print(a)
print(b)
```
- 関連例の出力: 8
3
- 関連例の説明: 1行ずつprintすると、aが8、bが3であることがはっきり確認できます。
- 覚えておくこと: 値型の代入はコピー。代入後に元の名前を変えても、コピー先は変わらない。

### practice-starter-006 挨拶を表示するのに必要な行だけ選ぶ [ブロック選択 / Lv1 ガイド]
対象レッスン: starter-read-line-by-line
シリーズ: starter-values (2段階目)
スキル: syntax, controlFlow
問題: 「Hello, Yuki」と1行だけ表示したいです。必要な行だけを選び、実行順に並べてください。
使うブロック:
- let name = "Yuki"
- print("Hello, " + name)
ヒント1: 表示したいのは1行だけです。printが2回実行されると2行出てしまいます。
ヒント2: 使う値を先に用意してから、それを使う行を書きます。使わない値の行は不要です。
ヒント3: 必要なのは名前を用意する行と、その名前を使って挨拶を組み立てるprintの2行です。ageの行とnameの再代入は結果に関係しません。
解説: 必要なのは `let name = "Yuki"` と `print("Hello, " + name)` の2行だけです。ageは表示に使われず、`print(age)` を入れると余計な行が出力されます。また `name = "Taro"` はletへの再代入なのでコンパイルエラーになり、そもそも含められません。プログラムは上から順に読まれるので、nameを使う行より前でnameを用意する必要があります。
- 使っている考え方: 「何を書く必要があるか」を判断するには、まず求められている出力から逆算します。出力に関係しない行はノイズであり、コードを読みにくくするだけです。
- 手順: 目標は「Hello, Yuki」という1行の出力。
- 手順: そのprintには name の値が必要なので、printより前に name を用意する行が要る。
- 手順: ageは出力に一切登場しないので不要。print(age)を足すと余計な1行が出る。
- 手順: `name = "Taro"` はletで作った名前への再代入なのでビルドが通らない。
- 動く理由: 上から順に実行されるため、値を作る行 → 値を使う行の順に並べる必要があります。この2行だけで「Hello, Yuki」が過不足なく出力されます。
- よくある間違い: 順番を逆にすると、nameがまだ存在しない位置で使うことになり 'Cannot find name in scope' になります。
- よくある間違い: 「あっても害がなさそう」とage関連の行を残すと、出力が2行になり要件を満たしません。
- 関連例:
```swift
let name = "Yuki"
print("Hello, " + name)
```
- 関連例の出力: Hello, Yuki
- 関連例の説明: 文字列同士は + でつなげます。"Hello, " の末尾のスペースがそのまま出力に残る点にも注目してください。
- 覚えておくこと: 必要な行は出力から逆算する。使われない値の行は、動いても要件違反になることがある。

### practice-starter-007 上から順に実行される順番に直す [並べ替え / Lv1 ガイド]
対象レッスン: starter-read-line-by-line
シリーズ: starter-values (3段階目)
スキル: syntax, controlFlow
問題: 「合計は 300 です」と表示したいです。ブロックを正しい実行順に並べ替えてください。
正解の並び:
```swift
let apple = 120
let orange = 180
let total = apple + orange
print("合計は \(total) です")
```
ヒント1: Swiftはファイルの上の行から順に実行します。使う値は、使う行より前に用意します。
ヒント2: totalを計算するには、appleとorangeの両方がすでに存在している必要があります。
ヒント3: apple → orange → total（2つを足す）→ print の順です。printは最後に来ます。
解説: Swiftのコードは上から順に実行されるため、値は使う前に用意しておく必要があります。appleとorangeを先に作り、その2つからtotalを計算し、最後にtotalを使ってprintします。printを先頭に置くと、まだtotalが存在しないため 'Cannot find total in scope' というコンパイルエラーになります。
- 使っている考え方: 文字列補間 `\(total)` は、文字列の途中に値を差し込む書き方です。差し込む値はその行に到達した時点で存在していなければなりません。
- 手順: `let apple = 120` でappleが使えるようになる。
- 手順: `let orange = 180` でorangeが使えるようになる。
- 手順: `let total = apple + orange` は右辺を先に計算する。120+180=300がtotalに入る。
- 手順: `print("合計は \(total) です")` で、totalの300が文字列に埋め込まれて出力される。
- 動く理由: 各行が必要とする値が、その行より前で必ず用意されているためです。依存関係の順（apple・orange → total → print）に並べたときだけコンパイルが通ります。
- よくある間違い: printを先頭に置く並びは、実行順ではなく「結論から書く」文章の感覚に引きずられた間違いです。コードでは材料が先です。
- よくある間違い: totalの行をappleより前に置くと、appleが未定義のためやはりスコープエラーになります。
- 関連例:
```swift
let apple = 120
let orange = 180
let total = apple + orange
print("合計は \(total) です")
```
- 関連例の出力: 合計は 300 です
- 関連例の説明: \(total) の部分がtotalの値に置き換わります。文字列の中に計算結果を混ぜたいときの標準的な書き方です。
- 覚えておくこと: コードは上から下へ。値は「作る → 使う」の順にしか書けない。

### practice-starter-008 変数を宣言する1行を書く [記述 / Lv1 ガイド]
対象レッスン: starter-assignment
シリーズ: starter-values (4段階目)
スキル: syntax
問題: あとで書き換える予定の整数 count を、初期値 0 で用意する1行を書いてください。
想定する書き方: var count = 0
ヒント1: あとで書き換えるので、変更を許可する宣言が必要です。
ヒント2: 「宣言のキーワード」「名前」「=」「初期値」の4つを並べます。名前は count、初期値は 0 です。
ヒント3: 変更可能な宣言キーワードのあとに `count = 0` と続けます。型注釈は省略でき、0からIntと推論されます。
解説: `var count = 0` と書きます。varはあとから書き換えられる名前を作る宣言で、= の右の 0 が初期値です。0はIntリテラルなのでcountの型はIntと推論され、`var count: Int = 0` と書いても同じ意味になります。letで宣言すると、次に予定している `count = count + 1` が再代入エラーになります。
- 使っている考え方: 宣言は「変更可否のキーワード + 名前 + = + 初期値」でできています。Swiftは初期値から型を推論するので、多くの場面で型注釈は省略できます。
- 手順: あとで書き換える予定なので、変更可能な宣言 var を選ぶ。
- 手順: 名前は問題文で指定された count。
- 手順: = の右に初期値 0 を書く。0 は整数リテラルなので Int と推論される。
- 手順: 結果として `var count = 0` の1行になる。
- 動く理由: varは再代入を許可するため、このあとの `count = count + 1` が合法になります。初期値0によって型がIntに決まり、整数の加算がそのまま書けます。
- よくある間違い: `let count = 0` と書くと、宣言自体は通りますが次の再代入でビルドが失敗します。
- よくある間違い: `var count` とだけ書くと初期値も型もないため 'Type annotation missing' エラーになります。少なくとも型か初期値のどちらかが必要です。
- 関連例:
```swift
var count = 0
count = count + 1
print(count)
```
- 関連例の出力: 1
- 関連例の説明: 宣言・再代入・出力という、もっとも基本的な3行の形です。

- 関連例の説明: 文字列補間なら変換を書かずに数値を文字列へ埋め込めます。

問題: Optionalに値があるときだけ挨拶を表示するコードに並べ替えてください。

### practice-starter-027 nilのときの代わりの値を指定する [穴埋め / Lv2 基本]
対象レッスン: starter-optional
シリーズ: starter-optional (3段階目)
スキル: optional
問題: nicknameがnilなら「ゲスト」を使うように空欄を埋めてください。
埋めたあと:
```swift
let nickname: String? = nil
let display = nickname ?? "ゲスト"
print(display)
```
ヒント1: 「値があればそれを、無ければ別の値を」を1つの演算子で書けます。
ヒント2: Optional専用の演算子で、記号が2つ並んだ形をしています。BoolのORとは別物です。
ヒント3: `nickname` と `"ゲスト"` の間に置く、疑問符を2つ重ねた演算子です。nil合体演算子と呼ばれます。
解説: `??` はnil合体演算子で、左がnilでなければその中身を、nilなら右の値を返します。ここではnicknameがnilなので display は "ゲスト" になります。結果はOptionalではない普通のStringなので、printしてもOptional(...)は付きません。`!` は強制アンラップでnilのときクラッシュし、`||` はBool同士のORなのでここでは使えません。
- 使っている考え方: ?? は「デフォルト値付きで取り出す」ための演算子です。if let より短く書けるので、値が無いときの代替値が決まっている場面で多用されます。
- 手順: `nickname` は String? 型で、中身は nil。
- 手順: `??` は左辺を評価し、nilかどうかを調べる。
- 手順: nilなので右辺の "ゲスト" が採用される。
- 手順: 結果の型は String（Optionalが外れる）ので、そのままprintできる。
- 動く理由: ?? は「nilなら右の値」という動作をひとつの式で表します。取り出した結果は非Optionalになるため、以降の処理でOptionalを気にせず扱えます。
- よくある間違い: `nickname!` と書くと、nilのときに 'Unexpectedly found nil while unwrapping an Optional value' で実行時クラッシュします。代替値がある場面では ?? を選びます。
- よくある間違い: `||` はBool専用の論理和です。String?に対して使うと型エラーになります。
- 関連例:
```swift
let nickname: String? = "ゆき"
print(nickname ?? "ゲスト")
```
- 関連例の出力: ゆき
- 関連例の説明: 値が入っていれば右辺は評価されず、中身がそのまま使われます。
- 覚えておくこと: ?? は「nilならこちらを使う」。安全で、結果は非Optionalになる。

対象レッスン: starter-optional
シリーズ: starter-optional (4段階目)
スキル: optional, controlFlow
問題: このコードの出力を選んでください。
正解: あり: A
なし
あり: C
ヒント1: 配列の要素は3つあり、ループは3回まわります。
ヒント2: 各要素はString?なので、値のときとnilのときで通る道が変わります。
ヒント3: 1番目は値あり、2番目はnil、3番目は値ありです。if letは値があるときだけ中に入り、nilのときはelseに行きます。

### practice-starter-029 強制アンラップのクラッシュを直す [修正 / Lv3 実装]
対象レッスン: starter-if-let
シリーズ: starter-optional (5段階目)
スキル: optional, debugging
問題: このコードは実行時にクラッシュします。3行目を置き換える安全な書き方を選んでください。
正解: if let number = Int(raw) { print(number * 2) } else { print("数値ではありません") }
ヒント1: `Int("abc")` は変換に失敗します。そのときの戻り値がどうなるかを考えてください。
ヒント2: 変換が失敗する可能性がある以上、「失敗したらどうするか」を書かないと安全になりません。
ヒント3: 値があるときだけ計算し、無いときは別のメッセージを出す構文を使います。強制アンラップ `!` は失敗時にクラッシュするので使いません。
解説: `Int("abc")` は数値に変換できないためnilを返します。そこに `!`（強制アンラップ）を使うと 'Unexpectedly found nil while unwrapping an Optional value' で実行時クラッシュします。if let で値がある場合と無い場合の両方を書けば、クラッシュせずに処理できます。`Int(raw) * 2` はOptionalのまま掛け算しようとして型エラー、`Int(raw)!` は結局同じ強制アンラップです。
- 使っている考え方: `Int(String)` は失敗するかもしれない変換なので、戻り値は `Int?` です。Optionalが返るということは「失敗した場合の分岐を書け」という設計上のメッセージです。
- 手順: `Int("abc")` は数字として解釈できないためnilを返す。
- 手順: `number!` はOptionalの中身を強制的に取り出す操作。中身がnilなら実行時にクラッシュする。
- 手順: if let なら「中身があれば取り出して計算、無ければelse」と両方の道を用意できる。
- 手順: 結果としてクラッシュせず、変換できない入力にもメッセージで対応できる。
- 動く理由: if let は取り出しと分岐を同時に行うため、nilのときにクラッシュする経路がそもそも存在しません。ユーザー入力のように失敗しうる値を扱うときの基本形です。
- よくある間違い: `!` は「絶対にnilではない」と断言する記号です。断言が外れると即クラッシュするので、外部入力には使いません。
- よくある間違い: `print(Int(raw) * 2)` はOptionalのまま演算しようとして 'Value of optional type Int? must be unwrapped' というコンパイルエラーになります。
- 関連例:
```swift

if let number = Int(raw) {
    print(number * 2)
} else {
    print("数値ではありません")
}
```
- 関連例の出力: 24
- 関連例の説明: 変換できる入力なら中身が取り出され、計算結果が出力されます。
- 覚えておくこと: 失敗しうる変換の結果はOptional。`!` ではなく if let / guard let / ?? で受ける。

### practice-starter-030 Optionalを返す関数を組み立てる [関数組み立て / Lv3 実装]
対象レッスン: starter-optional
シリーズ: starter-optional (6段階目)
スキル: optional, functions
問題: 文字列を受け取り、数値に変換できればその2倍を、できなければnilを返す関数を作ります。必要なブロックだけを選んで並べてください。
正解の並び:
```swift
func doubled(_ text: String) -> Int? {
    guard let number = Int(text) else {
        return nil
    }
    return number * 2
}
```
ヒント1: 変換に失敗することがあるので、戻り値の型も「無いかもしれない」ことを表せる必要があります。
ヒント2: 失敗したら早めに抜ける書き方を使うと、そのあとのコードは成功した場合だけを考えれば済みます。
ヒント3: `func doubled(_ text: String) -> Int? {` で始め、`guard let number = Int(text) else { return nil }` で失敗時に抜け、残りで `number * 2` を返します。
解説: 変換が失敗しうるので、戻り値は `Int?` にします。guard let は「取り出せなければelseで抜ける」書き方で、else節ではnilを返して関数を終了します。guardを抜けたあとの number は非Optionalとして使えるため、`number * 2` をそのまま返せます。戻り値を `Int` にしたり `Int(text)!` を使う版は、変換失敗時にクラッシュするので要件を満たしません。
- 使っている考え方: guard let は「条件を満たさなければ即座に抜ける」ための構文です。if let と違い、取り出した値はguardの後ろでも使えます。失敗ケースを先に片付けるので、本来の処理が入れ子にならず読みやすくなります。
- 手順: `-> Int?` … 変換できないことがあるので、戻り値の型自体をOptionalにする。
- 手順: `guard let number = Int(text) else {` … 変換に成功すれば number に中身が入る。
- 手順: `return nil` … 失敗した場合はここで関数を終える。guardのelseは必ず抜ける処理を書く決まり。
- 手順: `return number * 2` … ここに到達した時点で number は確実に存在するので、そのまま計算できる。
- 手順: `}` で関数を閉じる。
- 動く理由: 戻り値をInt?にしたことで「失敗した」という状態を呼び出し側に伝えられます。guard letにより失敗経路が先に処理され、残りのコードは成功時だけを扱えばよくなります。
- よくある間違い: 戻り値を `Int` にすると、失敗を表す方法が無くなり、0を返すなど意味の紛れる設計になります。
- よくある間違い: `Int(text)!` を使うと、"abc" のような入力でクラッシュします。関数の利用者は不正な入力を渡してくるものだと考えます。
- よくある間違い: guardのelseでreturnを書かないと 'guard body must not fall through' というコンパイルエラーになります。
- 関連例:
```swift
func doubled(_ text: String) -> Int? {
    guard let number = Int(text) else {
        return nil
    }
    return number * 2
}
print(doubled("21") ?? -1, doubled("abc") ?? -1)
```
- 関連例の出力: 42 -1
- 関連例の説明: 呼び出し側は ?? でデフォルト値を決められます。失敗を値として扱えるのがOptionalの利点です。
- 覚えておくこと: 失敗しうる処理はOptionalを返す。guard letで失敗を先に抜けると、本処理がすっきりする。

スキル: functions
問題: 税込み価格を返す関数と、その呼び出しになるよう並べ替えてください。
正解の並び:
```swift
func withTax(_ price: Int) -> Int {
    return Int(Double(price) * 1.1)
}

```
ヒント1: 関数の定義が先、呼び出しが後です。
ヒント2: 定義は「func の行」「中身」「閉じかっこ」の3つで1セットです。

- 使っている考え方: `func 名前(_ 引数名: 型) -> 戻り値の型 { … }` が関数定義の基本形です。引数は外から受け取る値、戻り値はその関数の計算結果です。

- 手順: `return Int(Double(price) * 1.1)` … IntのままではDoubleと掛けられないので、Doubleに変換して1.1倍し、Intに戻す。
- 手順: `}` … 関数定義の終わり。
- 手順: `print(withTax(1000))` … 1000を渡して呼び出し、返ってきた値を表示する。1000×1.1=1100.0を Int にして 1100。
- 動く理由: 定義が先にあるため、呼び出しの行で withTax という名前が解決できます。戻り値がIntなので、そのままprintに渡せます。
- よくある間違い: 呼び出しを先に書いても、Swiftのトップレベルコードでは「使う前に定義」が必要なため 'Cannot find withTax in scope' になる場合があります。定義を先に置くのが安全です。
- よくある間違い: `Double(price) * 1.1` の結果はDoubleなので、`-> Int` の関数からそのまま返すと型エラーになります。Int(...) で包む必要があります。
- 関連例:
```swift
func withTax(_ price: Int) -> Int {
    return Int(Double(price) * 1.1)
}
print(withTax(1000), withTax(250))
```
- 関連例の出力: 1100 275
- 関連例の説明: 同じ関数を違う引数で何度でも呼べます。これが関数を作る目的です。
- 覚えておくこと: 関数は定義してから呼び出す。引数の型・戻り値の型・returnの型は一致させる。

### practice-starter-033 戻り値の型と return を書く [穴埋め / Lv2 基本]
対象レッスン: starter-arguments-return
シリーズ: starter-function (3段階目)
スキル: functions
問題: 2つの整数を受け取って合計を返す関数になるよう、空欄を埋めてください。
埋めたあと:
```swift
func add(_ a: Int, _ b: Int) -> Int {
    return a + b
}
print(add(2, 3))
```
ヒント1: 「この関数は何を返すか」を宣言する記号と、「実際に返す」キーワードの2つが必要です。
ヒント2: 戻り値の型は引数リストのかっこの後ろに矢印で示します。
ヒント3: 1つ目は矢印の形をした記号です。2つ目は、計算した値を呼び出し元へ戻すキーワードで、表示するものではありません。
解説: `->` は「この関数が返す値の型」を宣言する記号で、引数リストの後ろに書きます。`return` は実際に値を呼び出し元へ返すキーワードです。printは画面に表示するだけで値を返さないため、`-> Int` と宣言した関数の中でprintだけを書くと 'Missing return' エラーになります。
- 使っている考え方: 関数の「入口」は引数、「出口」は戻り値です。-> で出口の型を宣言し、return で実際に値を出します。この2つは必ずセットで考えます。
- 手順: `func add(_ a: Int, _ b: Int)` … Intを2つ受け取る。
- 手順: `-> Int` … 戻り値がIntであることを宣言する。
- 手順: `return a + b` … 2+3=5 を計算して呼び出し元へ返す。
- 手順: `print(add(2, 3))` … 返ってきた5が表示される。
- 動く理由: -> Int と宣言し、return で Int を返しているため、宣言と実装が一致します。呼び出し側は結果の5を値として受け取り、自由に使えます。
- よくある間違い: `print(a + b)` にすると関数の中で表示はされますが、値を返さないので呼び出し側で結果を使えません。「表示」と「返却」は別です。
- よくある間違い: `-> Int` を書き忘れると戻り値なし（Void）の関数になり、returnで値を返そうとしてエラーになります。
- 関連例:
```swift
func add(_ a: Int, _ b: Int) -> Int {
    return a + b
}
let result = add(2, 3)
print(result * 10)
```
- 関連例の出力: 50
- 関連例の説明: 戻り値なので、変数に入れてさらに計算できます。printだけの関数ではこれができません。
- 覚えておくこと: -> は戻り値の型宣言、return は実際に返す動作。printは戻り値ではない。

対象レッスン: starter-arguments-return

スキル: functions
問題: add関数はすでに定義済みです。2と3の合計を計算し、その結果を使って「合計は5」と表示するために必要な行を選んで並べてください。

- let sum = add(2, 3)

ヒント1: 関数を呼ぶだけでは、結果はどこにも残りません。
ヒント2: 戻ってきた値を受け取る名前を用意してから、その名前を表示に使います。
ヒント3: `let sum = add(2, 3)` で結果を受け取り、`print("合計は\(sum)")` で表示します。かっこを付けずに `add` と書くと呼び出しになりません。

- 手順: `add(2, 3)` が実行されると 5 という値が返ってくる。
- 手順: `let sum = add(2, 3)` はその5を sum という名前で保存する。
- 手順: `print("合計は\(sum)")` は保存した5を文字列に埋め込んで表示する。
- 手順: 結果として「合計は5」が1行出力される。
- 動く理由: 戻り値を受け取る行と、それを使う行の2行で要件を満たします。呼び出しと利用が分かれているので、結果を何度でも使い回せます。
- よくある間違い: `add(2, 3)` だけを書くと結果が捨てられます（Swiftは 'Result of call is unused' と警告します）。
- よくある間違い: `\(add)` はかっこが無いので関数値そのものを指し、'Function is unused' や型の警告になります。呼び出しには必ずかっこが要ります。
- 関連例:
```swift
func add(_ a: Int, _ b: Int) -> Int { a + b }
let sum = add(2, 3)
print("合計は\(sum)")
```
- 関連例の出力: 合計は5
- 関連例の説明: 1行だけの関数では return を省略できます（暗黙のreturn）。
- 覚えておくこと: 関数呼び出しにはかっこが要る。戻り値は受け取らないと消える。

- よくある間違い: `return` だけ書くと、Intを返すべき関数から何も返さないことになりエラーです。
- 関連例:
```swift
func add(_ a: Int, _ b: Int) -> Int {
    return a + b
}
print(add(10, 5))
```

- 関連例の説明: 返ってきた値がそのままprintに渡されます。
- 覚えておくこと: return は「値を返して関数を終える」。printとは役割が違う。

### practice-starter-036 割引価格を計算する関数を組み立てる [関数組み立て / Lv3 実装]
対象レッスン: starter-arguments-return
シリーズ: starter-function (6段階目)
スキル: functions, types
問題: 価格と割引率（%）を受け取り、割引後の価格をIntで返す関数を作ります。必要なブロックだけを選んで並べてください。
正解の並び:
```swift
func discounted(price: Int, percent: Int) -> Int {
    let rate = Double(100 - percent) / 100.0
    return Int(Double(price) * rate)
}
```
ヒント1: 割引後の割合は「100 − 割引率」を100で割ったものです。この計算に何型を使うかが鍵になります。
ヒント2: Int同士の割り算は小数を切り捨てます。割合の計算では致命的です。
ヒント3: `func discounted(price: Int, percent: Int) -> Int {` で始め、割合をDoubleで計算し、`return Int(Double(price) * rate)` で返します。
解説: 20%引きなら残りは80%、つまり0.8倍です。この0.8を求めるには小数を扱えるDoubleが必要で、`(100 - percent) / 100` のようにInt同士で割ると80/100が0になり、価格が常に0になってしまいます。Doubleで割合を求め、価格に掛けてからIntへ戻すのが正しい順序です。printの版は値を返さないため 'Missing return' になります。
- 使っている考え方: 「割合の計算はDoubleで、金額の表示はIntで」という使い分けは実務でも頻出です。Intの割り算が切り捨てになることを忘れると、静かに0や誤差が混入します。
- 手順: `func discounted(price: Int, percent: Int) -> Int {` … 引数ラベル付きで2つ受け取り、Intを返す。
- 手順: `let rate = Double(100 - percent) / 100.0` … 割引後の割合。先にDoubleへ変換してから割るのがポイント。percent=20なら 80.0/100.0 = 0.8。
- 手順: `return Int(Double(price) * rate)` … 価格をDoubleにして掛け、結果をIntに戻して返す。1000×0.8=800.0 → 800。
- 手順: `}` で関数を閉じる。
- 動く理由: 割合をDoubleで求めているため小数が保たれ、掛け算のあとで初めてIntに戻すので誤差が最小限になります。戻り値の型Intとreturnの型Intも一致しています。
- よくある間違い: `(100 - percent) / 100` はInt同士なので、80/100 が 0 になります。エラーにならず結果だけが壊れる、発見しにくいバグです。
- よくある間違い: printの行を選ぶと表示はされますが値が返らず、関数として使えません。
- よくある間違い: Int(...) への変換は切り捨てです。四捨五入したい場合は `Int((Double(price) * rate).rounded())` を使います。
- 関連例:
```swift
func discounted(price: Int, percent: Int) -> Int {
    let rate = Double(100 - percent) / 100.0
    return Int(Double(price) * rate)
}
print(discounted(price: 1000, percent: 20), discounted(price: 999, percent: 10))
```
- 関連例の出力: 800 899
- 関連例の説明: 999円の10%引きは899.1なので、Intへの変換で切り捨てられて899になります。
- 覚えておくこと: 割合はDoubleで計算し、最後にIntへ戻す。Int同士の割り算は切り捨て。

### practice-starter-038 配列を1つずつ処理するループを組み立てる [並べ替え / Lv2 基本]
対象レッスン: starter-for-in
シリーズ: starter-array (2段階目)
スキル: collections, controlFlow
問題: 配列の要素をすべて表示したあとに「以上です」と表示するコードに並べ替えてください。
正解の並び:
```swift
let names = ["佐藤", "鈴木"]
for name in names {
    print(name)
}
print("以上です")
```

ヒント2: for-in は「配列の要素を1つずつ取り出して、名前を付けて、ブロックの中で使う」構文です。
ヒント3: 配列の用意 → `for name in names {` → `print(name)` → `}` → ループの外で「以上です」の順です。

- 手順: `for name in names {` … 1回目は name に "佐藤" が入る。
- 手順: `print(name)` … 佐藤を出力。ブロックの終わりまで来たら次の要素へ。
- 手順: 2回目は name が "鈴木" になり、鈴木を出力。要素が尽きたらループ終了。
- 手順: `print("以上です")` はループの外なので最後に1回だけ実行される。
- 動く理由: 配列の準備・ループの開始・本体・閉じかっこ・ループ後の処理という依存順に並んでいるためです。出力は佐藤、鈴木、以上ですの3行になります。
- よくある間違い: 「以上です」を `}` の内側に入れると要素ごとに表示され、2回出てしまいます。
- よくある間違い: 配列の宣言をforより後ろに置くと、ループの時点でnamesが存在せずスコープエラーになります。
- 関連例:
```swift
let names = ["佐藤", "鈴木"]
for (index, name) in names.enumerated() {
    print(index, name)
}
```
- 関連例の出力: 0 佐藤
1 鈴木
- 関連例の説明: 番号も一緒に欲しいときは enumerated() を使います。
- 覚えておくこと: for-in は「1件ずつ取り出す」。ループの外の行は繰り返されない。

### practice-starter-039 合計を求めるループを完成させる [穴埋め / Lv2 基本]
対象レッスン: starter-for-in
シリーズ: starter-array (3段階目)
スキル: collections, controlFlow
問題: 配列の合計を求めるコードになるよう、空欄を埋めてください。
埋めたあと:
```swift
let scores = [10, 20, 30]
var total = 0
for score in scores {
    total += score
}
print(total)
```
ヒント1: 合計を入れる箱は、ループのたびに中身が増えていきます。
ヒント2: for文で配列から1件ずつ取り出す部分には、決まったキーワードが入ります。
ヒント3: 3つ目の空欄は「今の値に足して入れ直す」複合代入演算子です。`total = total + score` と同じ意味の短い書き方があります。
解説: 合計を貯める total はループのたびに書き換わるので var で宣言します。for文の要素取り出しは `for 要素 in 配列` という形です。`+=` は `total = total + score` の短い書き方で、10・20・30が順に足されて60が出力されます。`=` にすると毎回上書きされ、最後の要素30だけが残ってしまいます。
- 使っている考え方: 合計や個数を数えるコードは「初期値0の変数を用意 → ループで更新 → ループ後に使う」という決まった形をしています。この形を覚えると多くの集計処理が書けます。
- 手順: `var total = 0` … 合計の出発点。letだと更新できない。
- 手順: `for score in scores {` … 要素を1つずつ score に取り出す。
- 手順: `total += score` … 1回目 0+10=10、2回目 10+20=30、3回目 30+60… ではなく 30+30=60。
- 手順: ループ終了後、total は 60。printが60を出力する。
- 動く理由: varで宣言したtotalを += で更新しているため、各要素が積み上がります。ループの外でprintしているので、最終結果の60が1回だけ表示されます。
- よくある間違い: `total = score` と書くと毎回上書きされ、最後の要素30が結果になります。エラーが出ないぶん厄介です。
- よくある間違い: `let total = 0` にすると `total += score` の時点で 'Left side of mutating operator isn't mutable' になります。
- 関連例:
```swift
let scores = [10, 20, 30]
print(scores.reduce(0, +))
```
- 関連例の出力: 60
- 関連例の説明: 同じ集計は reduce でも書けます。まずforで仕組みを理解してから、短い書き方に移るのがおすすめです。
- 覚えておくこと: 集計は「var で0を用意 → ループで += → ループ後に使う」。= と += の違いに注意。

対象レッスン: starter-array-index

ヒント1: 要素数と、使える最大の番号は同じではありません。
ヒント2: countは3ですが、有効なインデックスは0・1・2です。ループの続行条件を確かめてください。
ヒント3: クラッシュするのは `items[index]` の行ですが、indexが3まで進んでしまう原因は別の行にあります。ループを止める条件を見てください。
解説: 3行目の `while index <= items.count` が原因です。countは3なのでindexが3のときも条件がtrueになり、4周目で `items[3]` を評価して 'Fatal error: Index out of range' でクラッシュします。クラッシュが起きるのは4行目ですが、直すべきは条件を `<` にする3行目です。要素数nの配列で有効な番号は0からn-1までです。
- 使っている考え方: 「クラッシュした行」と「バグのある行」は別であることがよくあります。境界条件（off-by-oneエラー）は、条件式そのものを疑うのが定石です。
- 手順: index=0,1,2 のときは items[0], items[1], items[2] が正常に取れる。
- 手順: index=3 のとき、`3 <= 3` はtrueなのでループに入ってしまう。
- 手順: `items[3]` は存在しないため実行時エラー 'Index out of range' でプログラムが停止する。
- 手順: 条件を `index < items.count` にすれば index=3 でループが終わり、クラッシュしない。
- 動く理由: 配列の有効なインデックスは 0 から count-1 までです。ループ条件を `<` にすることで、ちょうどその範囲だけを回せます。
- よくある間違い: 4行目の `print(items[index])` を犯人だと考えると、`if index < items.count` を足すような遠回りな修正になります。条件式そのものを直すのが正解です。
- よくある間違い: `for item in items` で書けば、そもそもインデックスを扱わずに済み、この種のバグが起こりません。
- 関連例:
```swift
let items = ["A", "B", "C"]
for item in items {
    print(item)
}
```
- 関連例の出力: A
B
C
- 関連例の説明: for-inならインデックス計算そのものが不要になり、範囲外アクセスの余地がありません。
- 覚えておくこと: 配列の範囲外アクセスはコンパイルではなく実行時に落ちる。ループ条件は `< count` が基本。

### practice-starter-041 空配列でも落ちないように直す [修正 / Lv3 実装]
対象レッスン: starter-array-index
シリーズ: starter-array (5段階目)
スキル: collections, debugging, optional
問題: 配列が空のときにクラッシュしないよう、2行目を置き換える書き方を選んでください。
正解: let first = items.first ?? "なし"
ヒント1: 空の配列には0番の要素すらありません。存在しないかもしれない先頭要素を、安全に取る方法があります。
ヒント2: 配列には「先頭要素をOptionalで返す」プロパティがあります。無ければnilが返ります。
ヒント3: `items.first` は String? を返します。nilのときの代わりの値を ?? で指定すれば、空でも落ちません。
解説: `items[0]` は要素が無ければ 'Index out of range' で必ずクラッシュします。`items.first` は先頭要素をOptional（String?）で返し、空配列ならnilになるため、?? で代わりの値を指定すれば安全です。`items.first!` は強制アンラップなので空配列ではやはりクラッシュし、`items.count > 0` はBoolなので文字列として使えません。
- 使っている考え方: 添字アクセスは「そこに必ずある」という前提の操作です。前提が崩れうる場面では、Optionalを返す安全なAPI（first / last / indices）を使います。
- 手順: `items` は空配列なので count は 0、有効なインデックスは存在しない。
- 手順: `items[0]` は範囲外アクセスとなり実行時にクラッシュする。コンパイルは通ってしまう点に注意。
- 手順: `items.first` は Optional を返す設計なので、空なら nil。
- 手順: `?? "なし"` によって nil のときの値が決まり、first は必ず String になる。
- 動く理由: first がOptionalを返すことで「空かもしれない」状態が型に現れ、?? でその場で解決しています。結果としてクラッシュ経路が存在しなくなります。
- よくある間違い: `items[0] ?? "なし"` は書けません。添字は非Optionalを返すため ?? の対象になれず、そもそもクラッシュが先に起きます。
- よくある間違い: `items.first!` は「絶対にある」と断言する書き方で、空配列という今回の前提と矛盾します。
- よくある間違い: `items.count > 0` はBoolなので、Stringを期待する first に代入すると型エラーです。
- 関連例:
```swift
let items: [String] = []
print(items.first ?? "なし")
print(["A"].first ?? "なし")
```
- 関連例の出力: なし
A
- 関連例の説明: 同じ書き方で、空のときも要素があるときも安全に動きます。
- 覚えておくこと: 添字は前提が崩れると落ちる。空かもしれないなら first / last とOptionalで受ける。

### practice-starter-042 合計に足し込む1行を書く [記述 / Lv3 実装]
対象レッスン: starter-for-in
シリーズ: starter-array (6段階目)
スキル: collections, controlFlow
問題: ループの中で、今の合計 total に score を足し込む1行を書いてください。
想定する書き方: total += score
ヒント1: 今の合計を捨てずに、新しい値を積み上げます。
ヒント2: `total = total + score` と同じ意味を、短く書く複合代入演算子があります。
ヒント3: 記号は2文字で、足し算の記号と代入の記号を並べたものです。`total` と `score` の間に置きます。
解説: `total += score` と書きます。これは `total = total + score` の短縮形で、現在のtotalにscoreを足した結果をtotalに入れ直します。10・20・30が順に加算され、ループ後のtotalは60になります。`total = score` と書くと毎回上書きされ、最後の30だけが残ります。
- 使っている考え方: += のような複合代入演算子は「読み出して、計算して、書き戻す」を1つの記号で表します。集計処理では毎回この形が登場します。
- 手順: 1回目: score=10。total は 0+10 で 10 になる。
- 手順: 2回目: score=20。total は 10+20 で 30 になる。
- 手順: 3回目: score=30。total は 30+30 で 60 になる。
- 手順: ループ終了後、print(total) が 60 を出力する。
- 動く理由: 現在のtotalを右辺で使ってから代入し直しているため、値が累積します。totalがvarで宣言されているので再代入も合法です。
- よくある間違い: `total = score` は累積せず上書きになり、結果は最後の要素の値になります。
- よくある間違い: `total + score` とだけ書くと計算結果が捨てられ、'Result of operator + is unused' という警告になります。代入が必要です。
- 関連例:
```swift
let scores = [10, 20, 30]
var total = 0
for score in scores {
    total += score
}
print(total)
```
- 関連例の出力: 60
- 関連例の説明: 合計処理の定型です。個数を数えるなら count += 1 と同じ形になります。
- 覚えておくこと: 累積は `+=`。単なる `=` は上書き、計算だけでは何も残らない。
