## 01. プログラムとコードとは何か [Starter]

概要: プログラムはコンピュータへの指示書、コードはその指示を文字で書いたもの。まずこの関係を掴む。
考え方: コードは「上から下へ順番に読まれる指示のリスト」。魔法ではなく、書いた順に、書いたことだけが起きる。

重要ポイント:
- プログラムとは、コンピュータにやらせたい指示の集まり。
- コードとは、その指示を文字で書き表したもの。
- Swiftのコードは、基本的に上の行から下の行へ順番に実行される。
- print は「( ) の中身を画面に表示する」命令。" " で囲んだ部分は文字として扱われる。

コード:
```swift
print("Hello")
print("Gym")
```

なぜ重要か: 「このコードを実行すると何が起きるか」を自分で予測できることが、学習のすべての土台になる。予測できれば、結果とのズレから原因を探せる。
注意: コードは意味を推測して動いてはくれない。書いていないことは起きず、書いた順番は変わらない。

確認問題:
Q1. このコードを実行すると画面には何が表示されますか？ [Starter]
```swift
print("Hello")
print("Gym")
```
A. Hello だけ
B. Gym だけ
C. 1行目に Hello、2行目に Gym
D. 何も表示されない
正解: C
解説: print は上の行から順に1つずつ実行されます。1行目で Hello、2行目で Gym が表示され、合計2行が出ます。

詳しい解説:
- 用語・考え方: print は「( ) の中に書いたものを画面に表示する」という命令です。" " （ダブルクォート）で囲んだ部分は、そのままの文字として扱われます。Swift のコードは、上の行から下の行へ1行ずつ順番に実行されます。
- コードの流れ: 1行目の print("Hello") が実行され、Hello と表示される。
- コードの流れ: 続いて2行目の print("Gym") が実行され、Gym と表示される。
- コードの流れ: print は1回ごとに行を変えるので、表示は2行になる。
- 正解になる理由: 上から順に print が2回実行されるので、Hello が先、Gym が後に、別々の行として表示されます。
- 他の選択肢 Hello だけ: 1行目だけが実行されると考えると出る答えですが、Swift は下の行も続けて実行します。
- 他の選択肢 Gym だけ: 後の行が前の表示を打ち消すと考えると出る答えですが、print は前の表示を消しません。表示は積み重なっていきます。
- 他の選択肢 何も表示されない: print は書けばそれだけで表示される命令です。表示のために別の指示を追加する必要はありません。
- 関連例:
```swift
print("Fit24")
print("Yuki")
```
- 関連例の出力: Fit24
Yuki
- 関連例の説明: 中身を変えても仕組みは同じで、上の行から順に1行ずつ表示されます。
- 覚えておくこと: コードは上から下へ、1行ずつ。

Q2. print("Yuki") の " " は何を表す記号ですか？ [Starter]
```swift
print("Yuki")
```
A. 囲んだ中身を文字として扱う記号
B. 囲んだ中身を計算する記号
C. その行を消す記号
D. 画面をクリアする記号
正解: A
解説: " " （ダブルクォート）は「ここからここまでは文字である」という印です。中身は計算されず、そのままの文字として扱われます。

詳しい解説:
- 用語・考え方: " " はダブルクォートと呼ぶ記号で、「ここからここまでは文字として扱ってください」という印です。囲まれた中身は意味を解釈されず、そのままの文字になります。
- 正解になる理由: print("Yuki") の "Yuki" は「Y・u・k・i という文字の並び」を表しています。だから画面には Yuki と表示され、印である " " 自体は表示されません。
- 他の選択肢 囲んだ中身を計算する記号: むしろ逆で、" " で囲むと計算されなくなります。"2 + 3" と書くと 5 にはならず、2 + 3 という文字の並びとして扱われます。
- 他の選択肢 その行を消す記号: 行を実行しないようにするのは // で始まるコメントです（次のレッスンで学びます）。
- 他の選択肢 画面をクリアする記号: " " に画面を操作する働きはありません。print も前の表示を消しません。
- 関連例:
```swift
print("2 + 3")
```
- 関連例の出力: 2 + 3
- 関連例の説明: " " で囲むと計算されず、書いたままの文字が出ます。囲まずに print(2 + 3) と書けば 5 と表示されます。
- 覚えておくこと: " " で囲んだら、それは文字。

Q3. このコードで先に表示されるのはどちらですか？ [Starter]
```swift
print("A")
print("B")
```
A. A
B. B
C. 同時に表示される
D. どちらも表示されない
正解: A
解説: 実行の順番は上から下です。1行目の print が先に実行されるので A が先に表示されます。

詳しい解説:
- 用語・考え方: Swift はコードを上の行から下の行へ、1つずつ順番に実行します。書いた順番が、そのまま実行される順番になります。
- コードの流れ: 1行目の print("A") が実行され、A が表示される。
- コードの流れ: 次に2行目の print("B") が実行され、B が表示される。
- 正解になる理由: A を表示する行のほうが上にあるため、A が先に表示されます。
- 他の選択肢 B: 下の行が先に実行されることはありません。順番を変えたいときは、行そのものを入れ替えます。
- 他の選択肢 同時に表示される: 1行ずつ順番に実行されるので、同時にはなりません（人の目には一瞬に見えますが、内部では順番があります）。
- 他の選択肢 どちらも表示されない: どちらも正しい print なので、2つとも表示されます。
- 覚えておくこと: 実行の順番 ＝ 書いた順番。

## 02. コードを1行ずつ分解して読む [Starter]

概要: 1行を「何をする命令か」と「その対象は何か」に切り分けて読む練習をする。
考え方: 分からない行を丸ごと理解しようとしない。記号ごとに区切って、命令の名前と、その対象を分けて見る。

重要ポイント:
- 1行は「命令の名前」と「その対象」に分けて読める。
- print("Gym") なら、命令は print、対象は ( ) の中の "Gym"。
- // から行末まではコメントで、人間向けのメモとして扱われ実行されない。
- 読めない行は、記号（" " や ( ) など）を目印に区切って読む。

コード:
```swift
print("Yuki")   // これはコメント。実行されない
```

なぜ重要か: コードが読めない原因は「難しい機能」ではなく、1行の中でどこが命令でどこが対象かを見分けられていないことが多い。
注意: コメントは実行されないので、コメントに書いた内容が動作に影響することはない。

確認問題:
Q1. この行で「表示される対象」はどの部分ですか？ [Starter]
```swift
print("Gym")
```
A. print
B. "Gym"
C. ( )
D. 行全体
正解: B
解説: print は「表示する」という命令の名前で、実際に表示される対象は ( ) の中に書かれた "Gym" です。

詳しい解説:
- 用語・考え方: 1行のコードは「何をするか（命令の名前）」と「何に対してするか（対象）」に分けて読めます。print("Gym") では print が命令の名前、( ) の中が対象です。
- 正解になる理由: 実際に表示される中身は ( ) の中に書いた "Gym" です。print はその「表示する」という動作の名前にすぎません。
- 他の選択肢 print: print は動作の名前です。print という文字が画面に出るわけではありません。
- 他の選択肢 ( ): ( ) は「ここが対象です」と示す囲いで、括弧そのものは表示されません。
- 他の選択肢 行全体: 行全体には命令の名前も記号も含まれます。表示されるのは対象の部分だけです。
- 覚えておくこと: 命令の名前と、( ) の中の対象を分けて読む。

Q2. このコードの出力はどれですか？ [Starter]
```swift
print("A")   // print("B")
```
A. A
B. B
C. A と B
D. エラーになる
正解: A
解説: // から行末まではコメントとして無視されます。実行されるのは print("A") だけなので A のみが表示されます。

詳しい解説:
- 用語・考え方: // はコメントの始まりを表す記号です。// から行の終わりまでは人間へのメモとして扱われ、Swift は実行しません。
- コードの流れ: print("A") は普通のコードなので実行され、A が表示される。
- コードの流れ: その後ろの // 以降はメモ扱いになり、print("B") と書いてあっても実行されない。
- 正解になる理由: 実行されるのは print("A") だけなので、表示は A の1行だけです。
- 他の選択肢 B: コメントの中の print は実行されません。
- 他の選択肢 A と B: // の後ろも実行されると考えると出る答えですが、コメントは実行の対象から外れます。
- 他の選択肢 エラーになる: コメントを書くのは正しい書き方です。エラーにはなりません。
- 関連例:
```swift
print("Fit24")   // print("Anytime")
print("Yuki")
```
- 関連例の出力: Fit24
Yuki
- 関連例の説明: 1行目のコメント部分だけが無視され、2行目は普通に実行されます。
- 覚えておくこと: // から行末まではメモ。実行されない。

Q3. このコードの出力はどれですか？ [Starter]
```swift
print("score")
```
A. score
B. 0
C. 何も表示されない
D. エラーになる
正解: A
解説: " " の中は、たとえ英単語でもただの文字です。score という文字がそのまま表示されます。

詳しい解説:
- 用語・考え方: " " で囲まれた中身は、たとえ意味のありそうな英単語でも「ただの文字」として扱われます。
- 正解になる理由: "score" は s・c・o・r・e という文字の並びを表しているだけなので、そのまま score と表示されます。
- 他の選択肢 0: score という名前に数が入っている、と考えると出る答えです。名前を付ける話はレッスン4で学びます。ここでは " " で囲まれているので、名前ではなく文字です。
- 他の選択肢 何も表示されない: print は必ず ( ) の中身を表示します。
- 他の選択肢 エラーになる: 文字を表示するのは正しい使い方なので、エラーにはなりません。
- 覚えておくこと: " " の中身は、意味を持たないただの文字。

## 03. 値・文字・数字とは何か [Starter]

概要: コードが扱うデータ1つ1つを「値」と呼ぶ。文字の値と数の値の書き分けを覚える。
考え方: 値は「コードが手に持てるデータ1個」。同じ 10 でも、数として持つのか文字として持つのかで別物になる。

重要ポイント:
- 値とは、コードが扱うデータ1つ1つのこと。
- 文字の値は " " で囲んで書く（例："Yuki"）。
- 数の値は " " を付けずにそのまま書く（例：10）。
- 10 は数の値、"10" は文字の値で、別のものとして扱われる。

コード:
```swift
print(10)
print("10")
```

なぜ重要か: 後で出てくる「型」「計算」「比較」はすべて値の話。値の種類を取り違えると、原因の分からないエラーになる。
注意: "10" は文字なので、数としての大小や計算の対象にはできない。見た目が同じでも中身が違う。

確認問題:
Q1. 10 と "10" の違いの説明として正しいのはどれですか？ [Starter]
```swift
print(10)
print("10")
```
A. まったく同じもの
B. 10 は数の値、"10" は文字の値
C. "10" のほうが大きい値
D. どちらも文字の値
正解: B
解説: " " で囲むと文字の値になります。10 は数として扱える値、"10" は文字として扱われる値で、種類が違います。

詳しい解説:
- 用語・考え方: コードが扱うデータ1つ1つを「値」と呼びます。値には種類があり、" " で囲むと文字の値、囲まずに数字を書くと数の値になります。
- 正解になる理由: 10 は数として扱える値、"10" は「1」と「0」という2文字が並んだ文字の値です。画面に出すと同じ 10 に見えても、コードの中では別のものです。
- 他の選択肢 まったく同じもの: 表示は同じに見えますが、数として扱えるのは囲みの無い 10 だけです。
- 他の選択肢 "10" のほうが大きい値: 文字の値に「大きい・小さい」をそのまま当てはめることはできません。大小を比べられるのは数の値です。
- 他の選択肢 どちらも文字の値: 囲みの無い 10 は数の値です。囲みの有無が種類を分けます。
- 覚えておくこと: " " があるかどうかで、文字か数かが決まる。

Q2. 次のうち「文字の値」はどれですか？ [Starter]
```swift
// A から D の中から選ぶ
```
A. 100
B. "100"
C. 0
D. 12
正解: B
解説: " " で囲まれているものだけが文字の値です。囲みのない 100 や 0、12 は数の値です。

詳しい解説:
- 用語・考え方: 文字の値は必ず " " で囲んで書きます。囲みが無く数字だけが書かれていれば、それは数の値です。
- 正解になる理由: 選択肢の中で " " で囲まれているのは "100" だけなので、これが文字の値です。
- 他の選択肢 100: 囲みが無いので数の値です。"100" と 100 は見た目が似ていますが別物です。
- 他の選択肢 0: 囲みが無いので数の値です。
- 他の選択肢 12: 同じく囲みが無いので数の値です。
- 覚えておくこと: 判断はシンプル。" " があるかどうかだけを見る。

Q3. このコードの出力はどれですか？ [Starter]
```swift
print("Yuki")
print(30)
```
A. Yuki と 30
B. "Yuki" と 30
C. Yuki と "30"
D. エラーになる
正解: A
解説: " " は「ここは文字」という印なので、表示そのものには含まれません。Yuki と 30 が2行に分かれて表示されます。

詳しい解説:
- 用語・考え方: " " は「ここは文字ですよ」という印であって、表示される中身には含まれません。数の値は囲まずに書き、そのまま表示されます。
- コードの流れ: 1行目で "Yuki" の中身、Yuki が表示される。
- コードの流れ: 2行目で数の値 30 が表示される。
- コードの流れ: print は1回ごとに行を変えるので、2行に分かれる。
- 正解になる理由: 印である " " は画面に出ないので、Yuki と 30 が順に表示されます。
- 他の選択肢 "Yuki" と 30: " " も一緒に表示されると考えると出る答えですが、囲みは印なので表示されません。
- 他の選択肢 Yuki と "30": 30 はもともと囲まれていません。囲みが後から付くことはありません。
- 他の選択肢 エラーになる: 文字の値も数の値も、どちらも print で表示できます。
- 覚えておくこと: " " は目印。画面には出ない。

## 04. 名前を付ける・let・var [Starter]

概要: 値に名前を付けて何度も使い回す。後から変えない名前は let、変える名前は var。
考え方: let / var は「箱」ではなく「値に付けた名札」。let の名札は貼り替えられず、var の名札は貼り替えられる。

重要ポイント:
- 値に名前を付けると、その値を何度でも使い回せる。
- let で付けた名前は、後から別の値に変えられない。
- var で付けた名前は、後から別の値に変えられる。
- = は名前と値を結びつける記号（詳しくは次のレッスン）。

コード:
```swift
let userName = "Yuki"
var workoutCount = 3
print(userName)
print(workoutCount)
```

なぜ重要か: 実際のアプリでは「変わらない値」と「変わる値」を区別することが設計そのものになる。let を選べるところで let を選ぶと、想定外の変更を防げる。
注意: 「後で変えるかもしれない」と迷って全部 var にすると、どこで値が変わるのか追えなくなる。まず let で書く。

確認問題:
Q1. このコードでエラーになるのはどの行ですか？ [Starter]
```swift
let gymName = "Fit24"
gymName = "Anytime"
```
A. 1行目
B. 2行目
C. 両方
D. エラーにならない
正解: B
解説: let で付けた名前は後から変えられません。2行目で別の値に変えようとしているためエラーです。変える予定があるなら var を使います。

詳しい解説:
- 用語・考え方: let は「後から入れ替えない名前」を作るキーワードです。let gymName = "Fit24" と書くと gymName という名前に "Fit24" が結び付き、その後で別の値に変えることはできません。変える予定があるときは var を使います。
- コードの流れ: 1行目で let により gymName という名前が作られ、"Fit24" が入る。
- コードの流れ: 2行目は、その gymName に別の文字を入れ直そうとしている。
- コードの流れ: let で作った名前は入れ替えできないため、Swift はこのコードを受け付けず、実行を始めることすらできない。
- 正解になる理由: 原因は2行目の入れ替えです。1行目の書き方自体は正しいので、問題があるのは2行目だけになります。
- 他の選択肢 1行目: let で名前を作ること自体は正しい書き方です。1行目だけなら問題ありません。
- 他の選択肢 両方: 1行目は正しいので、両方ではありません。
- 他の選択肢 エラーにならない: let の名前を入れ替えようとしているため、このままでは動かせません。
- 関連例:
```swift
var gymName = "Fit24"
gymName = "Anytime"
print(gymName)
```
- 関連例の出力: Anytime
- 関連例の説明: 1行目を var に変えると、後から入れ替えられるようになります。同じコードでも let か var かで結果が変わります。
- 覚えておくこと: 変えないなら let、変えるなら var。

Q2. このコードの出力はどれですか？ [Starter]
```swift
var score = 10
score = 20
print(score)
```
A. 10
B. 20
C. 30
D. エラーになる
正解: B
解説: var で付けた名前は変更できます。2行目で score が 20 になり、その後に print されるので 20 が表示されます。

詳しい解説:
- 用語・考え方: var は「後から入れ替えられる名前」を作るキーワードです。入れ替えると前の値は残らず、上書きされます。
- コードの流れ: 1行目で var により score という名前が作られ、10 が入る。
- コードの流れ: 2行目で score の中身が 20 に入れ替わり、前の 10 は消える。
- コードの流れ: 3行目の print は、その時点の中身である 20 を表示する。
- 正解になる理由: print が実行されるのは入れ替えた後なので、表示されるのは 20 です。
- 他の選択肢 10: 最初に入れた値がそのまま残ると考えると出る答えですが、2行目で上書きされています。
- 他の選択肢 30: 10 と 20 が足されると考えると出る答えですが、= は入れ替えであって足し算ではありません。
- 他の選択肢 エラーになる: var で作った名前なので、入れ替えは正しい書き方です。
- 覚えておくこと: var は上書き。最後に入れた値が残る。

Q3. 値を後から変更しない名前として workoutCount を作るとき、行の先頭に入るキーワードはどれですか？ [Starter]
```swift
workoutCount = 0
```
A. let
B. var
C. print
D. " "
正解: A
解説: let は、値を後から変更しない名前を新しく作るキーワードです。完成したコードは let workoutCount = 0 です。

詳しい解説:
- 用語・考え方: 名前を作るときは、行の先頭に let か var のどちらかを書きます。let は後から入れ替えない名前、var は後から入れ替える名前です。
- 正解になる理由: 「値を後から変更しない名前」という条件なので let を選びます。完成したコードは let workoutCount = 0 です。
- 他の選択肢 var: var と書いても動きますが、変更しない予定の名前に var を使うと「ここは後で変わるのかもしれない」と読み手に誤解させます。変更しないなら let が適切です。
- 他の選択肢 print: print は画面に表示する命令で、名前を作る働きはありません。
- 他の選択肢 " ": " " は文字を囲む印であって、名前を作るキーワードではありません。
- 覚えておくこと: まず let。変える必要が出たときだけ var。

## 05. 代入の = [Starter]

概要: = は「等しい」ではない。右側を先に読み、その結果を左の名前に入れる動作。
考え方: = は矢印だと思うとよい。右 → 左に値が流れる。「等しいか確かめる」記号は別に存在する。

重要ポイント:
- = は代入。右側の値を、左側の名前に入れる。
- 右側が先に読まれ、その結果が左の名前に入る。
- 同じ名前にもう一度代入すると、前の値は上書きされる。
- 「等しいか」を確かめる記号は == で、これは別物（レッスン9で学ぶ）。

コード:
```swift
var score = 10
score = 25
print(score)
```

なぜ重要か: = を「等しい」と読んでしまうと、score = score + 5 のような行が意味不明になる。代入だと分かれば、上から順に値をたどれる。
注意: = の左に来るのは名前。10 = score のように左に値を書くことはできない。

確認問題:
Q1. Swift の = の意味として正しいのはどれですか？ [Starter]
```swift
var score = 10
```
A. 左と右が等しいか確認する
B. 右側の値を左側の名前に入れる
C. 左右の数を足す
D. 値を画面に表示する
正解: B
解説: = は代入です。まず右側の 10 が読まれ、その値が左側の名前 score に入ります。等しいかどうかを調べる記号ではありません。

詳しい解説:
- 用語・考え方: = は「代入」の記号です。数学の「左と右が等しい」という意味ではありません。左側には値を入れる先の名前、右側には入れたい値を書きます。var は、後から値を変えられる名前を作るキーワードです。
- コードの流れ: Swift はこの行を右側から片付けます。まず = の右にある 10 が値として読まれます。
- コードの流れ: var score という新しい名前が作られます。
- コードの流れ: 読み取った 10 が、名前 score に入ります。
- コードの流れ: この後 print(score) と書けば 10 が表示されます。
- 正解になる理由: = は右側の値を左側の名前へ入れる動作なので、「右側の値を左側の名前に入れる」が正しい説明です。この向き（右から左）は常に決まっていて、逆になることはありません。
- 他の選択肢 左と右が等しいか確認する: これは == の役割です。= は「入れる」という動作、== は「等しい？」という質問だと分けて覚えると混同しません。== はレッスン9で学びます。
- 他の選択肢 左右の数を足す: 足すのは + です。= 自体は計算しません。ただし score = score + 5 のように、右側で計算した結果を代入することはできます。
- 他の選択肢 値を画面に表示する: 表示するのは print です。= は名前に値を入れるだけで、画面には何も出ません。
- 関連例:
```swift
var score = 10
score = 25
print(score)
```
- 関連例の出力: 25
- 関連例の説明: 同じ名前にもう一度代入すると、前の値 10 は上書きされて消えます。最後に入った 25 だけが残るので、表示されるのは 25 です。
- 覚えておくこと: = は「入れる」、== は「等しい？」。

Q2. このコードの出力はどれですか？ [Starter]
```swift
var count = 2
count = 5
count = 1
print(count)
```
A. 2
B. 5
C. 1
D. 8
正解: C
解説: 代入は上から順に実行され、そのたびに前の値が上書きされます。最後の代入である 1 が残るので 1 が表示されます。

詳しい解説:
- 用語・考え方: = は「右の値を左の名前に入れる」動作です。同じ名前に何度も入れると、そのたびに前の中身が消えて新しい値に置き換わります。
- コードの流れ: 1行目: count に 2 が入る。
- コードの流れ: 2行目: count が 5 に置き換わる（2 は消える）。
- コードの流れ: 3行目: count が 1 に置き換わる（5 は消える）。
- コードの流れ: 4行目: print は、その時点の中身である 1 を表示する。
- 正解になる理由: 入れ替えは上から順に行われるので、最後に入った 1 だけが残ります。
- 他の選択肢 2: 最初の値が残ると考えると出る答えですが、後の行で2回上書きされています。
- 他の選択肢 5: 途中の値です。print はさらに後の行にあるため、その後の入れ替えも反映されます。
- 他の選択肢 8: 2 + 5 + 1 のように足されると考えると出る答えですが、= は足し算ではなく入れ替えです。
- 覚えておくこと: = は上書き。最後の1回が残る。

Q3. 代入の書き方として正しい行はどれですか？ [Starter]
```swift
var score = 0
// 次のうち正しい書き方は？
```
A. 10 = score
B. score = 10
C. score 10
D. let = score
正解: B
解説: = の左には名前、右には入れたい値が来ます。score = 10 だけが正しい形です。

詳しい解説:
- 用語・考え方: = の左には「入れる先の名前」、右には「入れたい値」を書きます。この向きは決まっていて、逆に書くことはできません。
- 正解になる理由: score = 10 は「score という名前に 10 を入れる」という正しい形になっています。
- 他の選択肢 10 = score: 左右が逆です。10 は値であって名前ではないので、何かを入れる先にはできません。
- 他の選択肢 score 10: = が無いため、名前と値を結び付ける指示になっていません。
- 他の選択肢 let = score: let の後ろには新しく作る名前を書きます。let = のように名前を省くことはできません。
- 覚えておくこと: = の左は名前、右は値。

## 06. 型とは何か [Starter]

概要: 型は「その値が何の種類か」を表す。型が決まると、できる操作も決まる。
考え方: 型は値に貼られた「種類のラベル」。ラベルが違えば、扱い方も許される操作も違う。

重要ポイント:
- 型とは、値の種類のこと。
- 型が違えば、その値に対してできる操作も違う。
- Swift は値を見て型を自動で判断する（型推論）。
- 名前の後に : 型名 と書けば、型を自分で明示できる（代表的な型名は次のレッスン）。

コード:
```swift
let userName: String = "Yuki"
let score: Int = 80
```

なぜ重要か: 型があるおかげで、意味の通らない操作を実行前に Swift が止めてくれる。エラーメッセージの多くは「型が合っていない」という指摘。
注意: 型を明示した名前には、その型の値しか入れられない。数の型に文字の値を入れることはできない。

確認問題:
Q1. 「型」の説明として正しいのはどれですか？ [Starter]
```swift
let score: Int = 80
```
A. 値に付けた名前のこと
B. 値の種類のこと
C. 値の個数のこと
D. 値の表示方法のこと
正解: B
解説: 型は値の種類です。名前（score）とは別の概念で、その値が数なのか文字なのかといった種類を表します。

詳しい解説:
- 用語・考え方: 型とは「その値がどんな種類か」を表すものです。数なのか文字なのか、といった区別が型です。名前（score）と型（Int）は別のもので、名前は呼び方、型は種類を表します。
- 正解になる理由: let score: Int = 80 の Int の位置に書くものが型で、「これは整数の仲間だ」という種類を示しています。
- 他の選択肢 値に付けた名前のこと: 名前はこの行では score の部分です。型は : の後ろに書く Int の部分で、別のものです。
- 他の選択肢 値の個数のこと: 個数を表す書き方ではありません。80 がいくつあるかとは無関係です。
- 他の選択肢 値の表示方法のこと: 表示のしかたを決めるのは print などの命令であって、型ではありません。
- 覚えておくこと: 名前は呼び方、型は種類。

Q2. この行がエラーになる理由はどれですか？ [Starter]
```swift
let score: Int = "80"
```
A. Int と明示した名前に文字の値を入れているから
B. print が無いから
C. let を使っているから
D. : を書いてはいけないから
正解: A
解説: Int は数の型です。"80" は文字の値なので、型が合わずエラーになります。見た目が数字でも " " で囲めば文字です。

詳しい解説:
- 用語・考え方: : の後ろに型を書くと、「この名前にはこの種類の値しか入れない」という約束になります。Int は整数の型です。
- コードの流れ: score には Int（整数）しか入れない、と宣言している。
- コードの流れ: 右側の "80" は " " で囲まれているので文字の値。
- コードの流れ: 種類が合わないため、Swift はこのコードを受け付けず、実行を始めることができない。
- 正解になる理由: 見た目が数字でも、" " で囲めば文字です。整数だけを入れると約束した名前に文字を入れようとしているのが原因です。
- 他の選択肢 print が無いから: print は表示のための命令で、名前を作るのに必須ではありません。
- 他の選択肢 let を使っているから: let は正しい書き方です。var にしても種類が合わないままなので、同じ理由で受け付けられません。
- 他の選択肢 : を書いてはいけないから: : で型を書くのは正しい書き方です。むしろ種類をはっきりさせるための書き方です。
- 関連例:
```swift
let score: Int = 80
print(score)
```
- 関連例の出力: 80
- 関連例の説明: " " を外して数の値にすると種類が合い、そのまま動きます。
- 覚えておくこと: " " が付いたら文字。Int には入らない。

Q3. この行で gymName の型はどう決まりますか？ [Starter]
```swift

```
A. 書いた値から Swift が文字の型と判断する
B. 型は決まらないままになる
C. 常に数の型になる
D. 型を書かないとエラーになる
正解: A
解説: 型を書かなくても、Swift は代入された値から型を判断します。これを型推論と呼びます。

詳しい解説:
- 用語・考え方: 型は自分で書くこともできますが、書かなくても Swift が右側の値を見て種類を判断してくれます。これを型推論と呼びます。
- 正解になる理由: "Fit24" は " " で囲まれた文字なので、Swift は gymName を文字の型だと判断します。書かなくても型は決まっています。
- 他の選択肢 型は決まらないままになる: 書かなくても必ず型は決まります。種類が決まらないまま進むことはありません。
- 他の選択肢 常に数の型になる: 右側の値によって決まります。数を書けば数の型、文字を書けば文字の型です。
- 他の選択肢 型を書かないとエラーになる: 型を書かない書き方はよく使われます。エラーにはなりません。
- 覚えておくこと: 型は書かなくても、右側の値から決まる。

## 07. Int・Double・String・Bool [Starter]

## 08. 計算式と評価結果 [Starter]

概要: 式は計算されて1つの値になる。この「計算されて値になること」を評価と呼ぶ。
考え方: 式は「まだ答えになっていない書きかけ」。評価されると1つの値に落ち着き、その値を名前に入れたり表示したりできる。

重要ポイント:
- 式とは、計算されて1つの値になる書き方のこと。
- 評価とは、式を計算して1つの値にすること。
- + 足す、- 引く、* かける、/ わる。* と / が + と - より先に計算される。
- 評価結果は名前に入れたり、print で表示したりできる。

コード:
```swift
let sets = 3
let reps = 10
let total = sets * reps
print(total)
```

なぜ重要か: 画面に出す数値のほとんどは、その場で計算された評価結果。式のどこが先に計算されるかを読めれば、数値がずれる原因を追える。
注意: * と / は + と - より先に計算される。順番を変えたいときは ( ) でまとめる。

確認問題:
Q1. このコードの出力はどれですか？ [Starter]
```swift
print(2 + 3 * 4)
```
A. 20
B. 14
C. 24
D. 9
正解: B
解説: * が + より先に計算されます。3 * 4 = 12、それに 2 を足して 14 になります。

詳しい解説:
- 用語・考え方: 式とは、計算されて1つの値になる書き方のことです。計算されて1つの値に決まることを「評価」と呼びます。* と / は + と - より先に計算されます（算数と同じ順番です）。
- コードの流れ: まず 3 * 4 が計算されて 12 になる。
- コードの流れ: 次に 2 + 12 が計算されて 14 になる。
- コードの流れ: print はその結果 14 を表示する。
- 正解になる理由: 掛け算が先に計算されるため、答えは 14 になります。
- 他の選択肢 20: 左から順に 2 + 3 = 5、5 * 4 = 20 と計算すると出る答えです。書かれた順ではなく、* が先というきまりがあります。
- 他の選択肢 24: 2 * 3 * 4 と考えると出る答えですが、最初の記号は + です。
- 他の選択肢 9: 2 + 3 + 4 と考えると出る答えですが、2つ目の記号は * です。
- 関連例:
```swift
print((2 + 3) * 4)
```
- 関連例の出力: 20
- 関連例の説明: ( ) で囲むと、その中が先に計算されます。順番を変えたいときに使います。
- 覚えておくこと: * と / が先。順番を変えたいときは ( )。

Q2. このコードの出力はどれですか？ [Starter]
```swift
let sets = 3
let reps = 10
print(sets * reps)
```
A. 3
B. 10
C. 30
D. 310
正解: C
解説: sets には 3、reps には 10 が入っています。sets * reps は 3 * 10 と評価され 30 になります。

詳しい解説:
- 用語・考え方: 名前を付けた値は、その名前を書くだけで計算に使えます。計算のときは、名前がその中身の値に置き換わってから計算されます。
- コードの流れ: 1行目で sets に 3 が入る。
- コードの流れ: 2行目で reps に 10 が入る。
- コードの流れ: 3行目で sets * reps が 3 * 10 として計算され、30 になる。
- コードの流れ: print はその結果 30 を表示する。
- 正解になる理由: sets の中身は 3、reps の中身は 10 なので、掛け合わせると 30 になります。
- 他の選択肢 3: sets の中身だけが表示されると考えると出る答えですが、print の中身は sets * reps という計算です。
- 他の選択肢 10: 同じく reps の中身だけを見た場合の答えです。
- 他の選択肢 310: 3 と 10 が文字としてつながると考えると出る答えですが、どちらも数の値なので掛け算になります。
- 覚えておくこと: 名前は中身の値に置き換わってから計算される。

Q3. 「評価」の意味として正しいのはどれですか？ [Starter]
```swift
let total = 3 * 10
```
A. 式を計算して1つの値にすること
B. コードを画面に表示すること
C. 名前を消すこと
D. 型を書き換えること
正解: A
解説: 評価とは式を計算して1つの値にすることです。3 * 10 は評価されて 30 という値になり、それが total に代入されます。

詳しい解説:
- 用語・考え方: 「評価」とは、計算されて1つの値に決まることです。3 * 10 は書いた時点ではまだ計算前ですが、評価されると 30 という1つの値になります。
- 正解になる理由: let total = 3 * 10 では、右側が先に評価されて 30 になり、その 30 が total に入ります。名前に入るのは式そのものではなく、計算された結果です。
- 他の選択肢 コードを画面に表示すること: 表示は print の役割です。評価は表示とは関係なく行われます。
- 他の選択肢 名前を消すこと: 評価によって名前が消えることはありません。
- 他の選択肢 型を書き換えること: 型は値の種類のことで、評価によって書き換わるものではありません。
- 覚えておくこと: 評価 ＝ 計算して1つの値になること。

## 09. 比較・==・true・false [Starter]

概要: 比較すると結果は必ず true か false になる。= と == の違いをここで確定させる。
考え方: 比較は「質問」。答えは必ず true か false のどちらか。代入の = は動作、比較の == は質問。

重要ポイント:
- == は「左と右が等しいか」を確かめ、結果は true か false になる。
- != は「等しくないか」を確かめる。
- > < >= <= は大小の比較で、結果も true か false。
- = は代入、== は比較。1文字違いで意味がまったく違う。

コード:
```swift
let score = 80
let isPassed = score >= 70
print(isPassed)
```

なぜ重要か: アプリの分岐はすべて true / false で決まる。比較の結果を正しく読めることが、次のレッスンの if の前提になる。
注意: if score = 70 のように比較のつもりで = を書くのはよくある間違い。等しいか調べたいときは == 。（if は次のレッスンで学びます。）

確認問題:
Q1. = と == の違いの説明として正しいのはどれですか？ [Starter]
```swift
var score = 80
print(score == 80)
```
A. どちらも代入
B. = は代入、== は等しいか確かめる比較
C. = は比較、== は代入
D. どちらも比較
正解: B
解説: = は右の値を左の名前に入れる代入です。== は左右が等しいかを確かめ、true か false を返す比較です。

詳しい解説:
- 用語・考え方: = は「入れる」動作、== は「等しいか？」という質問です。== の答えは必ず true か false のどちらかになります。1文字違いですが役割はまったく違います。
- コードの流れ: 1行目の = は代入で、score に 80 を入れている。
- コードの流れ: 2行目の == は比較で、score の中身 80 と 80 が等しいかを調べている。
- コードの流れ: 等しいので答えは true になり、print がその true を表示する。
- 正解になる理由: = は値を入れる動作、== は等しいかを確かめる質問で、役割が分かれています。
- 他の選択肢 どちらも代入: == は値を入れません。調べた結果として true か false を返すだけです。
- 他の選択肢 = は比較、== は代入: 説明が逆です。記号が短い = のほうが代入です。
- 他の選択肢 どちらも比較: = は比較ではありません。if の条件に = を書いてしまうのは、よくある間違いです。
- 関連例:
```swift
var score = 70
print(score == 80)
score = 80
print(score == 80)
```
- 関連例の出力: false
true
- 関連例の説明: = で中身を入れ替えると、== の答えも変わります。= が動作、== が質問だとわかります。
- 覚えておくこと: = は入れる、== は等しい？

Q2. このコードの出力はどれですか？ [Starter]
```swift

```
A. true
B. false
C. 3
D. エラーになる
正解: B
解説: == は「左と右が等しいか」を確かめる記号で、答えは true か false のどちらかになります。3 と 4 は等しくないので false になり、それが print で表示されます。

詳しい解説:
- 用語・考え方: == は左右が等しいかを調べる記号で、答えは true（はい）か false（いいえ）のどちらかになります。
- コードの流れ: print の中の 3 == 4 が先に調べられる。
- コードの流れ: 3 と 4 は違う数なので、答えは false になる。
- コードの流れ: print はその false を表示する。
- 正解になる理由: 3 と 4 は等しくないので false です。print が表示するのは数の 3 ではなく、比べた結果です。
- 他の選択肢 true: 等しいときの答えです。3 と 4 は違う数です。
- 他の選択肢 3: 左側の数がそのまま出ると考えると出る答えですが、print の中身は比較の結果です。
- 他の選択肢 エラーになる: 数どうしを比べるのは正しい書き方です。
- 覚えておくこと: == の答えは true か false。

Q3. このコードの出力はどれですか？ [Starter]
```swift

print(count != 5)
```
A. true
B. false
C. 5
D. エラーになる
正解: B

詳しい解説:

- コードの流れ: count には 5 が入っている。
- コードの流れ: count != 5 は「5 は 5 と違うか？」という質問になる。
- コードの流れ: 同じ数なので「違う」は成り立たず、答えは false になる。
- 正解になる理由: 同じ値どうしなので「等しくない」は成り立たず、false になります。
- 他の選択肢 true: count に 5 以外が入っていれば true になります。ここでは 5 が入っています。
- 他の選択肢 5: count の中身がそのまま出ると考えると出る答えですが、表示されるのは比べた結果です。
- 他の選択肢 エラーになる: != は正しい記号です。
- 覚えておくこと: != は == の反対。

## 10. if・else [Starter]

概要: 条件が true のときだけ処理を実行する。それ以外は else 側を実行する。
考え方: if は分かれ道。条件が true なら右の道、false なら else の道。通るのはどちらか一方だけ。

重要ポイント:
- if の後ろには、true か false になる条件を書く。
- 条件が true のとき、直後の { } の中が実行される。
- else を書くと、条件が false のときに else の { } が実行される。
- if と else の両方が実行されることはない。

コード:
```swift
let score = 55
if score >= 70 {
  print("合格")
} else {
  print("不合格")
}
```

なぜ重要か: アプリの「ログイン済みなら〜」「記録が0件なら〜」といった振る舞いは、すべてこの分岐でできている。
注意: 条件は true / false になる式である必要がある。数や文字をそのまま条件に書くことはできない。

確認問題:
Q1. このコードの出力はどれですか？ [Starter]
```swift
let score = 55
if score >= 70 {
  print("合格")
} else {
  print("不合格")
}
```
A. 合格
B. 不合格
C. 合格 と 不合格
D. 何も表示されない
正解: B
解説: score は 55 なので score >= 70 は false です。よって else 側が実行され、不合格 だけが表示されます。

詳しい解説:
- 用語・考え方: if は「条件が true のときだけ、直後の { } の中を実行する」という指示です。else を書くと、条件が false のときに else の { } が実行されます。両方が実行されることはありません。
- コードの流れ: score には 55 が入っている。
- コードの流れ: 条件 score >= 70 は「55 は 70 以上か？」という質問で、答えは false。
- コードの流れ: false なので if の { } は飛ばされ、else の { } が実行される。
- コードの流れ: print("不合格") だけが実行される。
- 正解になる理由: 条件が false なので else 側だけが動き、不合格 が1回だけ表示されます。
- 他の選択肢 合格: 条件が true のときの結果です。55 は 70 以上ではありません。
- 他の選択肢 合格 と 不合格: if と else はどちらか一方だけが実行されます。両方が実行されることはありません。
- 他の選択肢 何も表示されない: else が書かれているので、条件が false でも必ずどちらかが実行されます。
- 関連例:
```swift
let score = 80
if score >= 70 {
  print("合格")
} else {
  print("不合格")
}
```
- 関連例の出力: 合格
- 関連例の説明: 同じ形のコードでも score を 80 にすると条件が true になり、実行される側が入れ替わります。
- 覚えておくこと: if と else は、どちらか一方だけ。

Q2. else の役割として正しいのはどれですか？ [Starter]
```swift
let isMember = true
if isMember {
  print("会員")
} else {
  print("未登録")
}
```
A. 条件が true のときに実行される
B. 条件が false のときに実行される
C. 条件を2回調べる
D. if を無効にする
正解: B
解説: else は条件が false だったときに実行される側です。true のときは if の { } 側だけが実行されます。

詳しい解説:
- 用語・考え方: else は「それ以外のとき」を表します。if の条件が false だったときに実行される受け皿です。
- コードの流れ: isMember には true が入っている。
- コードの流れ: if の条件が true なので、if の { } の中が実行され 会員 が表示される。
- コードの流れ: else の { } は実行されない。
- コードの流れ: もし isMember が false なら、逆に else 側の 未登録 だけが実行される。
- 正解になる理由: else は条件が false のときの受け皿です。true のときは if 側だけが実行されます。
- 他の選択肢 条件が true のときに実行される: それは if の { } 側の役割です。else はその反対側を担当します。
- 他の選択肢 条件を2回調べる: 条件を調べるのは1回だけです。その1回の答えで、どちらを実行するかが決まります。
- 他の選択肢 if を無効にする: else は if を打ち消すものではなく、if と組になって「どちらか一方」を選ぶ仕組みです。
- 覚えておくこと: if は「そのとき」、else は「それ以外のとき」。

Q3. if の書き方として正しい行はどれですか？ [Starter]

解説: 条件には比較を書くので == や >= を使います。= は代入なので条件にはなりません。条件の後ろは { で始めます。C は閉じ括弧と { が無いため不完全です。Swiftでは if (score >= 70) { } のように条件を丸括弧で囲む書き方自体は可能です。

詳しい解説:
- 用語・考え方: if の後ろには true か false になる質問（比較）を書き、その後ろを { で始めます。質問には == や >= のような比較の記号を使います。
- 正解になる理由: if score >= 70 { は「score が 70 以上なら」という質問になっていて、その後ろが { で始まっているため正しい形です。
- 他の選択肢 if score = 70 {: = は「入れる」動作なので、質問になっていません。等しいか調べたいときは == を使います。
- 他の選択肢 if (score >= 70: 質問の部分は正しいのですが、開いた ( が閉じておらず、{ もありません。なお Swift でも if (score >= 70) { } のように丸括弧で囲む書き方自体は可能です。
- 他の選択肢 if score >= 70 then: then は他の言語で使う書き方です。Swift では使わず、{ } で範囲を示します。
- 覚えておくこと: if の条件は比較。続きは { から。

## 11. { } と Scope [Starter]

概要: { } は処理のまとまりを表す。その中で作った名前は、外からは使えない。
考え方: { } は「部屋」。部屋の中で作った名前は部屋の外に持ち出せない。この有効範囲を Scope と呼ぶ。

重要ポイント:
- { } は処理のまとまり（ブロック）を表す記号。
- { } の中で let / var で作った名前は、その { } の中だけで使える。
- この「名前が使える範囲」を Scope（スコープ）と呼ぶ。
- if の { } も、後で学ぶ関数の { } も、同じく範囲を表している。

コード:
```swift
let count = 3
if count > 0 {
  let message = "今日も行く"
  print(message)
}
```

なぜ重要か: 「さっき作ったはずの名前が使えない」というエラーの正体はほぼこれ。どの { } の中にいるかを意識できると、コードの構造が見えてくる。
注意: { } の中で作った名前を外で使うとエラーになる。外でも使いたいなら、{ } の外側で名前を作る。

確認問題:
Q1. このコードはどうなりますか？ [Starter]
```swift
let count = 3
if count > 0 {
  let message = "今日も行く"
}
print(message)
```
A. 今日も行く と表示される
B. 何も表示されない
C. message が { } の外では使えずエラーになる
D. 空行が表示される
正解: C
解説: message は if の { } の中で作られたので、有効範囲はその { } の中だけです。外側の print では使えずエラーになります。

詳しい解説:
- 用語・考え方: { } は処理のまとまりを表す記号です。{ } の中で let や var を使って作った名前は、その { } の中でだけ使えます。この「名前が使える範囲」を Scope（スコープ）と呼びます。
- コードの流れ: count は { } の外で作られているので、この後どこでも使える。
- コードの流れ: message は if の { } の中で作られている。
- コードの流れ: { } が閉じた時点で、message は使えなくなる。
- コードの流れ: 最後の print(message) は範囲の外なので、Swift はこのコードを受け付けず、実行を始めることができない。
- 正解になる理由: 文字が表示されるかどうか以前に、名前が見つからないためコードとして成立しません。動かしてみて何も出ない、のではなく、そもそも動かせない状態です。
- 他の選択肢 今日も行く と表示される: message が最後まで残ると考えると出る答えですが、{ } を出た時点で使えなくなります。
- 他の選択肢 何も表示されない: 何も起きずに正常終了するのではなく、動かす前の段階で止められます。
- 他の選択肢 空行が表示される: 名前の中身が空になるのではなく、名前そのものが存在しない扱いになります。
- 関連例:
```swift
let count = 3
let message = "今日も行く"
if count > 0 {
  print(message)
}
```
- 関連例の出力: 今日も行く
- 関連例の説明: message を { } の外側で作れば、中からも外からも使えます。外側で作った名前は、内側からは見えます。
- 覚えておくこと: { } の中で作った名前は、外に持ち出せない。

Q2. { } が表しているものはどれですか？ [Starter]
```swift
if count > 0 {
  print(count)
}
```
A. 処理のまとまりと、その中だけで有効な名前の範囲
B. 計算の順番
C. 文字の値
D. コメント
正解: A
解説: { } は処理のまとまりを表し、同時にその中で作った名前が有効な範囲（Scope）も決めます。

詳しい解説:
- 用語・考え方: { } は「ここからここまでが1つのまとまり」を示す記号です。同時に、その中で作った名前が使える範囲（Scope）も決めます。
- 正解になる理由: { } には「まとめて実行する範囲」と「名前が有効な範囲」という2つの意味があり、その両方を含む説明が正解になります。
- 他の選択肢 計算の順番: 計算の順番をまとめるのは丸括弧 ( ) です。{ } とは別の記号です。
- 他の選択肢 文字の値: 文字は " " で囲みます。
- 他の選択肢 コメント: 人へのメモは // で書きます。
- 覚えておくこと: { } ＝ 処理のまとまり ＋ 名前の有効範囲。

Q3. message を print できるようにするには、どの書き方が正しいですか？ [Starter]
```swift
// message を if の外でも表示したい
```
A. if の { } の中で let message を作る
B. if の { } より前で let message を作る
C. print を { } の前に書く
D. { } を2つ重ねる
正解: B
解説: 外でも使いたい名前は、外側の範囲で作ります。if の前で作れば、if の中からも後ろからも使えます。

詳しい解説:
- 用語・考え方: 名前は、作った場所の { } の中でしか使えません。逆に、外側で作った名前は内側からも使えます。だから「使いたい範囲より外側で作る」のが基本になります。
- 正解になる理由: if より前（外側）で作れば、if の中でも、if が終わった後でも使えます。
- 他の選択肢 if の { } の中で let message を作る: それが今の状態で、外から使えないという問題そのものです。
- 他の選択肢 print を { } の前に書く: 作られる前の場所で使うことになるので、解決しません。
- 他の選択肢 { } を2つ重ねる: 内側に入れ子を増やしても外からは見えません。むしろ使える範囲は狭くなります。
- 覚えておくこと: 使いたい範囲より外側で名前を作る。

## 12. nilとは何か [Starter]

概要: nil は「値が無い」ことを表す。0 や "" のような「値がある状態」とは違う。
考え方: 0 は「0という値がある」、"" は「長さ0の文字がある」。nil は「そもそも値が入っていない」。空の箱ではなく、箱そのものが空欄。

重要ポイント:
- nil は「値が存在しない」ことを表す特別な書き方。
- 0 や "" は値が存在している状態で、nil とは違う。
- String や Int のような普通の型に nil を入れることはできない。
- nil を入れられる型が Optional（次のレッスンで学ぶ）。

コード:
```swift
let nickname: String = "Yuki"
let emptyText: String = ""
```

なぜ重要か: 現実のデータには「まだ入力されていない」「見つからなかった」が必ずある。それを 0 や "" でごまかさず nil で表すのが Swift の考え方。
注意: "未入力を 0 で表す" ようなやり方は、本当の 0 と区別できなくなる。無い状態は nil で表す。

確認問題:
Q1. nil の意味として正しいのはどれですか？ [Starter]
```swift
// nil が表すもの
```
A. 値が存在しないこと
B. 値が 0 であること
C. 文字が空であること
D. エラーが起きたこと
正解: A
解説: nil は「値が存在しない」ことを表します。0 や空文字は値が存在している状態なので、nil とは別です。

詳しい解説:
- 用語・考え方: nil は「値が存在しない」ことを表す特別な書き方です。「空っぽの値が入っている」のではなく、「そもそも何も入っていない」状態を指します。
- 正解になる理由: まだ入力されていない項目や、探したけれど見つからなかった場合など、「値がない」ことをはっきり表すために使います。
- 他の選択肢 値が 0 であること: 0 は「0 という数がある」状態です。たとえば「今月の来店回数が 0 回」と「まだ集計していない」は意味が違います。前者が 0、後者が nil です。
- 他の選択肢 文字が空であること: "" は「長さ 0 の文字がある」状態で、値としては存在しています。
- 他の選択肢 エラーが起きたこと: nil はエラーではなく、正常な状態の1つです。
- 覚えておくこと: nil は「無い」。0 や "" は「有る」。

Q2. "" と nil の違いの説明として正しいのはどれですか？ [Starter]
```swift
let emptyText: String = ""
```
A. どちらも同じ意味
B. "" は長さ0の文字という値、nil は値そのものが無い状態
C. "" のほうが nil より小さい
D. nil は文字の一種
正解: B
解説: "" は「長さ0の文字列」という値が存在している状態です。nil は値が存在しないことを表すので、意味が違います。

詳しい解説:

## 14. if letでOptionalを取り出す [Starter]

## 15. 関数の定義と実行 [Starter]

概要: func で処理に名前を付ける。定義しただけでは動かず、呼び出したときに実行される。

- func で始めると、処理のまとまりに名前を付けられる（関数の定義）。
- 処理の中身は { } の中に書く。
- 定義しただけでは実行されない。名前() と書いて呼び出すと実行される。
- 一度定義すれば、何度でも呼び出せる。


C. 何も表示されない
D. エラーになる

詳しい解説:
- 用語・考え方: func は「この処理に名前を付ける」というキーワードで、これを関数の定義と呼びます。処理の中身は { } の中に書きます。定義しただけでは動かず、名前の後ろに ( ) を付けて呼び出したときに初めて中身が実行されます。

- コードの流れ: 4行目の showGym() で呼び出しが起き、{ } の中の print が実行される。
- コードの流れ: Fit24 が表示される。
- 正解になる理由: 最後の行に呼び出しがあるため、中身の print が実行されます。
- 他の選択肢 showGym: 関数の名前そのものが表示されることはありません。表示されるのは print に書いた中身です。
- 他の選択肢 何も表示されない: 定義だけなら何も起きませんが、この問題には呼び出しの行があります。
- 他の選択肢 エラーになる: 定義も呼び出しも正しい書き方です。

## 16. ()・引数・return [Starter]

概要: ( ) は関数の受け渡し口。渡す値を引数、返ってくる値を戻り値と呼び、return で返す。
考え方: 関数は自動販売機。引数はお金を入れる口（( ) の中）、return は出てくる商品。

重要ポイント:
- 関数定義の ( ) の中には、受け取る値（引数）を 名前: 型 の形で書く。
- 呼び出すときは ( ) の中に実際の値を渡す。
- -> の後ろには返す値の型を書く。
- return はその値を呼び出し元に返し、関数を終える。

コード:
```swift
func doubled(value: Int) -> Int {
  return value * 2
}
print(doubled(value: 5))
```

なぜ重要か: 引数と戻り値が分かると、関数を「入力を渡すと結果が返ってくる部品」として読めるようになる。これが実務のコードを読む中心になる。
注意: -> で戻り値の型を書いたのに return を書かないとエラーになる。逆に戻り値が無い関数では return で値を返せない。

確認問題:
Q1. このコードの出力はどれですか？ [Starter]
```swift
func doubled(value: Int) -> Int {
  return value * 2
}
print(doubled(value: 5))
```
A. 5
B. 10
C. value * 2
D. エラーになる
正解: B
解説: 5 が引数 value に渡され、value * 2 が評価されて 10 が return されます。その戻り値が print されます。

詳しい解説:
- 用語・考え方: 関数は値を受け取って、結果を返すことができます。受け取る値を引数、返す値を戻り値と呼びます。定義の ( ) の中に受け取る値を書き、-> の後ろに返す値の型を書きます。return は、その結果を呼び出した場所に返す指示です。
- コードの流れ: print(doubled(value: 5)) では、まず内側の doubled(value: 5) が実行される。
- コードの流れ: 渡した 5 が、引数 value に入る。
- コードの流れ: { } の中で value * 2 が 5 * 2 として計算され、10 になる。
- コードの流れ: return がその 10 を呼び出した場所へ返す。
- コードの流れ: print が、返ってきた 10 を表示する。
- 正解になる理由: 渡した 5 が関数の中で2倍され、10 が返って表示されます。

## 17. .・Property・Method [Starter]

概要: . は「〜の」。値が持つデータが property、値が持つ動作が method。
考え方: 値を「機能付きの道具」と見る。userName.count は「その文字列の文字数（データ）」、userName.uppercased() は「大文字にする動作」。

重要ポイント:
- . は「〜の」を表し、値が持つものにアクセスする記号。
- property は値が持っているデータ（例：文字列の count は文字数）。
- method は値に対して行う動作で、呼び出すので ( ) が付く。
- ( ) が付いていなければ property、付いていれば method と見分けられる。

コード:
```swift
let userName = "Yuki"
print(userName.count)
print(userName.uppercased())
```

なぜ重要か: Swift の標準機能はほぼすべて property と method の形で提供される。この2つを見分けられると、初めて見るコードでも「データか動作か」を判断できる。
注意: ( ) を付けない場合は、動作を実行せずに『その動作そのもの』を指してしまい、期待した結果になりません。使う場所によっては型が合わずエラーになります。

確認問題:

C. どちらも同じもの
D. property は数値専用、method は文字専用
正解: B
解説: property は値が持っているデータで、method は値に対して行う動作です。method は呼び出すので ( ) が付きます。

詳しい解説:
- 用語・考え方: . は「〜の」を意味し、値が持っているものを取り出す記号です。値がもともと持っている情報を property、値に対して行う動作を method と呼びます。method には「実行して」の合図である ( ) が付きます。
- 正解になる理由: userName.count は「その文字の文字数」という情報（property）、userName.uppercased() は「大文字にする」という動作（method）です。( ) が付いているかどうかで見分けられます。
- 他の選択肢 property は動作、method はデータ: 説明が逆です。動作のほうに ( ) が付きます。
- 他の選択肢 どちらも同じもの: 情報を見ることと、動作をさせることは別です。
- 他の選択肢 property は数値専用、method は文字専用: 値の種類による区別ではありません。文字にも数にも、property と method の両方があります。
- 覚えておくこと: ( ) が無ければ情報、あれば動作。

- 関連例の出力: 4

- 関連例の説明: count は情報なので数がそのまま出て、uppercased() は動作なので大文字にした結果が返ります。

## 18. Array・Index [Starter]

概要: Array は順番の付いた複数の値。何番目かを表す番号が index で、0 から始まる。
考え方: Array は棚に並んだ値。棚の番号（index）は 0 から数える。存在しない番号を指すと実行時に止まる。

重要ポイント:
- Array は同じ型の値を順番に並べて持つ型で、[ ] で作る。
- index は「何番目か」を表す番号で、0 から始まる。
- 配列名[番号] でその位置の値を取り出せる。
- .count は要素の個数を表す property。範囲外の index を指定すると実行時にエラーで止まる。

コード:
```swift
let scores = [80, 65, 90]
print(scores[0])
print(scores.count)
```

なぜ重要か: 記録一覧、検索結果、履歴など、アプリの画面に並ぶものはほぼ Array。index の数え方を間違えると1件ずれたり落ちたりする。
注意: index は 0 から始まるので、3個の要素がある Array の最後の index は 2。3 を指定すると実行時に止まる。

確認問題:
Q1. このコードの出力はどれですか？ [Starter]
```swift
let scores = [80, 65, 90]
print(scores[1])
```
A. 80
B. 65
C. 90
D. 1
正解: B
解説: index は 0 から始まるので、scores[0] が 80、scores[1] が 65 です。よって 65 が表示されます。

詳しい解説:
- 用語・考え方: Array は複数の値を順番に並べて持つ入れ物で、[ ] を使って作ります。何番目かを表す番号を index と呼び、0 から数え始めます。名前[番号] と書くと、その位置の値を取り出せます。
- コードの流れ: scores には 80, 65, 90 がこの順で入っている。
- コードの流れ: index は 0 から始まるので、80 が 0 番、65 が 1 番、90 が 2 番。
- コードの流れ: scores[1] は 1 番の値、つまり 65 になる。
- 正解になる理由: 番号が 0 から始まるため、[1] は先頭ではなく2番目の 65 を指します。
- 他の選択肢 80: [1] が1番目＝先頭だと考えると出る答えです。先頭は [0] です。
- 他の選択肢 90: 最後の値の index は [2] です。
- 他の選択肢 1: 書いた番号そのものが出ると考えると出る答えですが、取り出されるのはその位置にある中身です。
- 関連例:
```swift
let scores = [80, 65, 90]
print(scores[0])
print(scores[2])
```
- 関連例の出力: 80
90
- 関連例の説明: 先頭は [0]、3個あるときの最後は [2] です。番号と順番が1つずれることに慣れておくと間違えにくくなります。
- 覚えておくこと: index は 0 から。[1] は2番目。

Q2. Array の最初の要素の index はどれですか？ [Starter]
```swift
let scores = [80, 65, 90]
```
A. 0
B. 1
C. -1
D. 要素数と同じ番号
正解: A
解説: Swift の Array の index は 0 から始まります。最初の要素は scores[0] で取り出します。

詳しい解説:
- 用語・考え方: index は「先頭から何個ずれているか」を表す番号だと考えると分かりやすいです。先頭は 0 個ずれているので 0 になります。
- 正解になる理由: 先頭の値は scores[0] で取り出します。日常の数え方（1番目）とは1つずれます。
- 他の選択肢 1: 日常では「1番目」と数えますが、Swift の index は 0 から始まります。この 1 のずれが間違いの元になりやすい所です。
- 他の選択肢 -1: 負の番号は使えません。
- 他の選択肢 要素数と同じ番号: 3個ある場合の [3] は範囲の外で、使うとプログラムが途中で止まります。
- 覚えておくこと: 先頭は 0 番。

Q3. このコードを実行するとどうなりますか？ [Starter]

詳しい解説:
- 用語・考え方: index は 0 から始まるので、3個の値がある Array で使える番号は 0・1・2 の3つだけです。存在しない番号を指定すると、Swift はその場でプログラムを止めます。
- コードの流れ: scores には3個の値が入っている。
- コードの流れ: 使える index は 0, 1, 2 の3つ。
- コードの流れ: scores[3] は存在しない位置を指している。

- 覚えておくこと: 最後の index は「個数 - 1」。

## 19. forで1つずつ取り出す [Starter]

概要: for は Array の値を先頭から1つずつ取り出して、同じ処理を繰り返す。
考え方: for は「棚の値を1つずつ手に取る」動作。取り出した値に名前が付き、その名前で { } の中の処理が回数分実行される。

重要ポイント:
- for 名前 in 配列 と書くと、先頭から順に1つずつ取り出せる。
- 取り出した値に付けた名前は、その { } の中だけで使える。
- 繰り返しの回数は要素の個数と同じ。
- 取り出される順番は Array に並んでいる順番のまま。

コード:
```swift
let counts = [2, 3, 1]
for count in counts {
  print(count)
}
```

なぜ重要か: 一覧の全件に同じ処理をする場面は非常に多い。index を自分で計算しなくても済むため、範囲外エラーも起きにくい。
注意: 取り出した名前（count）が使えるのは { } の中だけ。外で使うとエラーになる。

確認問題:
Q1. このコードの出力はどれですか？ [Starter]
```swift
let counts = [2, 3, 1]
for count in counts {
  print(count)
}
```
A. 2 3 1 の順に3行
B. 1 2 3 の順に3行
C. 3 だけ
D. counts と1行
正解: A
解説: for は Array に並んでいる順番で1つずつ取り出します。2、3、1 の順に print されるので3行表示されます。

詳しい解説:
- 用語・考え方: for 名前 in 配列 と書くと、配列の先頭から値を1つずつ取り出して、{ } の中の処理をその回数だけ繰り返します。取り出した値は毎回、指定した名前に入ります。
- コードの流れ: 1回目: 先頭の 2 が count に入り、print が 2 を表示する。
- コードの流れ: 2回目: 次の 3 が count に入り、3 を表示する。
- コードの流れ: 3回目: 最後の 1 が count に入り、1 を表示する。
- コードの流れ: 取り出す値が無くなったので、繰り返しが終わる。
- 正解になる理由: 並んでいる順にそのまま取り出されるので、2, 3, 1 の順で3行表示されます。
- 他の選択肢 1 2 3 の順に3行: 小さい順に並べ替えられると考えると出る答えですが、for は並べ替えません。並び順のまま取り出します。
- 他の選択肢 3 だけ: 最後の1回だけが実行されると考えると出る答えですが、要素の数だけ繰り返されます。
- 他の選択肢 counts と1行: 配列の名前がそのまま表示されるのではなく、中身が1つずつ取り出されます。
- 関連例:
```swift
let exercises = ["squat", "bench"]
for name in exercises {
  print(name)
}
```
- 関連例の出力: squat
bench
- 関連例の説明: 取り出した値に付ける名前は自由に決められます。中身が文字でも、仕組みは同じです。
- 覚えておくこと: for は並び順のまま、1つずつ。

Q2. このコードで print は何回実行されますか？ [Starter]
```swift
let counts = [2, 3, 1]
for count in counts {
  print(count)
}
```
A. 1回
B. 2回
C. 3回
D. 6回
正解: C
解説: 繰り返しの回数は要素の個数と同じです。要素が3個なので print は3回実行されます。

詳しい解説:
- 用語・考え方: 繰り返しの回数は、配列に入っている値の個数と同じになります。回数を自分で数えて指定する必要はありません。
- 正解になる理由: counts には 2, 3, 1 の3個が入っているので、{ } の中の print は3回実行されます。
- 他の選択肢 1回: print は1行しか書かれていませんが、for によって要素の数だけ繰り返し実行されます。
- 他の選択肢 2回: 先頭の値が 2 なので「2回」と考えると出る答えですが、回数は値の中身ではなく個数で決まります。
- 他の選択肢 6回: 値を足した数（2 + 3 + 1）と考えると出る答えです。回数はあくまで個数です。
- 覚えておくこと: 回数 ＝ 要素の個数。

Q3. for で取り出した count が使える範囲はどれですか？ [Starter]
```swift
let counts = [2, 3, 1]
for count in counts {
  print(count)
}

```

B. コード全体
C. for より前だけ
D. どこでも使えない

詳しい解説:
- 用語・考え方: for の後ろに書いた名前（ここでは count）は、その回に取り出した値を受け取るための名前で、{ } の中だけで使えます。繰り返しが終わると使えなくなります。
- コードの流れ: for が counts から値を1つずつ取り出し、count に入れる。
- コードの流れ: { } の中では count を使える。
- コードの流れ: { } が閉じると count は使えなくなる。
- コードの流れ: 最後の print(count) は範囲の外なので、Swift はこのコードを受け付けず、実行を始めることができない。
- 正解になる理由: 「{ } の中だけで有効」という点は、レッスン11で学んだ { } と名前の範囲（Scope）の話と同じ仕組みです。
- 他の選択肢 コード全体: for の外でも使えると考えると出る答えですが、有効なのは { } の中だけです。
- 他の選択肢 for より前だけ: 作られる前の場所で使えることはありません。
- 他の選択肢 どこでも使えない: { } の中では使えます。実際、繰り返しの中の print(count) は正しく動きます。
- 覚えておくこと: for で取り出した名前も、{ } の中だけ。

## 20. 同じ記号でも文脈で意味が変わる [Starter]

概要: let・?・( )・{ } は、書かれる場所によって役割が変わる。文脈で読む習慣を付ける。
考え方: 記号の意味は「暗記」ではなく「どこに書かれているか」で決まる。前後を見てから意味を決めるのが、コードを読める人の読み方。

重要ポイント:
- let は名前の宣言にも使うが、if let では Optional の中身の取り出しにも使う。
- ? は型名の後ろに付くと Optional を表します。Swift Starterで扱うのはこの使い方ですが、? は書かれる位置によって役割が変わる記号だと覚えておきましょう。
- ( ) は関数定義の引数リスト、関数の呼び出し、計算の順番のまとめ、の3つの使い方がある。
- { } は if・for・func いずれでも「処理のまとまりと有効範囲」を表す。どの範囲かは直前の行が決める。

コード:
```swift
let base: Int? = 3
if let value = base {
  print((value + 1) * 2)
}
```

なぜ重要か: 同じ記号を毎回違う機能として覚えるとキリがない。「文脈で意味が決まる」と分かれば、初めて見る書き方でも前後から意味を推測できる。
注意: 記号を1つの意味だけで覚えると、別の文脈で出てきたときに読めなくなる。まず前後の行を見る。

確認問題:
Q1. 1行目の let と2行目の let の違いの説明として正しいのはどれですか？ [Starter]
```swift
let base: Int? = 3
if let value = base {
  print(value)
}
```
A. どちらも新しい名前に値を入れる宣言だが、2行目は Optional の中身を取り出す形
B. どちらもまったく同じ意味
C. 1行目は取り出し、2行目は宣言
D. 2行目の let は書かなくてもよい
正解: A
解説: 1行目は値に名前を付ける普通の宣言です。2行目の if let は Optional の中身がある場合だけ取り出して名前を付ける形で、役割が違います。

詳しい解説:
- 用語・考え方: 同じ let でも、書かれる場所によって役割が変わります。1行目の let は「新しい名前を作って値を入れる」宣言です。2行目の if let は「中身があれば取り出して、新しい名前に入れる」という取り出しの形で、失敗することもあります。
- コードの流れ: 1行目: base という名前が作られ、Int?（数が入っているか nil）として 3 が入る。
- コードの流れ: 2行目: if let が base の中身を取り出そうとする。
- コードの流れ: 取り出せたので value という名前に 3 が入り、{ } の中が実行される。
- 正解になる理由: どちらも「新しい名前に値を入れる」点は共通ですが、2行目は Optional から中身を取り出し、取り出せたときだけ先に進むという条件付きの動きが加わっています。
- 他の選択肢 どちらもまったく同じ意味: 1行目は必ず成功しますが、2行目は中身が nil なら取り出せず { } が実行されません。この違いがあります。
- 他の選択肢 1行目は取り出し、2行目は宣言: 説明が逆になっています。
- 他の選択肢 2行目の let は書かなくてもよい: let を書かないと「取り出して新しい名前に入れる」形になりません。
- 関連例:
```swift
let base: Int? = nil
if let value = base {
  print(value)
} else {
  print("値なし")
}
```
- 関連例の出力: 値なし
- 関連例の説明: 同じ if let でも、中身が nil なら取り出しに失敗します。普通の let 宣言は必ず成功するので、ここが大きな違いです。
- 覚えておくこと: let は場所によって「作る」と「取り出す」に変わる。

Q2. このコードの ( ) のうち、value + 1 を囲んでいるものの役割はどれですか？ [Starter]
```swift
let value = 3
print((value + 1) * 2)
```
A. 関数の呼び出し
B. 引数リストの宣言
C. 計算の順番をまとめる
D. Optional を表す
正解: C
解説: ( ) は文脈で役割が変わります。ここでは先に value + 1 を計算させるためのまとまりで、結果 4 * 2 = 8 が表示されます。

詳しい解説:
- 用語・考え方: ( ) も場所によって役割が変わります。関数の定義では受け取る値を並べる場所、関数の呼び出しでは「実行して」の合図、計算の中では「ここを先に計算する」というまとまりを表します。
- コードの流れ: 内側の (value + 1) が先に計算され、3 + 1 で 4 になる。
- コードの流れ: 次に 4 * 2 が計算され、8 になる。
- コードの流れ: 外側の ( ) は print を呼び出す合図で、計算のまとまりではない。
- コードの流れ: print が 8 を表示する。
- 正解になる理由: 内側の ( ) は、掛け算より先に足し算をさせるためのまとまりです。同じ1行の中で、外側と内側の ( ) が別々の役割を持っています。
- 他の選択肢 関数の呼び出し: それは print の直後にある外側の ( ) の役割です。同じ行に両方の使い方が出てきています。
- 他の選択肢 引数リストの宣言: それは func で関数を定義するときの ( ) の役割です。ここは定義ではありません。
- 他の選択肢 Optional を表す: Optional を表すのは型名の後ろの ? です。( ) とは別の記号です。
- 覚えておくこと: ( ) は場所しだいで、呼び出し・引数・計算のまとまりに変わる。

Q3. { } の意味の説明として正しいのはどれですか？ [Starter]
```swift
let isMember = true
let counts = [2, 3, 1]
if isMember {
  print("会員")
}
for count in counts {
  print(count)
}
```
A. if では条件、for では配列を表す
B. どちらも処理のまとまりと有効範囲を表し、何の範囲かは直前の行で決まる
C. if の { } だけが処理のまとまり
D. { } は飾りで意味はない
正解: B
解説: { } はいつでも「処理のまとまりとその中で有効な名前の範囲」を表します。それが条件付き実行なのか繰り返しなのかは、直前の if や for が決めます。

詳しい解説:
- 用語・考え方: { } はどこに出てきても「処理のまとまりと、その中で有効な名前の範囲」を表します。ただし、そのまとまりが「条件付きで1回だけ実行される」のか「繰り返し実行される」のかは、直前に書かれた if や for が決めます。
- コードの流れ: if isMember { ... } は、条件が true のときに中を1回だけ実行する。
- コードの流れ: for count in counts { ... } は、要素の数だけ中を繰り返し実行する。
- コードの流れ: どちらの { } も、中で作った名前は外から使えないという点は共通している。
- 正解になる理由: { } 自体の意味は変わりません。変わるのは「どういうときに、何回実行されるか」で、それを決めているのは直前の行です。記号の意味を1つに決めつけず、前後を見て読むことが大切です。
- 他の選択肢 if では条件、for では配列を表す: 条件は if の後ろ、配列は in の後ろに書かれていて、どちらも { } の外側です。{ } はその後ろのまとまりを表します。
- 他の選択肢 if の { } だけが処理のまとまり: for や func の { } も同じくまとまりです。同じ記号が同じ役割で使われています。
- 他の選択肢 { } は飾りで意味はない: { } を消すと、どこまでが条件や繰り返しの対象なのか分からなくなります。範囲を示す大切な記号です。
- 覚えておくこと: { } は常に「まとまり」。回数や条件は直前の行が決める。
