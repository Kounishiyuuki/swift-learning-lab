## 01. 値・let / var・型・型推論 [Beginner]

概要: Swiftの土台。値に名前を付け、型で安全性を確保する仕組みを理解する。
考え方: 変数は「箱」よりも、「値に付けた名前」と考えると後で理解しやすい。let は再代入できない名前、var は再代入できる名前。

重要ポイント:
- let は再代入不可、var は再代入可能。
- Int / Double / String / Bool は代表的な基本型。
- 型推論により、明示しなくても Swift が型を判断できる。
- Swift は型安全で、意味の合わない値の操作をコンパイル時に多く検出する。

コード:
```swift
let userName = "Yuki"
var score = 10
score += 5

let isPassed = score >= 12
print("\(userName): \(score), \(isPassed)")
```

なぜ重要か: アプリが大きくなるほど、「この値は変化するのか」「何型なのか」が設計そのものになる。SwiftUI の状態管理や API モデルでもこの基礎がそのまま使われる。
注意: プログラミングの = は「等しい」ではなく、右辺を評価して左辺へ代入する演算。

確認問題:
Q1. このコードの出力は？ [Beginner]
```swift
var score = 10
score += 5
print(score)
```
A. 5
B. 10
C. 15
D. コンパイルエラー
正解: C
解説: score は var なので変更可能。`score += 5` は `score = score + 5` と同じ意味で、10 + 5 = 15。

Q2. コンパイルエラーになるものは？ [Beginner]
```swift
let name = "Swift"
// 次のうち name に対して不可能なのは？
```
A. print(name)
B. let copy = name
C. name = "UIKit"
D. print("\(name)!")
正解: C
解説: `let` で宣言した name には再代入できない。読み取りや別の定数への代入は可能。

## 02. 数値型・型変換・オーバーフロー [Beginner]

概要: Int / UInt / Double / Float の違いと、安全な型変換を理解する。
考え方: 同じ『数字』でも型が違えば別物。Swiftは暗黙変換を控えめにして、意図しない計算を防ぐ。

重要ポイント:
- Intは一般的な整数、UIntは負数を持たない整数。
- Doubleは通常の小数計算で第一候補。
- 異なる数値型同士は明示変換が必要な場合が多い。
- 整数演算は範囲外になるとオーバーフローする。

コード:
```swift
let count: Int = 3
let price: Double = 120.5
let total = Double(count) * price
```

なぜ重要か: API値、JSON、画面入力、計算結果で型がずれることは多い。変換の意味を理解するとバグを減らせる。
注意: `Int(3.9)` は丸めではなく小数部分を切り捨てる。

確認問題:
Q1. result の型と値は？ [Beginner]
```swift
let a = 3
let b = 2.5
let result = Double(a) + b
```
A. Intの5
B. Doubleの5.5
C. Floatの5.5
D. コンパイルエラー
正解: B
解説: aをDoubleへ明示変換しているため5.5。

Q2. Int(3.9) の結果は？ [Basic]
```swift
let value = Int(3.9)
```
A. 3
B. 4
C. 3.9
D. nil
正解: A
解説: 小数部分が切り捨てられて3になる。

## 03. Tuple・Typealias [Beginner]

概要: 複数値を一時的にまとめるTupleと、型へ分かりやすい別名を付けるTypealiasを学ぶ。
考え方: Tupleは『小さな一時セット』。長く意味を持つデータならstructを検討する。

重要ポイント:
- Tupleは複数値を1つにまとめる。
- 要素へ名前を付けられる。
- 分解代入ができる。
- typealiasは既存型へ意味のある別名を付ける。

コード:
```swift
let user = (name: "Yuki", score: 90)
typealias UserID = String
let id: UserID = "u-001"
```

なぜ重要か: 関数から複数値を返すときや複雑な型を読みやすくするときに使う。
注意: Tupleが大きくなったらstructへ移す方が保守しやすい。

確認問題:
Q1. 出力は？ [Beginner]
```swift
let point = (x: 2, y: 5)
print(point.y)
```
A. 2
B. 5
C. x
D. コンパイルエラー
正解: B
解説: 名前付きTupleのy要素は5。

Q2. typealias の説明として正しいものは？ [Basic]
```swift
typealias UserID = String
```
A. 新しい実行時型を作る
B. StringにUserIDという別名を付ける
C. Stringを継承する
D. Optionalに変換する
正解: B
解説: typealiasは既存型の別名。

## 04. 演算子・比較・論理式 [Beginner]

概要: 算術・比較・論理演算子を組み合わせ、条件や計算結果を作る。
考え方: 式は「値を生み出すもの」。`score >= 60` も Bool という値を生み出す式。

重要ポイント:
- + - * / % で算術演算。
- == != > < >= <= は Bool を返す。
- && は AND、|| は OR、! は NOT。
- 文字列補間 `\(value)` で値を String に埋め込める。

コード:
```swift
let price = 1200
let count = 3
let total = price * count
let message = "合計は\(total)円です"
print(message)
```

なぜ重要か: if や guard の条件も最終的には Bool を作る式。比較演算を理解すると制御フローが自然に読める。
注意: `=` は代入、`==` は比較。混同しない。

確認問題:
Q1. result の値は？ [Beginner]
```swift
let a = 10
let b = 3
let result = a % b
print(result)
```
A. 0
B. 1
C. 3
D. 3.333...
正解: B
解説: `%` は剰余（余り）。10 ÷ 3 の余りは 1。

Q2. isValid は最終的に何になる？ [Beginner]
```swift
let age = 20
let hasTicket = false
let isValid = age >= 18 && hasTicket
```
A. true
B. false
C. nil
D. コンパイルエラー
正解: B
解説: `&&` は両方が true のときだけ true。年齢条件は true だが hasTicket が false なので false。

## 05. String・Character・Unicode [Basic]

概要: Swiftの文字列がUnicodeを正しく扱うことと、文字列indexが整数ではない理由を理解する。
考え方: 見た目の1文字は内部で複数のUnicode scalarから構成されることがある。

重要ポイント:
- StringはUnicode対応。
- Characterは人が認識する1文字に近い単位。
- String.Indexを使って安全に位置へアクセスする。
- prefix / suffix / splitなど実用操作を覚える。

コード:
```swift
let text = "Swift🍎"
print(text.count)
print(text.prefix(5))
```

なぜ重要か: ユーザー入力、検索、表示名、API文字列など、文字列処理はどのアプリでも必須。
注意: `text[0]` のようなInt添字アクセスはできない。

確認問題:
Q1. 先頭1文字を安全に取得する代表的な方法は？ [Basic]
```swift
let text = "Swift"
```
A. text[0]
B. text.first
C. text[Int(0)]
D. text.byte(0)
正解: B
解説: firstはCharacter?を返す。

Q2. text.count が数えるものとして最も近いのは？ [Basic]
```swift
let text = "A🍎"
```
A. UTF-8バイト数
B. Characterとしての文字数
C. メモリ容量
D. ASCIIコード
正解: B
解説: String.countはCharacter単位の数を返す。

## 06. if・switch・guard [Beginner]

概要: 条件によって実行するコードを変える。
考え方: 制御フローは「次にどの道を通るか」を決める仕組み。条件式そのものは Bool。

重要ポイント:
- if / else if / else で条件分岐。
- switch は複数パターンを網羅的に扱うのが得意。
- guard は「条件を満たさないなら早く抜ける」ために使う。
- Swift の switch は原則としてすべてのケースを扱う必要がある。

コード:
```swift
let score = 82

switch score {
case 90...100: print("A")
case 70..<90: print("B")
default: print("C")
}
```

なぜ重要か: 読みやすい分岐はバグを減らす。guard で異常系を先に処理すると、正常系のネストが浅くなる。
注意: switch の `case 70..<90` は 70 以上 90 未満。`...` と `..<` の違いに注意。

確認問題:
Q1. 出力は？ [Beginner]
```swift
let score = 75
if score >= 80 {
    print("A")
} else if score >= 60 {
    print("B")
} else {
    print("C")
}
```
A. A
B. B
C. C
D. 何も出ない
正解: B
解説: 75 >= 80 は false。次の 75 >= 60 が true なので B が出力され、その後の else は評価されない。

Q2. この guard の役割として最も近いものは？ [Basic]
```swift
func greet(name: String?) {
    guard let name else { return }
    print("Hello, \(name)")
}
```
A. name を必ず nil にする
B. nil なら関数を早期終了する
C. name をグローバル変数にする
D. 例外を投げる
正解: B
解説: guard let で Optional をアンラップし、nil なら return。以降では name を非 Optional として使える。

## 07. Pattern Matching・where・if case [Basic]

概要: switchを強力にするPattern Matchingを理解する。
考え方: switchは『値が一致するか』だけでなく『形が一致するか』を判定できる。

重要ポイント:
- Range、Tuple、Enumのassociated valueを分解できる。
- whereでcaseへ追加条件を書ける。
- if case / guard caseで1patternだけ判定できる。
- Optionalもpattern matchingできる。

コード:
```swift
let value = (200, "OK")
switch value {
case (200, let body): print(body)
default: break
}
```

なぜ重要か: enum中心の状態設計やレスポンス分岐で読みやすいコードを書くために重要。
注意: caseの順序で広いpatternが先に一致すると後ろへ到達しない。

確認問題:
Q1. body は何になる？ [Basic]
```swift
let value=(200,"OK")
switch value { case (200, let body): print(body); default: break }
```
A. 200
B. OK
C. Tuple全体
D. nil
正解: B
解説: 2要素目をlet bodyで取り出す。

Q2. where の役割は？ [Intermediate]
```swift
case let x where x > 10:
```
A. 型を作る
B. 一致した値へ追加条件を課す
C. Optional化する
D. ループ終了
正解: B
解説: pattern一致後に追加条件を適用する。

## 08. for・while・Range [Beginner]

概要: 同じ処理を繰り返し、コレクションを順番に処理する。
考え方: for-in は「要素を1つずつ取り出して名前を付ける」。配列を読む基本動作。

重要ポイント:
- `1...3` は 1,2,3 を含む ClosedRange。
- `0..<3` は 0,1,2。配列インデックスと相性が良い。
- for-in は配列や Range の各要素を順番に処理する。
- while は条件が true の間だけ繰り返す。

コード:
```swift
var total = 0
for number in 1...3 {
    total += number
}
print(total)
```

なぜ重要か: map / filter / reduce などの高階関数を理解する前に、for で何をしているのか追えることが重要。
注意: 無条件の while や、条件を更新しない while は無限ループになり得る。

確認問題:
Q1. 出力は？ [Beginner]
```swift
var total = 0
for i in 1...4 {
    total += i
}
print(total)
```
A. 4
B. 6
C. 10
D. 11
正解: C
解説: 1 + 2 + 3 + 4 = 10。`...` は終端の 4 を含む。

Q2. ループは何回実行される？ [Basic]
```swift
for _ in 0..<5 {
    print("Swift")
}
```
A. 4回
B. 5回
C. 6回
D. 無限
正解: B
解説: `0..<5` は 0,1,2,3,4 の5要素。アンダースコアは値を使わないことを表す。

## 09. 関数・引数・戻り値 [Basic]

概要: 処理に名前を付け、入力と出力を明確にする。
考え方: 関数は「入力 → 処理 → 出力」の小さな機械。責務を小さくすると読みやすい。

重要ポイント:
- 引数ラベルとパラメータ名は別にできる。
- `-> Type` が戻り値の型。
- 副作用の少ない関数はテストしやすい。
- 関数も型を持つため、変数に代入したり引数として渡せる。

コード:
```swift
func total(price: Int, count: Int) -> Int {
    price * count
}

let result = total(price: 500, count: 3)
```

なぜ重要か: 大きな処理を関数に分解すると、名前によって意図を表現でき、テスト単位も作りやすい。
注意: 同じ型の引数が複数ある場合、ラベルを雑にすると呼び出し側で意味が分からなくなる。

確認問題:
Q1. result の値は？ [Basic]
```swift
func double(_ value: Int) -> Int {
    value * 2
}
let result = double(4)
```
A. 2
B. 4
C. 8
D. コンパイルエラー
正解: C
解説: `_` により呼び出し時の引数ラベルを省略できる。4 * 2 = 8。

Q2. この関数の型として正しいものは？ [Basic]
```swift
func add(_ a: Int, _ b: Int) -> Int {
    a + b
}
```
A. Int
B. (Int, Int) -> Int
C. (Int) -> Int
D. Void -> Int
正解: B
解説: Int を2つ受け取り Int を返すので、関数型は `(Int, Int) -> Int`。

## 10. 引数ラベル・Default・Variadic・inout [Basic]

概要: 関数呼び出しを読みやすくし、特殊な入力方法を理解する。
考え方: 関数は処理だけでなくAPI。呼び出し側が自然に読める設計が重要。

重要ポイント:
- 外部引数ラベルと内部名を分けられる。
- default parameterで省略可能な引数を作れる。
- variadicは可変個数の引数を受け取る。
- inoutは呼び出し元の値そのものを変更する。

コード:
```swift
func greet(_ name: String, prefix: String = "Hello") {
    print("\(prefix), \(name)")
}
```

なぜ重要か: 標準ライブラリやApple APIの関数signatureを読む力に直結する。
注意: inoutは副作用が明確な場面で使う。

確認問題:
Q1. 出力は？ [Basic]
```swift
func greet(_ name:String,prefix:String="Hi"){print("\(prefix) \(name)")}
greet("Yuki")
```
A. Yuki
B. Hi
C. Hi Yuki
D. エラー
正解: C
解説: prefixの既定値Hiが使われる。

Q2. inout引数を渡す記号は？ [Intermediate]
```swift
func addOne(_ x: inout Int){x+=1}
var n=1
addOne(/* ? */ n)
```
A. $
B. &
C. @
D. !
正解: B
解説: inoutへは&nのように渡す。

## 11. 関数型・Higher-Order Function [Intermediate]

概要: 関数を値として保存・受け渡しできることを理解する。
考え方: Swiftでは『何をするか』そのものを値として扱える。

重要ポイント:
- 関数には型がある。
- 関数を変数へ代入できる。
- 関数を引数/戻り値として扱う関数を高階関数という。
- map/filterは高階関数の代表。

コード:
```swift
func add(_ a:Int,_ b:Int)->Int{a+b}
let operation: (Int,Int)->Int = add
```

なぜ重要か: クロージャやコールバック、DIを読む根本になる。
注意: `add` と `add(1,2)` は関数そのものと実行結果で別。

確認問題:
Q1. operation の型は？ [Basic]
```swift
func add(_ a:Int,_ b:Int)->Int{a+b}
let operation=add
```
A. Int
B. (Int, Int) -> Int
C. () -> Void
D. String
正解: B
解説: 2つのIntを受け取りIntを返す関数型。

Q2. 高階関数とは？ [Intermediate]
```swift
func apply(_ v:Int, operation:(Int)->Int)->Int{operation(v)}
```
A. 関数を値として受け取る/返す関数
B. 必ず再帰する関数
C. 非同期関数だけ
D. UIKit専用
正解: A
解説: 関数を引数または戻り値として扱う。

## 12. Closure・map / filter / reduce 入門 [Intermediate]

概要: 処理そのものを値として扱う。
考え方: クロージャは「名前のない関数」。map は各要素を変換、filter は残す要素を選別、reduce は1つに畳み込む。

重要ポイント:
- クロージャは `{ parameters in expression }` の形。
- map は要素数を保ちながら変換する。
- filter は条件に合う要素だけ残す。
- reduce は複数要素から1つの結果を作る。

コード:
```swift
let numbers = [1, 2, 3, 4]
let doubled = numbers.map { $0 * 2 }
let evens = doubled.filter { $0.isMultiple(of: 4) }
```

なぜ重要か: Swift / SwiftUI の API ではクロージャが大量に出てくる。ViewBuilder、Button action、非同期処理などの読解にも直結する。
注意: `map` は元配列を変更しない。新しい配列を返す。

確認問題:
Q1. result は？ [Intermediate]
```swift
let numbers = [1, 2, 3]
let result = numbers.map { $0 * 2 }
```
A. [1, 2, 3]
B. [2, 4, 6]
C. [1, 4, 9]
D. 6
正解: B
解説: map は各要素をクロージャで変換した新しい配列を返す。各要素を2倍して [2,4,6]。

Q2. result は？ [Intermediate]
```swift
let values = [1, 2, 3, 4]
let result = values.filter { $0 % 2 == 0 }
```
A. [1, 3]
B. [2, 4]
C. [true, false, true, false]
D. 10
正解: B
解説: filter はクロージャが true を返す要素だけ残す。偶数の 2 と 4 が残る。

## 13. @escaping・Capture・Capture List [Intermediate]

概要: クロージャが外側の値を保持する仕組みとescapingを理解する。
考え方: クロージャは外側の値を捕まえて後から使える。その保持が参照循環にもつながる。

重要ポイント:
- closureは外側の値をcaptureできる。
- @escapingは関数終了後にも保持される可能性があるclosure。
- classのselfを強くcaptureすると循環が起こる場合がある。
- [weak self]などcapture listで保持方法を制御。

コード:
```swift
onFinish = { [weak self] in
    self?.handleFinish()
}
```

なぜ重要か: UIKit completion、URLSession、Task、animationなどで頻出。
注意: weak selfを機械的に付けず、所有関係を考える。

確認問題:
Q1. @escaping が必要になる代表例は？ [Intermediate]
```swift
func load(completion: @escaping ()->Void){ /* 保存して後で呼ぶ */ }
```
A. すぐ実行して破棄
B. 関数終了後に保存して呼ぶ
C. Intを返すだけ
D. letを使う
正解: B
解説: 関数終了後にもclosureが生存する場合。

Q2. [weak self] を使う主な理由は？ [Intermediate]
```swift
callback = { [weak self] in self?.finish() }
```
A. selfを値型にする
B. 強参照循環を避ける
C. 同期化する
D. Optional禁止
正解: B
解説: closureとselfの循環を避けるために使うことがある。

## 14. Collection入門：Array・Set・Dictionary [Basic]

概要: 複数の値を目的に合わせてまとめる。
考え方: Array=順序付き、Set=重複なし、Dictionary=キーから値を引く。

重要ポイント:
- Array は順序を持ち、添字でアクセスする。
- Set は順序を前提とせず、一意な要素を保持する。
- Dictionary は Key: Value の対応を保持する。
- 存在しない Dictionary キーへのアクセス結果は Optional。

コード:
```swift
var scores = ["A": 90, "B": 75]
scores["C"] = 82

if let score = scores["C"] {
    print(score)
}
```

なぜ重要か: APIレスポンス、画面一覧、ID検索など、実アプリはコレクションの処理だらけ。型ごとの性質を使い分ける。
注意: 配列の存在しない index にアクセスすると実行時エラー。Dictionary は Optional を返す。

確認問題:
Q1. numbers の最終状態は？ [Basic]
```swift
var numbers = [1, 2]
numbers.append(3)
numbers.removeFirst()
```
A. [1, 2, 3]
B. [2, 3]
C. [1, 3]
D. [3]
正解: B
解説: append で [1,2,3]、removeFirst で先頭の 1 が削除され [2,3]。

Q2. Dictionary の scores["C"] の型は？ [Basic]

## 16. Set・集合演算 [Basic]

- 順序を前提にしない。

コード:
```swift
let a:Set=[1,2,3]

```

なぜ重要か: 選択済みID、権限、tag、重複排除に自然に使える。
注意: 表示順が必要ならArrayなど別構造を使う。

確認問題:
Q1. intersection結果は？ [Basic]
```swift

```
A. 1だけ
B. 3だけ
C. 3と4
D. 1,2,3,4
正解: B
解説: 共通要素3だけ。

Q2. Set要素に必要な代表Protocolは？ [Basic]
```swift
Set<MyType>()
```
A. Codable
B. Hashable
C. Observable
D. Sendableだけ
正解: B
解説: Setはhash値で要素を管理する。

詳しい解説:
- 用語・考え方: Set は「重複のない値の集まり」を表す型で、並び順を持たない代わりに「その値が既に入っているか」を高速に判定できる。この判定を成立させるために、要素の型は Hashable に適合している必要がある。Hashable は値から hash 値（値を要約した整数）を計算できることを保証し、さらに Equatable（== による同値比較）も要求する。
- コードの流れ: Set に値を入れるとき、まず要素の hash 値を計算し、格納先の候補を絞り込む。
- コードの流れ: hash 値が一致した要素同士だけを == で比較し、本当に同じ値かどうかを確定する。
- コードの流れ: 同じ値が既にあれば追加されない。これが重複排除の仕組み。
- コードの流れ: つまり要素型には hash の計算と == の判定の両方が必要で、その2つをまとめて要求するのが Hashable。
- 正解になる理由: Set<MyType> の MyType に必要なのは Hashable。Hashable は Equatable を継承しているため、hash 値による絞り込みと == による確定の両方が揃う。Int / String / Bool など標準の型は既に Hashable に適合しているので、そのまま Set に入れられる。
- 他の選択肢 Codable: Encodable と Decodable をまとめた別名で、JSON など外部表現との相互変換のための Protocol。保存や通信のためのものであり、重複判定とは無関係。
- 他の選択肢 Observable: 値の変化を観測して UI を更新するための仕組みで、主に SwiftUI の状態管理で使う。集合の要素条件とは無関係。
- 他の選択肢 Sendableだけ: Sendable は「並行処理の境界を越えて安全に渡せる」ことを表す契約で、スレッド安全性の話。重複判定には使えず、Sendable だけでは Set の要素にできない。
- 関連例:
```swift
struct Member: Hashable {
    let id: Int
    let name: String
}

var members: Set<Member> = []
members.insert(Member(id: 1, name: "Yuki"))
members.insert(Member(id: 1, name: "Yuki"))
print(members.count)
```
- 関連例の出力: 1
- 関連例の説明: すべての stored property が Hashable なら、struct は Hashable への適合を自動合成でき、== と hash(into:) が自動生成される。同じ内容の Member を2回入れても2回目は重複と判定されるため、要素数は 1 のまま。
- 覚えておくこと: Set の要素と Dictionary の Key は Hashable。hash で候補を絞り、== で確定する。

## 19. Optional・if let・guard let [Basic]

概要: 「値がある / ない」を型として安全に扱う。
考え方: Optional は空っぽになれる箱ではなく、`.some(value)` または `.none` の2状態を持つ型と考える。

重要ポイント:
- `String?` は String または nil。
- if let / guard let で安全にアンラップする。
- nil-coalescing `??` で nil のときの既定値を指定できる。
- 強制アンラップ `!` は nil ならクラッシュするため慎重に使う。

コード:
```swift
let nickname: String? = nil
let displayName = nickname ?? "Guest"
print(displayName)
```

なぜ重要か: API、ユーザー入力、検索結果など「存在しない可能性」は現実のアプリで必ず発生する。Optional はその可能性を型で表現する。
注意: `!` を「Optionalを消す記号」と覚えない。nil の可能性を無視して値を強制取得する操作。

確認問題:
Q1. 出力は？ [Basic]
```swift
let name: String? = nil
print(name ?? "Guest")
```
A. nil
B. Optional(nil)
C. Guest
D. クラッシュ
正解: C
解説: `??` は左側が nil の場合に右側を返す。したがって Guest。

詳しい解説:
- 用語・考え方: String? は「String が入っているか、nil か」を表す Optional 型。?? は nil 合体演算子（nil-coalescing operator）で、「左が nil なら右の既定値を使う」という意味になる。左の Optional を安全に外し、必ず値のある結果を返す。
- コードの流れ: name は String? 型で、値は nil。
- コードの流れ: print に渡す前に、name ?? "Guest" が先に評価される。
- コードの流れ: ?? は左の name を確認し、nil なので右側の "Guest" を採用する。
- コードの流れ: 結果は Optional が外れた String の "Guest" になり、そのまま出力される。
- 正解になる理由: ?? の結果は Optional が外れた String なので、Optional(...) の形にはならない。name が nil であるため既定値の "Guest" が選ばれ、出力は Guest になる。
- 他の選択肢 nil: ?? があるため nil のまま出力されることはない。?? を書かずに print(name) とした場合は nil と出力される。
- 他の選択肢 Optional(nil): そのような値は存在しない。Optional をそのまま print すると Optional("Yuki") のように包まれた形で出るが、?? で既定値に置き換えた後は包みが外れている。
- 他の選択肢 クラッシュ: クラッシュするのは name! のように強制アンラップした場合。?? は nil でも安全に既定値へ切り替わるのでクラッシュしない。
- 関連例:
```swift
let nickname: String? = "Yuki"
let missing: String? = nil
print(nickname ?? "Guest")
print(missing ?? "Guest")
```
- 関連例の出力: Yuki
Guest
- 関連例の説明: ?? は左に値があればその中身を、nil なら右の既定値を返す。どちらの場合も結果は Optional ではない String になるため、そのまま文字列として扱える。
- 覚えておくこと: ?? は「無ければこれ」。! と違って nil でもクラッシュしない。

Q2. 最も安全な書き方は？ [Basic]
```swift
let text: String? = getText()
// text を表示したい
```
A. print(text!)
B. if let text { print(text) }
C. print(text as String)
D. text = nil
正解: B
解説: if let は値がある場合だけ安全にアンラップする。`!` は nil の場合クラッシュする。

## 27. Extension [Intermediate]

考え方: 元の型定義を巨大化させず、責務や準拠ごとに分けられる。

重要ポイント:
- computed property/method/initializerなどを追加。
- Protocol準拠を分離。
- stored propertyは追加不可。
- 標準型にも機能追加できる。

コード:
```swift
extension String{
 var isBlank:Bool{trimmingCharacters(in:.whitespacesAndNewlines).isEmpty}
}
```

なぜ重要か: UIKit delegate準拠の分離やmodel機能整理で非常によく使う。
注意: 便利Extensionを無制限に増やすとAPIが乱立する。

確認問題:
Q1. Extensionで追加できないものは？ [Intermediate]
```swift
extension User { /* ? */ }
```
A. method
B. computed property
C. Protocol準拠
D. 新しいstored property
正解: D
解説: stored propertyは追加できない。

Q2. 準拠をExtensionに分ける利点は？ [Intermediate]
```swift
extension Screen:UITableViewDelegate { }
```
A. 責務ごとに整理
B. 必ず高速
C. 継承不要確定
D. Optional化
正解: A
解説: 関連実装をまとまりとして分けられる。

## 28. Protocol・Protocol Extension [Intermediate]

概要: 具体型ではなく『満たすべき能力・契約』でコードを組み立てる。
考え方: Protocolは『何者か』より『何ができるか』を表す契約。

重要ポイント:
- property/method要件を定義。
- struct/class/enumが準拠できる。
- Protocol Extensionで共通実装。
- 複数Protocolを合成できる。

コード:
```swift
protocol IdentifiableItem{var id:String{get}}
struct Item:IdentifiableItem{let id:String}
```

なぜ重要か: DI、Repository、test doubleなど実アプリ設計の基礎。
注意: 何でもProtocol化すると複雑になる。変更境界がある場所で使う。

確認問題:
Q1. Protocol準拠できる型は？ [Intermediate]
```swift
protocol Named{var name:String{get}}
```
A. classだけ
B. structだけ
C. struct/class/enumなど
D. Tupleだけ
正解: C
解説: 複数種類の型が準拠できる。

Q2. Protocolの主目的は？ [Intermediate]
```swift
protocol Loading{func load()}
```
A. 必要な能力/要件を定義
B. instanceを保存
C. JSON化
D. UI描画
正解: A
解説: 準拠型が満たす契約を表す。

- where句で型関係を表現。
- Array/Dictionaryもgeneric型。

正解: B

A. generic型引数
B. Protocol名
C. 関数名
D. access level
正解: A

## 30. associatedtype・any・some [Intermediate]

概要: Protocolを値として扱うexistentialと、具体型を隠すopaque typeを区別する。
考え方: `any P`はP準拠値を入れる箱、`some P`は具体型を1つに固定し外から隠す。

重要ポイント:
- associatedtypeで関連型を抽象化。
- any Protocolはexistential。
- some Protocolはopaque result type。
- some Viewは代表例。

コード:
```swift
protocol Store{associatedtype Item;func load()->Item}
func makeView()->some View{Text("Hello")}
```

なぜ重要か: SwiftUIやmodern Swift APIで頻出。
注意: anyとsomeは型情報の扱いが異なる。

B. 具体型を隠しつつ1つの具体型
C. Anyと同じ
D. Optional
正解: B
解説: opaque typeは実装側で具体型が固定。

Q2. any P の意味は？ [Intermediate]
```swift
let value:any P
```
A. P準拠値を保持できるexistential
B. Pを継承するclassだけ
C. Macro
D. static member
正解: A
解説: 準拠する具体型を包んで扱う。

## 31. Type Casting・is / as? / as!・Any [Intermediate]

概要: 実行時の型を確認し、より具体的な型へ安全に変換する。
考え方: 静的型だけでは分からない値をruntimeで確認する操作。

重要ポイント:
- isで型判定。
- as?は失敗時nil。
- as!は失敗時crash。
- Anyは多様な値を保持するが型安全性が下がる。

```swift
let value:Any="Swift"
if let text=value as? String{print(text.count)}
```

なぜ重要か: UIKitやObjective-C連携、汎用dataで遭遇する。
注意: as!を安易に使わない。

確認問題:

```swift
let value:Any="Swift"
```
A. value as! Int
B. value as? String
C. value is String!
D. value -> String
正解: B
解説: as?は失敗時nil。

Q2. is の結果型は？ [Intermediate]
```swift
let r=value is String
```
A. String
B. Bool
C. String?
D. Any
正解: B

## 36. Memory Safety・Exclusive Access [Intermediate]

概要: Swiftが不正なmemory accessや重複変更を防ぐ仕組みを理解する。
考え方: 自動memory管理でも、同じ値を同時にどう触るかには安全ruleがある。

重要ポイント:
- 未初期化/範囲外/解放後accessを防ぐ。
- inoutは長時間のwrite accessになり得る。
- 重複write accessを制限。
- 並行data race対策とも関連。

コード:
```swift
func balance(_ x:inout Int,_ y:inout Int){
 let total=x+y
 x=total/2
 y=total-x
}
```

なぜ重要か: Swiftの安全性の根本。inoutやConcurrency error理解につながる。
注意: 同じ変数を複数inoutへ同時に渡す等は許可されない。

確認問題:
Q1. Memory Safetyの目的は？ [Intermediate]
```swift
var values=[1,2,3]
```
A. 無効/競合memory accessを防ぐ
B. UI自動配置
C. 通信暗号化
D. Git conflict防止
正解: A
解説: Swiftはmemory accessの安全性を保証する。

Q2. swapLike(&x,&x) の問題は？ [Intermediate]
```swift
swapLike(&x,&x)
```
A. 重複した排他的accessになり得る
B. 必ず高速
C. Optional化
D. 問題なし
正解: A
解説: 同じmemoryへのoverlapping write accessになる。
