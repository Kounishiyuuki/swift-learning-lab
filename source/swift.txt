## 01. 値・let / var・型・型推論 [Beginner]

概要: Swiftの土台。値に名前を付け、型で安全性を確保する仕組みを理解する。
考え方: 変数は「箱」よりも、「値に付けた名前」と考えると後で理解しやすい。let は再代入できない名前、var は再代入できる名前。

重要ポイント:
- let は再代入不可、var は再代入可能。
- Int / Double / String / Bool は代表的な基本型。
- 型推論により、明示しなくても Swift が型を判断できる。
- Swift は型安全で、意味の合わない値の操作をコンパイル時に多く検出する。

コード:
```swift
let userName = "Yuki"
var score = 10
score += 5

let isPassed = score >= 12
print("\(userName): \(score), \(isPassed)")
```

なぜ重要か: アプリが大きくなるほど、「この値は変化するのか」「何型なのか」が設計そのものになる。SwiftUI の状態管理や API モデルでもこの基礎がそのまま使われる。
注意: プログラミングの = は「等しい」ではなく、右辺を評価して左辺へ代入する演算。

確認問題:
Q1. このコードの出力は？ [Beginner]
```swift
var score = 10
score += 5
print(score)
```
A. 5
B. 10
C. 15
D. コンパイルエラー
正解: C
解説: score は var なので変更可能。`score += 5` は `score = score + 5` と同じ意味で、10 + 5 = 15。

詳しい解説:
- 用語・考え方: var は後から中身を入れ替えられる名前を作ります。`+=` は複合代入演算子と呼ばれ、`score += 5` は `score = score + 5` の短い書き方です。左の名前の今の値に右の値を足して、その結果を同じ名前に入れ直します。
- コードの流れ: 1行目で score に 10 が入る。
- コードの流れ: 2行目の score += 5 は score = score + 5 と同じで、10 + 5 = 15 が score に入り直る。
- コードの流れ: 3行目の print はその時点の値 15 を表示する。
- 正解になる理由: `+=` は「足してから入れ直す」操作なので、print の時点で score は 15 になっています。
- 他の選択肢 5: 足す側の 5 だけを見た場合の答えです。`+=` の結果は「元の値 + 5」なので 5 単独にはなりません。
- 他の選択肢 10: `+=` の行が無かった場合の値です。この行は score 自身を書き換えるので、10 のままにはなりません。
- 他の選択肢 コンパイルエラー: score は var なので書き換えは正しい操作です。let で宣言していれば、この 2 行目がコンパイルエラーになります。
- 覚えておくこと: `x += n` は `x = x + n` の短縮形。

Q2. コンパイルエラーになるものは？ [Beginner]
```swift
let name = "Swift"
// 次のうち name に対して不可能なのは？
```
A. print(name)
B. let copy = name
C. name = "UIKit"
D. print("\(name)!")
正解: C
解説: `let` で宣言した name には再代入できない。読み取りや別の定数への代入は可能。

詳しい解説:
- 用語・考え方: let で宣言した名前は「一度決めたら変えない」という約束付きです。読み取り・コピー・文字列への埋め込みはいくらでもできますが、その名前自体に別の値を入れ直すことだけができません。`\(...)` は文字列補間で、文字列の中に値を差し込む書き方です。
- 正解になる理由: 再代入だけが let の約束を破ります。Swift はこれをコンパイル時（プログラムを動かす前）に検出するので、実行以前にビルドが失敗します。
- 他の選択肢 print(name): 値を読み取って表示するだけの操作です。let は読み取りを禁止しません。
- 他の選択肢 let copy = name: name の値を別の定数へコピーしています。元の name は変わらないため問題ありません。
- 他の選択肢 print("\(name)!"): 文字列補間で name の中身を文字列に差し込んでいるだけで、name 自体は書き換えていません。
- 関連例:
```swift
var name = "Swift"
name = "UIKit"
print(name)
```
- 関連例の出力: UIKit
- 関連例の説明: 書き換える予定があるなら var を使います。逆に書き換えない値を let にしておくと、意図しない変更をコンパイル時に止められます。
- 覚えておくこと: let は再代入だけを禁止する。読み取りとコピーは自由。

## 02. 数値型・型変換・オーバーフロー [Beginner]

概要: Int / UInt / Double / Float の違いと、安全な型変換を理解する。
考え方: 同じ『数字』でも型が違えば別物。Swiftは暗黙変換を控えめにして、意図しない計算を防ぐ。

重要ポイント:
- Intは一般的な整数、UIntは負数を持たない整数。
- Doubleは通常の小数計算で第一候補。
- 異なる数値型同士は明示変換が必要な場合が多い。
- 整数演算は範囲外になるとオーバーフローする。

コード:
```swift
let count: Int = 3
let price: Double = 120.5
let total = Double(count) * price
```

なぜ重要か: API値、JSON、画面入力、計算結果で型がずれることは多い。変換の意味を理解するとバグを減らせる。
注意: `Int(3.9)` は丸めではなく小数部分を切り捨てる。

確認問題:
Q1. result の型と値は？ [Beginner]
```swift
let a = 3
let b = 2.5
let result = Double(a) + b
```
A. Intの5
B. Doubleの5.5
C. Floatの5.5
D. コンパイルエラー
正解: B
解説: aをDoubleへ明示変換しているため5.5。

詳しい解説:
- 用語・考え方: Swift は数値型どうしを自動では変換しません。Int と Double を混ぜて計算したいときは、`Double(a)` のように書いて明示的に変換します。これは「Int の a から Double の値を新しく作る」という意味です。
- コードの流れ: a は 3（Int）、b は 2.5（Double）。
- コードの流れ: Double(a) で 3 から 3.0（Double）が作られる。
- コードの流れ: 3.0 + 2.5 は Double どうしの足し算なので 5.5（Double）になる。
- コードの流れ: result は型を書いていないので、右辺の型から Double と推論される。
- 正解になる理由: 両辺が Double に揃ってから計算されるため、結果は Double の 5.5 です。
- 他の選択肢 Intの5: 整数に丸められた場合の答えです。Double どうしの計算結果は小数部分を保ったままになります。
- 他の選択肢 Floatの5.5: Float も小数を扱う型ですが、Swift が小数リテラルから推論する既定の型は Double です。Float にしたいときは明示的に指定します。
- 他の選択肢 コンパイルエラー: `Double(a) + b` は型が揃っているため正しいコードです。`a + b` と書いた場合は Int と Double が混在してコンパイルエラーになります。
- 覚えておくこと: 型が違う数値は、計算前に明示変換で揃える。

Q2. Int(3.9) の結果は？ [Basic]
```swift
let value = Int(3.9)
```
A. 3
B. 4
C. 3.9
D. nil
正解: A
解説: 小数部分が切り捨てられて3になる。

詳しい解説:
- 用語・考え方: `Int(3.9)` は Double から Int を作る変換です。この変換は四捨五入ではなく、小数点以下を捨てて 0 に近づける「切り捨て」を行います。
- 正解になる理由: 3.9 の小数部分 0.9 が捨てられ、整数部分の 3 だけが残ります。
- 他の選択肢 4: 四捨五入だと考えると出る答えです。四捨五入したい場合は `Int(3.9.rounded())` のように、丸めてから変換します。
- 他の選択肢 3.9: Int は整数専用の型なので、3.9 のまま保持することはできません。
- 他の選択肢 nil: 文字列から数値へ変換する `Int("abc")` は失敗して nil になりますが、Double からの変換は必ず成功するため nil にはなりません。
- 関連例:
```swift
print(Int(3.9))
print(Int(-3.9))
print(Int(3.9.rounded()))
```
- 関連例の出力: 3
-3
4
- 関連例の説明: 切り捨ては「小さいほうへ」ではなく「0 に近づく方向」です。負の数では -3.9 が -3 になります。四捨五入したいときは rounded() を挟みます。
- 覚えておくこと: Int(小数) は四捨五入ではなく 0 方向への切り捨て。

## 03. Tuple・Typealias [Beginner]

概要: 複数値を一時的にまとめるTupleと、型へ分かりやすい別名を付けるTypealiasを学ぶ。
考え方: Tupleは『小さな一時セット』。長く意味を持つデータならstructを検討する。

重要ポイント:
- Tupleは複数値を1つにまとめる。
- 要素へ名前を付けられる。
- 分解代入ができる。
- typealiasは既存型へ意味のある別名を付ける。

コード:
```swift
let user = (name: "Yuki", score: 90)
typealias UserID = String
let id: UserID = "u-001"
```

なぜ重要か: 関数から複数値を返すときや複雑な型を読みやすくするときに使う。
注意: Tupleが大きくなったらstructへ移す方が保守しやすい。

確認問題:
Q1. 出力は？ [Beginner]
```swift
let point = (x: 2, y: 5)
print(point.y)
```
A. 2
B. 5
C. x
D. コンパイルエラー
正解: B
解説: 名前付きTupleのy要素は5。

詳しい解説:
- 用語・考え方: Tuple は複数の値を1つにまとめた軽量な入れ物です。`(x: 2, y: 5)` のように要素へ名前を付けると、`point.y` のように名前で取り出せます。型を新しく定義するほどではない、その場限りの組み合わせに向いています。
- コードの流れ: point には x = 2、y = 5 の 2 要素が入る。
- コードの流れ: point.y は名前 y の要素、つまり 5 を取り出す。
- コードの流れ: print が 5 を表示する。
- 正解になる理由: `.y` は名前による取り出しなので、y に対応する 5 が表示されます。
- 他の選択肢 2: x 側の値です。`point.x` と書いた場合にこちらが取り出されます。
- 他の選択肢 x: x は要素の名前であって値ではありません。名前がそのまま表示されることはありません。
- 他の選択肢 コンパイルエラー: 名前付き Tuple への `.y` アクセスは正しい書き方です。
- 覚えておくこと: 名前付き Tuple は `.名前` で取り出せる。

Q2. typealias の説明として正しいものは？ [Basic]
```swift
typealias UserID = String
```
A. 新しい実行時型を作る
B. StringにUserIDという別名を付ける
C. Stringを継承する
D. Optionalに変換する
正解: B
解説: typealiasは既存型の別名。

詳しい解説:
- 用語・考え方: typealias は既存の型に別名を付ける機能です。`typealias UserID = String` と書くと、以降 UserID と書いても String と書いても同じ型を指します。新しい型が生まれるわけではなく、コードの意図を読み取りやすくするための仕組みです。
- 正解になる理由: UserID は String の言い換えにすぎません。関数の引数に `UserID` と書けば「単なる文字列ではなく利用者の識別子だ」と読み手に伝わります。
- 他の選択肢 新しい実行時型を作る: 実行時に別の型として区別されることはありません。UserID と String は完全に同じ型として扱われ、互いに代入できます。区別したいなら struct でラップします。
- 他の選択肢 Stringを継承する: String は struct なので継承できません。typealias は継承とは無関係です。
- 他の選択肢 Optionalに変換する: Optional にするのは型名の後ろの `?` です。typealias 自体は値の有無を変えません。
- 覚えておくこと: typealias は別名。型が増えるわけではない。

## 04. 演算子・比較・論理式 [Beginner]

概要: 算術・比較・論理演算子を組み合わせ、条件や計算結果を作る。
考え方: 式は「値を生み出すもの」。`score >= 60` も Bool という値を生み出す式。

重要ポイント:
- + - * / % で算術演算。
- == != > < >= <= は Bool を返す。
- && は AND、|| は OR、! は NOT。
- 文字列補間 `\(value)` で値を String に埋め込める。

コード:
```swift
let price = 1200
let count = 3
let total = price * count
let message = "合計は\(total)円です"
print(message)
```

なぜ重要か: if や guard の条件も最終的には Bool を作る式。比較演算を理解すると制御フローが自然に読める。
注意: `=` は代入、`==` は比較。混同しない。

確認問題:
Q1. result の値は？ [Beginner]
```swift
let a = 10
let b = 3
let result = a % b
print(result)
```
A. 0
B. 1
C. 3
D. 3.333...
正解: B
解説: `%` は剰余（余り）。10 ÷ 3 の余りは 1。

詳しい解説:
- 用語・考え方: `%` は剰余演算子で、割り算の「余り」を求めます。Int どうしの `/` が商（小数切り捨て）を返すのに対し、`%` は割り切れずに残った分を返します。
- コードの流れ: a は 10、b は 3。
- コードの流れ: 10 ÷ 3 は商が 3、余りが 1。
- コードの流れ: `a % b` は余りの側なので 1 になり、print が 1 を表示する。
- 正解になる理由: 10 = 3 × 3 + 1 なので、余りは 1 です。偶数判定（`n % 2 == 0`）など実務でもよく使います。
- 他の選択肢 0: 割り切れる場合の余りです。10 は 3 で割り切れません。
- 他の選択肢 3: `a / b` の商が 3 です。`%` は商ではなく余りを返します。
- 他の選択肢 3.333...: 小数で割った結果です。Int どうしの計算に小数は現れず、`%` は常に整数の余りを返します。
- 覚えておくこと: `/` は商、`%` は余り。

Q2. isValid は最終的に何になる？ [Beginner]
```swift
let age = 20
let hasTicket = false
let isValid = age >= 18 && hasTicket
```
A. true
B. false
C. nil
D. コンパイルエラー
正解: B
解説: `&&` は両方が true のときだけ true。年齢条件は true だが hasTicket が false なので false。

詳しい解説:
- 用語・考え方: `&&` は論理積で、左右の両方が true のときだけ true になります。`>=` の比較結果は Bool なので、比較と `&&` を組み合わせて複数条件をまとめられます。
- コードの流れ: age >= 18 は 20 >= 18 なので true。
- コードの流れ: hasTicket は false。
- コードの流れ: true && false は、片方が false なので全体が false。
- コードの流れ: isValid には false が入る。
- 正解になる理由: `&&` は「かつ」です。年齢条件を満たしていてもチケットが無いため、両方を満たす必要のある条件は成立しません。
- 他の選択肢 true: `||`（または）だった場合の結果です。どちらか一方でも true なら true になる演算子は `||` です。
- 他の選択肢 nil: Bool どうしの計算結果は必ず true か false になり、nil にはなりません。nil が現れるのは Optional を扱うときです。
- 他の選択肢 コンパイルエラー: 比較結果は Bool なので `&&` にそのまま渡せます。型は合っています。
- 覚えておくこと: `&&` は両方 true のときだけ true。

## 05. String・Character・Unicode [Basic]

概要: Swiftの文字列がUnicodeを正しく扱うことと、文字列indexが整数ではない理由を理解する。
考え方: 見た目の1文字は内部で複数のUnicode scalarから構成されることがある。

重要ポイント:
- StringはUnicode対応。
- Characterは人が認識する1文字に近い単位。
- String.Indexを使って安全に位置へアクセスする。
- prefix / suffix / splitなど実用操作を覚える。

コード:
```swift
let text = "Swift🍎"
print(text.count)
print(text.prefix(5))
```

なぜ重要か: ユーザー入力、検索、表示名、API文字列など、文字列処理はどのアプリでも必須。
注意: `text[0]` のようなInt添字アクセスはできない。

確認問題:
Q1. 先頭1文字を安全に取得する代表的な方法は？ [Basic]
```swift
let text = "Swift"
```
A. text[0]
B. text.first
C. text[Int(0)]
D. text.byte(0)
正解: B
解説: firstはCharacter?を返す。

詳しい解説:
- 用語・考え方: Swift の String は「1文字が必ず同じバイト数」ではないため、`text[0]` のような整数の添字アクセスができません。代わりに `first` を使います。first は空文字列の場合を考慮して Character? （Character か nil）を返します。
- 正解になる理由: `text.first` は空文字列でも安全に nil を返すため、範囲外アクセスでプログラムが止まる心配がありません。取り出した後は if let などで中身を確認して使います。
- 他の選択肢 text[0]: String は Int の添字に対応していないため、この書き方はコンパイルエラーになります。Swift では String.Index という専用の位置指定を使います。
- 他の選択肢 text[Int(0)]: Int(0) と書いても中身は Int のままなので、同じくコンパイルエラーです。
- 他の選択肢 text.byte(0): byte(0) という API は String に用意されていません。バイト列として扱いたい場合は `text.utf8` を使います。
- 関連例:
```swift
let text = "Swift"
if let head = text.first {
    print(head)
}
print("".first == nil)
```
- 関連例の出力: S
true
- 関連例の説明: first は Character? を返すので if let で取り出します。空文字列では nil になり、クラッシュせずに「空だった」と判断できます。
- 覚えておくこと: String に整数の添字は使えない。先頭は first。

Q2. text.count が数えるものとして最も近いのは？ [Basic]
```swift
let text = "A🍎"
```
A. UTF-8バイト数
B. Characterとしての文字数
C. メモリ容量
D. ASCIIコード
正解: B
解説: String.countはCharacter単位の数を返す。

詳しい解説:
- 用語・考え方: Swift の Character は「人が1文字と感じるまとまり」を表します。絵文字や結合文字は内部的に複数バイトでも 1 Character として数えられます。String.count はこの Character の個数を返します。
- 正解になる理由: "A🍎" は A と 🍎 の 2 Character なので count は 2 です。内部のバイト数とは一致しません。
- 他の選択肢 UTF-8バイト数: UTF-8 のバイト数を知りたい場合は `text.utf8.count` を使います。"A🍎" では A が 1 バイト、🍎 が 4 バイトで合計 5 になり、count の値とは異なります。
- 他の選択肢 メモリ容量: count は文字の個数であって、メモリ使用量を表す値ではありません。
- 他の選択肢 ASCIIコード: ASCII コードは1文字を表す数値であり、個数とは別の概念です。
- 関連例:
```swift
let text = "A🍎"
print(text.count)
print(text.utf8.count)
```
- 関連例の出力: 2
5
- 関連例の説明: 同じ文字列でも、Character 単位では 2、UTF-8 バイト単位では 5 です。文字数を扱うときはどちらの単位かを意識します。
- 覚えておくこと: count は Character の個数。バイト数は utf8.count。

## 06. if・switch・guard [Beginner]

概要: 条件によって実行するコードを変える。
考え方: 制御フローは「次にどの道を通るか」を決める仕組み。条件式そのものは Bool。

重要ポイント:
- if / else if / else で条件分岐。
- switch は複数パターンを網羅的に扱うのが得意。
- guard は「条件を満たさないなら早く抜ける」ために使う。
- Swift の switch は原則としてすべてのケースを扱う必要がある。

コード:
```swift
let score = 82

switch score {
case 90...100: print("A")
case 70..<90: print("B")
default: print("C")
}
```

なぜ重要か: 読みやすい分岐はバグを減らす。guard で異常系を先に処理すると、正常系のネストが浅くなる。
注意: switch の `case 70..<90` は 70 以上 90 未満。`...` と `..<` の違いに注意。

確認問題:
Q1. 出力は？ [Beginner]
```swift
let score = 75
if score >= 80 {
    print("A")
} else if score >= 60 {
    print("B")
} else {
    print("C")
}
```
A. A
B. B
C. C
D. 何も出ない
正解: B
解説: 75 >= 80 は false。次の 75 >= 60 が true なので B が出力され、その後の else は評価されない。

詳しい解説:
- 用語・考え方: `else if` は上から順に条件を試し、最初に true になった枝だけを実行します。どれか1つが実行された時点で、残りの条件は調べられません。
- コードの流れ: score は 75。
- コードの流れ: 1つ目の条件 75 >= 80 は false なので A の枝は実行されない。
- コードの流れ: 2つ目の条件 75 >= 60 は true なので B が出力される。
- コードの流れ: 1つ実行されたので、最後の else は調べられず実行されない。
- 正解になる理由: 上から順に評価して最初に成立するのが 2 つ目の条件だからです。条件の順番を入れ替えると結果が変わる点に注意します。
- 他の選択肢 A: score が 80 以上のときの出力です。75 は届いていません。
- 他の選択肢 C: どの条件も false のときに実行される枝です。ここでは 2 つ目が成立しています。
- 他の選択肢 何も出ない: else があるため、必ずどれか 1 つの枝が実行されます。
- 覚えておくこと: else if は上から順、最初に true の枝だけ実行。

Q2. この guard の役割として最も近いものは？ [Basic]
```swift
func greet(name: String?) {
    guard let name else { return }
    print("Hello, \(name)")
}
```
A. name を必ず nil にする
B. nil なら関数を早期終了する
C. name をグローバル変数にする
D. 例外を投げる
正解: B
解説: guard let で Optional をアンラップし、nil なら return。以降では name を非 Optional として使える。

詳しい解説:
- 用語・考え方: guard は「条件を満たさないなら、この先へ進まない」を表す書き方です。`guard let name else { return }` は Optional の中身を取り出し、取り出せなければ else の中で関数を抜けます。if let と違い、取り出した値は guard の後ろの行でもそのまま使えます。
- コードの流れ: 引数 name は String?（文字列か nil）。
- コードの流れ: guard let が中身を取り出そうとする。
- コードの流れ: nil なら else の return が実行され、関数はここで終了する。
- コードの流れ: 取り出せた場合だけ次の行へ進み、name を非 Optional の String として使える。
- 正解になる理由: guard の役割は「前提を満たさない場合に早めに抜ける」ことです。これにより、本筋の処理を深いネストにせず素直に書けます。
- 他の選択肢 name を必ず nil にする: guard let は nil を代入するのではなく、nil でないことを確認して中身を取り出します。
- 他の選択肢 name をグローバル変数にする: guard は変数の有効範囲を広げますが、関数の外から使えるグローバル変数を作るわけではありません。取り出した name が使えるのはこの関数の中だけです。
- 他の選択肢 例外を投げる: Swift の例外的な処理は throw / try で書きます。guard の else では return や throw などで確実に抜ければよく、必ず throw する必要はありません。
- 覚えておくこと: guard は「ダメなら先に抜ける」。取り出した値は後の行でも使える。

## 07. Pattern Matching・where・if case [Basic]

概要: switchを強力にするPattern Matchingを理解する。
考え方: switchは『値が一致するか』だけでなく『形が一致するか』を判定できる。

重要ポイント:
- Range、Tuple、Enumのassociated valueを分解できる。
- whereでcaseへ追加条件を書ける。
- if case / guard caseで1patternだけ判定できる。
- Optionalもpattern matchingできる。

コード:
```swift
let value = (200, "OK")
switch value {
case (200, let body): print(body)
default: break
}
```

なぜ重要か: enum中心の状態設計やレスポンス分岐で読みやすいコードを書くために重要。
注意: caseの順序で広いpatternが先に一致すると後ろへ到達しない。

確認問題:
Q1. body は何になる？ [Basic]
```swift
let value=(200,"OK")
switch value { case (200, let body): print(body); default: break }
```
A. 200
B. OK
C. Tuple全体
D. nil
正解: B
解説: 2要素目をlet bodyで取り出す。

詳しい解説:
- 用語・考え方: switch は値の形（パターン）に照らして分岐します。`case (200, let body)` は「1 つ目が 200 で、2 つ目は何でもよい。その 2 つ目を body という名前で取り出す」という意味です。この let をパターン内の値取り出しと呼びます。
- コードの流れ: value は (200, "OK") という 2 要素の Tuple。
- コードの流れ: case (200, let body) と照合すると、1 つ目の 200 が一致する。
- コードの流れ: 2 つ目の "OK" が body という名前に取り出される。
- コードの流れ: print(body) が OK を表示する。
- 正解になる理由: パターンの中の `let body` は照合した値そのものを受け取る仕組みなので、body には 2 番目の要素 "OK" が入ります。
- 他の選択肢 200: 1 つ目の要素はパターン側にリテラル 200 として書かれており、照合条件として使われています。body に入るのは 2 つ目です。
- 他の選択肢 Tuple全体: Tuple 全体を受け取りたい場合は `case let pair` のように書きます。ここでは要素ごとに分解しています。
- 他の選択肢 nil: パターンが一致して値も存在するため nil にはなりません。
- 覚えておくこと: パターン内の let は、一致した部分を取り出す。

Q2. where の役割は？ [Intermediate]
```swift
case let x where x > 10:
```
A. 型を作る
B. 一致した値へ追加条件を課す
C. Optional化する
D. ループ終了
正解: B
解説: pattern一致後に追加条件を適用する。

詳しい解説:
- 用語・考え方: where はパターンが一致した後に、さらに条件を重ねるための書き方です。`case let x where x > 10:` は「値を x として受け取り、なおかつ x が 10 より大きいときだけこの case を選ぶ」という意味になります。
- 正解になる理由: パターンだけでは表せない「値の大小」などの条件を追加できます。where が false なら、その case は選ばれず次の case の照合に進みます。
- 他の選択肢 型を作る: where は条件を書く場所であり、型を定義する機能ではありません。なお generics の宣言では `where T: Equatable` のように型の制約を書く用途もありますが、これも新しい型を作るものではありません。
- 他の選択肢 Optional化する: Optional にするのは型の後ろの `?` です。where は値の有無を変えません。
- 他の選択肢 ループ終了: ループを抜けるのは break や return です。where は条件の指定だけを行います。
- 関連例:
```swift
let score = 42
switch score {
case let x where x > 100:
    print("over")
case let x where x > 10:
    print("normal \(x)")
default:
    print("low")
}
```
- 関連例の出力: normal 42
- 関連例の説明: 1 つ目の case は where が false なので選ばれず、2 つ目で初めて条件が成立します。同じ `case let x` でも where によって選ばれ方が変わります。
- 覚えておくこと: where はパターン一致の後に足す追加条件。

## 08. for・while・Range [Beginner]

概要: 同じ処理を繰り返し、コレクションを順番に処理する。
考え方: for-in は「要素を1つずつ取り出して名前を付ける」。配列を読む基本動作。

重要ポイント:
- `1...3` は 1,2,3 を含む ClosedRange。
- `0..<3` は 0,1,2。配列インデックスと相性が良い。
- for-in は配列や Range の各要素を順番に処理する。
- while は条件が true の間だけ繰り返す。

コード:
```swift
var total = 0
for number in 1...3 {
    total += number
}
print(total)
```

なぜ重要か: map / filter / reduce などの高階関数を理解する前に、for で何をしているのか追えることが重要。
注意: 無条件の while や、条件を更新しない while は無限ループになり得る。

確認問題:
Q1. 出力は？ [Beginner]
```swift
var total = 0
for i in 1...4 {
    total += i
}
print(total)
```
A. 4
B. 6
C. 10
D. 11
正解: C
解説: 1 + 2 + 3 + 4 = 10。`...` は終端の 4 を含む。

詳しい解説:
- 用語・考え方: `1...4` は閉区間（Closed Range）で、終端の 4 を含む 1, 2, 3, 4 を表します。for-in はその値を先頭から順に取り出し、`total += i` は total にその値を足し込みます。
- コードの流れ: total は 0 から開始。
- コードの流れ: i = 1 → total は 1。
- コードの流れ: i = 2 → total は 3。
- コードの流れ: i = 3 → total は 6。
- コードの流れ: i = 4 → total は 10。ここで範囲が尽きてループ終了。
- 正解になる理由: 1 + 2 + 3 + 4 = 10 です。`...` は終端を含むため 4 まで加算されます。
- 他の選択肢 4: 最後の i の値です。total は各回の合計なので、最後の値だけにはなりません。
- 他の選択肢 6: `1..<4`（4 を含まない）で 1 + 2 + 3 とした場合の答えです。`...` と `..<` の違いがここに出ます。
- 他の選択肢 11: 0 から数え始めて 5 要素分足した場合などに出る値です。開始は 1 です。
- 覚えておくこと: `...` は終端を含む、`..<` は含まない。

Q2. ループは何回実行される？ [Basic]
```swift
for _ in 0..<5 {
    print("Swift")
}
```
A. 4回
B. 5回
C. 6回
D. 無限
正解: B
解説: `0..<5` は 0,1,2,3,4 の5要素。アンダースコアは値を使わないことを表す。

詳しい解説:
- 用語・考え方: `0..<5` は半開区間（Half-Open Range）で、開始の 0 を含み終端の 5 を含みません。つまり 0, 1, 2, 3, 4 の 5 要素です。`_` は「取り出した値を使わない」ことを示すワイルドカードで、回数だけ繰り返したいときに使います。
- 正解になる理由: 要素が 5 つあるので、ループの中身は 5 回実行されます。0 から始まるので終端が 5 でも回数は 5 回である点が要注意です。
- 他の選択肢 4回: `1..<5` のように開始が 1 の場合の回数です。ここは 0 から始まります。
- 他の選択肢 6回: `0...5` のように終端を含めた場合の回数です。`..<` は終端を含みません。
- 他の選択肢 無限: 範囲の要素数は有限なので、必ず終わります。無限に繰り返すのは `while true` のような書き方です。
- 覚えておくこと: `0..<n` はちょうど n 回。

## 09. 関数・引数・戻り値 [Basic]

概要: 処理に名前を付け、入力と出力を明確にする。
考え方: 関数は「入力 → 処理 → 出力」の小さな機械。責務を小さくすると読みやすい。

重要ポイント:
- 引数ラベルとパラメータ名は別にできる。
- `-> Type` が戻り値の型。
- 副作用の少ない関数はテストしやすい。
- 関数も型を持つため、変数に代入したり引数として渡せる。

コード:
```swift
func total(price: Int, count: Int) -> Int {
    price * count
}

let result = total(price: 500, count: 3)
```

なぜ重要か: 大きな処理を関数に分解すると、名前によって意図を表現でき、テスト単位も作りやすい。
注意: 同じ型の引数が複数ある場合、ラベルを雑にすると呼び出し側で意味が分からなくなる。

確認問題:
Q1. result の値は？ [Basic]
```swift
func double(_ value: Int) -> Int {
    value * 2
}
let result = double(4)
```
A. 2
B. 4
C. 8
D. コンパイルエラー
正解: C
解説: `_` により呼び出し時の引数ラベルを省略できる。4 * 2 = 8。

詳しい解説:
- 用語・考え方: 関数の引数には呼び出し時に書くラベルを付けられます。`_ value: Int` の `_` は「ラベルを省略する」指定で、呼び出し側は `double(4)` と書けます。また、本体が 1 つの式だけの関数は return を省略でき、その式の値がそのまま戻り値になります。
- コードの流れ: double(4) の 4 が引数 value に渡る。
- コードの流れ: 本体は `value * 2` の 1 式だけなので、その結果が暗黙に返される。
- コードの流れ: 4 * 2 = 8 が result に入る。
- 正解になる理由: ラベル省略と暗黙 return はどちらも書き方の話で、計算内容は 4 × 2 のままです。
- 他の選択肢 2: 掛ける側の 2 です。戻り値は引数を 2 倍した結果です。
- 他の選択肢 4: 渡した引数そのものです。関数の中で 2 倍されています。
- 他の選択肢 コンパイルエラー: `_` によるラベル省略も、1 式関数の暗黙 return も正しい Swift の書き方です。
- 覚えておくこと: `_` はラベル省略。1 式だけの関数は return を省ける。

Q2. この関数の型として正しいものは？ [Basic]
```swift
func add(_ a: Int, _ b: Int) -> Int {
    a + b
}
```
A. Int
B. (Int, Int) -> Int
C. (Int) -> Int
D. Void -> Int
正解: B
解説: Int を2つ受け取り Int を返すので、関数型は `(Int, Int) -> Int`。

詳しい解説:
- 用語・考え方: Swift では関数そのものが値であり、型を持ちます。関数型は `(引数の型の並び) -> 戻り値の型` という形で書きます。引数ラベルは型には含まれません。
- 正解になる理由: add は Int を 2 つ受け取り Int を返すので、型は `(Int, Int) -> Int` です。この型の値は変数に入れたり、他の関数に渡したりできます。
- 他の選択肢 Int: 戻り値の型だけを書いたものです。関数型には引数側の情報も必要です。
- 他の選択肢 (Int) -> Int: 引数が 1 つの関数の型です。add は 2 つ受け取ります。
- 他の選択肢 Void -> Int: Swift で「引数なし」を表すのは `()` で、`() -> Int` と書きます。`Void -> Int` という書き方は使いません。
- 覚えておくこと: 関数型は (引数) -> 戻り値。ラベルは含まれない。

## 10. 引数ラベル・Default・Variadic・inout [Basic]

概要: 関数呼び出しを読みやすくし、特殊な入力方法を理解する。
考え方: 関数は処理だけでなくAPI。呼び出し側が自然に読める設計が重要。

重要ポイント:
- 外部引数ラベルと内部名を分けられる。
- default parameterで省略可能な引数を作れる。
- variadicは可変個数の引数を受け取る。
- inoutは呼び出し元の値そのものを変更する。

コード:
```swift
func greet(_ name: String, prefix: String = "Hello") {
    print("\(prefix), \(name)")
}
```

なぜ重要か: 標準ライブラリやApple APIの関数signatureを読む力に直結する。
注意: inoutは副作用が明確な場面で使う。

確認問題:
Q1. 出力は？ [Basic]
```swift
func greet(_ name:String,prefix:String="Hi"){print("\(prefix) \(name)")}
greet("Yuki")
```
A. Yuki
B. Hi
C. Hi Yuki
D. エラー
正解: C
解説: prefixの既定値Hiが使われる。

詳しい解説:
- 用語・考え方: 引数に `= "Hi"` のような既定値を書くと、呼び出し時にその引数を省略できます。省略された場合は既定値が使われます。文字列補間 `\(...)` は値を文字列に差し込む書き方です。
- コードの流れ: greet("Yuki") は name にだけ値を渡している。
- コードの流れ: prefix は省略されたので既定値の "Hi" が使われる。
- コードの流れ: print("\(prefix) \(name)") が Hi と Yuki を空白区切りで組み立てる。
- 正解になる理由: 既定値があるおかげで、よくある呼び出しは短く書け、必要なときだけ `greet("Yuki", prefix: "Hello")` と指定できます。
- 他の選択肢 Yuki: prefix 側が出力されていない場合の答えです。print には両方が含まれています。
- 他の選択肢 Hi: name 側が出力されていない場合の答えです。
- 他の選択肢 エラー: 既定値があるため引数を省略した呼び出しは正しく、エラーにはなりません。
- 覚えておくこと: 既定値付き引数は省略でき、省略時にその値が入る。

Q2. inout引数を渡す記号は？ [Intermediate]
```swift
func addOne(_ x: inout Int){x+=1}
var n=1
addOne(/* ? */ n)
```
A. $
B. &
C. @
D. !
正解: B
解説: inoutへは&nのように渡す。

詳しい解説:
- 用語・考え方: inout は「引数として渡した変数そのものを関数内で書き換え、呼び出し元にも反映する」指定です。値がコピーされる通常の引数と区別するため、呼び出し側でも `&` を付けて「これは書き換えられます」と明示します。
- 正解になる理由: `addOne(&n)` の `&` は、渡しているのが値のコピーではなく変数そのものへの参照であることを読み手にもコンパイラにも示します。渡せるのは var で宣言した変数だけです。
- 他の選択肢 $: `$` は Property Wrapper の projectedValue にアクセスする記号で、SwiftUI の `$value` などで使います。inout とは無関係です。
- 他の選択肢 @: `@` は属性を書くための記号です（`@escaping` や `@MainActor` など）。引数の受け渡しには使いません。
- 他の選択肢 !: `!` は Optional の強制アンラップなどに使う記号です。inout の指定ではありません。
- 関連例:
```swift
func addOne(_ x: inout Int) { x += 1 }
var n = 1
addOne(&n)
print(n)
```
- 関連例の出力: 2
- 関連例の説明: inout でない普通の引数なら関数内の変更は呼び出し元に伝わりません。`&` が付くことで、n 自体が書き換わることが呼び出し側からも読み取れます。
- 覚えておくこと: inout には `&` を付けて渡す。渡せるのは var だけ。

## 11. 関数型・Higher-Order Function [Intermediate]

概要: 関数を値として保存・受け渡しできることを理解する。
考え方: Swiftでは『何をするか』そのものを値として扱える。

重要ポイント:
- 関数には型がある。
- 関数を変数へ代入できる。
- 関数を引数/戻り値として扱う関数を高階関数という。
- map/filterは高階関数の代表。

コード:
```swift
func add(_ a:Int,_ b:Int)->Int{a+b}
let operation: (Int,Int)->Int = add
```

なぜ重要か: クロージャやコールバック、DIを読む根本になる。
注意: `add` と `add(1,2)` は関数そのものと実行結果で別。

確認問題:
Q1. operation の型は？ [Basic]
```swift
func add(_ a:Int,_ b:Int)->Int{a+b}
let operation=add
```
A. Int
B. (Int, Int) -> Int
C. () -> Void
D. String
正解: B
解説: 2つのIntを受け取りIntを返す関数型。

詳しい解説:
- 用語・考え方: 関数名を `()` を付けずに書くと、その関数を「呼び出す」のではなく「関数そのものを値として取り出す」意味になります。取り出した値の型は、その関数の関数型です。
- コードの流れ: add は Int を 2 つ受け取り Int を返す関数。
- コードの流れ: `let operation = add` は呼び出しではなく、関数の値をそのまま代入している。
- コードの流れ: operation の型は add の関数型 `(Int, Int) -> Int` になる。
- コードの流れ: 以降は `operation(2, 3)` のように呼び出せる。
- 正解になる理由: `add` の後ろに `()` が無いため実行されず、関数値のまま operation に入ります。
- 他の選択肢 Int: `let operation = add(1, 2)` のように呼び出していれば Int になります。ここでは呼び出していません。
- 他の選択肢 () -> Void: 引数も戻り値も無い関数の型です。add は引数も戻り値も持ちます。
- 他の選択肢 String: 関数値であって文字列ではありません。
- 覚えておくこと: `()` を付けなければ、関数は値として渡せる。

Q2. 高階関数とは？ [Intermediate]
```swift
func apply(_ v:Int, operation:(Int)->Int)->Int{operation(v)}
```
A. 関数を値として受け取る/返す関数
B. 必ず再帰する関数
C. 非同期関数だけ
D. UIKit専用
正解: A
解説: 関数を引数または戻り値として扱う。

詳しい解説:
- 用語・考え方: 高階関数とは、関数を引数として受け取る、あるいは関数を戻り値として返す関数のことです。処理の一部を呼び出し側から差し替えられるようになり、map や filter、sorted(by:) といった標準の API もこの形で作られています。
- 正解になる理由: apply は `operation: (Int) -> Int` という関数型の引数を受け取っているため、まさに関数を値として受け取る関数です。
- 他の選択肢 必ず再帰する関数: 再帰は関数が自分自身を呼ぶことで、高階関数とは別の概念です。高階関数が再帰する必要はありません。
- 他の選択肢 非同期関数だけ: 同期・非同期とは無関係です。通常の同期関数でも高階関数になれます。
- 他の選択肢 UIKit専用: Swift 標準ライブラリの map や reduce も高階関数であり、特定のフレームワーク専用の概念ではありません。
- 関連例:
```swift
func apply(_ v: Int, operation: (Int) -> Int) -> Int { operation(v) }
print(apply(5, operation: { $0 * 2 }))
print(apply(5, operation: { $0 + 10 }))
```
- 関連例の出力: 10
15
- 関連例の説明: apply 自体は変えずに、渡す処理だけを差し替えて結果を変えられます。これが関数を値として扱う利点です。
- 覚えておくこと: 関数を受け取る／返す関数が高階関数。

## 12. Closure・map / filter / reduce 入門 [Intermediate]

概要: 処理そのものを値として扱う。
考え方: クロージャは「名前のない関数」。map は各要素を変換、filter は残す要素を選別、reduce は1つに畳み込む。

重要ポイント:
- クロージャは `{ parameters in expression }` の形。
- map は要素数を保ちながら変換する。
- filter は条件に合う要素だけ残す。
- reduce は複数要素から1つの結果を作る。

コード:
```swift
let numbers = [1, 2, 3, 4]
let doubled = numbers.map { $0 * 2 }
let evens = doubled.filter { $0.isMultiple(of: 4) }
```

なぜ重要か: Swift / SwiftUI の API ではクロージャが大量に出てくる。ViewBuilder、Button action、非同期処理などの読解にも直結する。
注意: `map` は元配列を変更しない。新しい配列を返す。

確認問題:
Q1. result は？ [Intermediate]
```swift
let numbers = [1, 2, 3]
let result = numbers.map { $0 * 2 }
```
A. [1, 2, 3]
B. [2, 4, 6]
C. [1, 4, 9]
D. 6
正解: B
解説: map は各要素をクロージャで変換した新しい配列を返す。各要素を2倍して [2,4,6]。

詳しい解説:
- 用語・考え方: map は「各要素を変換して、同じ個数の新しい配列を作る」操作です。`{ $0 * 2 }` はクロージャ（名前のない関数）で、`$0` は「渡されてきた 1 つ目の引数」を表す省略記法です。元の配列は変更されず、新しい配列が返ります。
- コードの流れ: 1 が渡され 1 * 2 = 2。
- コードの流れ: 2 が渡され 2 * 2 = 4。
- コードの流れ: 3 が渡され 3 * 2 = 6。
- コードの流れ: 変換結果を順に集めた [2, 4, 6] が返る。
- 正解になる理由: map は要素数を変えずに中身だけを変換するため、3 要素が 3 要素のまま 2 倍になります。
- 他の選択肢 [1, 2, 3]: 元の配列です。map は元を書き換えず新しい配列を返すので、result には変換後が入ります。
- 他の選択肢 [1, 4, 9]: 各要素を 2 乗した場合の結果です。`$0 * 2` は 2 倍であって 2 乗ではありません。
- 他の選択肢 6: 合計にするのは reduce です。map は配列を返します。
- 覚えておくこと: map は個数そのまま、中身を変換。

Q2. result は？ [Intermediate]
```swift
let values = [1, 2, 3, 4]
let result = values.filter { $0 % 2 == 0 }
```
A. [1, 3]
B. [2, 4]
C. [true, false, true, false]
D. 10
正解: B
解説: filter はクロージャが true を返す要素だけ残す。偶数の 2 と 4 が残る。

詳しい解説:
- 用語・考え方: filter は「条件を満たす要素だけを残した新しい配列」を作ります。クロージャは Bool を返す必要があり、true の要素だけが残ります。`$0 % 2 == 0` は「2 で割った余りが 0」つまり偶数判定です。
- コードの流れ: 1 → 1 % 2 は 1 なので false、残らない。
- コードの流れ: 2 → 0 == 0 で true、残る。
- コードの流れ: 3 → false、残らない。
- コードの流れ: 4 → true、残る。結果は [2, 4]。
- 正解になる理由: 偶数だけが条件を満たすため、2 と 4 が順序を保ったまま残ります。
- 他の選択肢 [1, 3]: 条件を反転した場合（奇数）の結果です。`$0 % 2 != 0` ならこちらになります。
- 他の選択肢 [true, false, true, false]: クロージャが返した Bool の一覧です。filter が返すのは判定結果ではなく、条件を満たした元の要素です。判定結果の配列が欲しい場合は map を使います。
- 他の選択肢 10: 合計値です。合計は reduce の役割です。
- 覚えておくこと: filter は個数が減ることがある。中身は変えない。

## 13. @escaping・Capture・Capture List [Intermediate]

概要: クロージャが外側の値を保持する仕組みとescapingを理解する。
考え方: クロージャは外側の値を捕まえて後から使える。その保持が参照循環にもつながる。

重要ポイント:
- closureは外側の値をcaptureできる。
- @escapingは関数終了後にも保持される可能性があるclosure。
- classのselfを強くcaptureすると循環が起こる場合がある。
- [weak self]などcapture listで保持方法を制御。

コード:
```swift
onFinish = { [weak self] in
    self?.handleFinish()
}
```

なぜ重要か: UIKit completion、URLSession、Task、animationなどで頻出。
注意: weak selfを機械的に付けず、所有関係を考える。

確認問題:
Q1. @escaping が必要になる代表例は？ [Intermediate]
```swift
func load(completion: @escaping ()->Void){ /* 保存して後で呼ぶ */ }
```
A. すぐ実行して破棄
B. 関数終了後に保存して呼ぶ
C. Intを返すだけ
D. letを使う
正解: B
解説: 関数終了後にもclosureが生存する場合。

詳しい解説:
- 用語・考え方: クロージャは通常、渡された関数の実行中に使われて終わります。しかし関数が終わった後まで保存して後から呼び出す場合、そのクロージャは関数の外へ「逃げる（escape）」ため、`@escaping` の指定が必要になります。通信の完了時に呼ぶコールバックが典型例です。
- 正解になる理由: プロパティに保存したり、非同期処理の完了後に呼んだりする場合、関数の実行が終わってもクロージャが生き続けます。これを Swift に伝えるのが @escaping です。
- 他の選択肢 すぐ実行して破棄: 関数の中ですぐ実行して捨てるだけなら関数の外へ逃げないため、非エスケープのままで書けます。@escaping は不要です。
- 他の選択肢 Intを返すだけ: 戻り値の型の話であって、クロージャの寿命とは関係ありません。
- 他の選択肢 letを使う: let / var の選択は値を書き換えるかどうかの話で、@escaping の要否とは別です。
- 覚えておくこと: 関数終了後も残るクロージャには @escaping。

Q2. [weak self] を使う主な理由は？ [Intermediate]
```swift
callback = { [weak self] in self?.finish() }
```
A. selfを値型にする
B. 強参照循環を避ける
C. 同期化する
D. Optional禁止
正解: B
解説: closureとselfの循環を避けるために使うことがある。

詳しい解説:
- 用語・考え方: クロージャは、その中で使った外の値を掴んで保持します（キャプチャ）。self を使うクロージャを self 自身のプロパティに保存すると、self がクロージャを持ち、クロージャが self を持つ、という相互の強い参照ができます。これが強参照循環（retain cycle）で、どちらも解放されなくなります。`[weak self]` はキャプチャリストと呼ばれ、self を弱い参照で掴むことでこの輪を断ち切ります。
- コードの流れ: self が callback プロパティにクロージャを保存する（self → クロージャの強い参照）。
- コードの流れ: クロージャの中で self を使うと、通常は self を強く掴む（クロージャ → self）。
- コードの流れ: この 2 本が揃うと互いに手放せなくなり、メモリが解放されない。
- コードの流れ: [weak self] にすると 2 本目が弱い参照になり、self が不要になれば解放できる。
- 正解になる理由: weak は参照カウントを増やさないため、循環が切れます。弱い参照は対象が解放されると nil になるため、`self?` のように Optional として扱う点も重要です。
- 他の選択肢 selfを値型にする: weak にしても class のままで、値型に変わることはありません。値型（struct）はそもそも参照カウントを持たないため、この問題自体が起きにくくなります。
- 他の選択肢 同期化する: weak はメモリ管理の指定であり、複数の処理の順番を整える仕組みではありません。
- 他の選択肢 Optional禁止: むしろ逆で、weak な参照は Optional になります。Optional を禁止するどころか、Optional として扱う必要が生じます。
- 覚えておくこと: [weak self] で循環を断つ。weak な self は Optional になる。

## 14. Collection入門：Array・Set・Dictionary [Basic]

概要: 複数の値を目的に合わせてまとめる。
考え方: Array=順序付き、Set=重複なし、Dictionary=キーから値を引く。

重要ポイント:
- Array は順序を持ち、添字でアクセスする。
- Set は順序を前提とせず、一意な要素を保持する。
- Dictionary は Key: Value の対応を保持する。
- 存在しない Dictionary キーへのアクセス結果は Optional。

コード:
```swift
var scores = ["A": 90, "B": 75]
scores["C"] = 82

if let score = scores["C"] {
    print(score)
}
```

なぜ重要か: APIレスポンス、画面一覧、ID検索など、実アプリはコレクションの処理だらけ。型ごとの性質を使い分ける。
注意: 配列の存在しない index にアクセスすると実行時エラー。Dictionary は Optional を返す。

確認問題:
Q1. numbers の最終状態は？ [Basic]
```swift
var numbers = [1, 2]
numbers.append(3)
numbers.removeFirst()
```
A. [1, 2, 3]
B. [2, 3]
C. [1, 3]
D. [3]
正解: B
解説: append で [1,2,3]、removeFirst で先頭の 1 が削除され [2,3]。

詳しい解説:
- 用語・考え方: Array は順序を保つ要素の並びです。append は末尾に追加し、removeFirst は先頭を取り除きます。どちらも配列自身を書き換えるので、変数は var である必要があります。
- コードの流れ: 初期状態は [1, 2]。
- コードの流れ: append(3) で末尾に 3 が加わり [1, 2, 3]。
- コードの流れ: removeFirst() で先頭の 1 が取り除かれ [2, 3]。
- 正解になる理由: 追加は末尾、削除は先頭なので、残るのは [2, 3] です。
- 他の選択肢 [1, 2, 3]: append までの状態です。removeFirst の効果が反映されていません。
- 他の選択肢 [1, 3]: 真ん中の 2 が削除された場合の結果です。removeFirst が消すのは先頭の 1 です。
- 他の選択肢 [3]: 2 要素が削除された場合の結果です。removeFirst は 1 つだけ取り除きます。
- 覚えておくこと: append は末尾へ、removeFirst は先頭から。

Q2. Dictionary の scores["C"] の型は？ [Basic]
```swift
let scores = ["A": 90, "B": 75]
let value = scores["C"]
```
A. Int
B. Int?
C. String
D. Bool
正解: B
解説: キーが存在しない可能性があるため Dictionary の添字アクセスは Optional。ここでは Int?。

詳しい解説:
- 用語・考え方: Dictionary はキーと値の対応表です。`scores["C"]` のような添字アクセスは、そのキーが存在しない可能性があるため、値そのものではなく Optional を返します。値が Int なら結果は Int? になります。
- 正解になる理由: "C" は登録されていないため実際の結果は nil ですが、型としては「Int が入っているか nil」を表す Int? です。存在しないキーでもクラッシュせず nil で受け取れるのが Swift の設計です。
- 他の選択肢 Int: 必ず値が存在する前提の型です。存在しないキーを扱えないため、Dictionary の添字はこの型を返しません。取り出した後に `?? 0` などで既定値を補うと Int になります。
- 他の選択肢 String: String はキー側の型です。取り出されるのは値側です。
- 他の選択肢 Bool: 値の型は Int なので Bool にはなりません。
- 関連例:
```swift
let scores = ["A": 90, "B": 75]
print(scores["C"] ?? 0)
if let a = scores["A"] { print(a) }
```
- 関連例の出力: 0
90
- 関連例の説明: `?? 0` で「無ければ 0」と既定値を与えられます。if let で取り出せば、存在した場合だけの処理を書けます。
- 覚えておくこと: Dictionary の添字アクセスは常に Optional。

## 15. Arrayを深く理解する [Basic]

概要: 順序付きCollectionの追加・削除・検索・安全な扱いを学ぶ。
考え方: Arrayは『順序が意味を持つ一覧』。indexは要素のIDではない。

重要ポイント:
- append / insert / remove / contains / first(where:)を使う。
- first / lastはOptional。
- indexは並べ替えや削除で変わる。
- 操作によって計算量が異なる。

コード:
```swift
var names=["A","B"]
names.append("C")
let firstB = names.first { $0 == "B" }
```

なぜ重要か: List、API response、検索結果など最も頻出するCollection。
注意: 存在確認せずarray[index]へアクセスすると範囲外crashになる。

確認問題:
Q1. 安全に最初の要素を取りたい場合は？ [Basic]
```swift
let values=[1,2,3]
```
A. values[0]だけ
B. values.first
C. values[-1]
D. values.get(0)!
正解: B
解説: firstは空配列ならnilを返す。

詳しい解説:
- 用語・考え方: `values[0]` は指定位置に必ず要素がある前提のアクセスで、空配列に対して行うとプログラムが実行中に停止します（実行時エラー）。`first` は空なら nil を返す Optional なので、事前に個数を確認しなくても安全に扱えます。
- 正解になる理由: first は「取れなかった」という結果を nil として返せるため、空配列でも停止しません。取り出した後に if let などで確認して使います。
- 他の選択肢 values[0]だけ: 値が入っていることが確実なら使えますが、空の可能性がある場面では実行時に停止する危険があります。安全性を問われている場面では first が適切です。
- 他の選択肢 values[-1]: Swift の配列は負の添字に対応しておらず、実行時に停止します。末尾を取りたい場合は last を使います。
- 他の選択肢 values.get(0)!: get(_:) という API は Array にありません。仮にあっても末尾の `!` は nil のとき停止するため、安全な書き方にはなりません。
- 関連例:
```swift
let values: [Int] = []
print(values.first == nil)
print(values.first ?? -1)
```
- 関連例の出力: true
-1
- 関連例の説明: 空配列でも停止せず nil として扱えます。`??` で既定値を与えれば、そのまま値として使えます。
- 覚えておくこと: 空かもしれない配列には添字より first / last。

Q2. removeFirst() 後は？ [Basic]
```swift
var v=["A","B","C"]
v.removeFirst()
```
A. [A,B]
B. [B,C]
C. [A,C]
D. []
正解: B
解説: 先頭Aが削除される。

詳しい解説:
- 用語・考え方: removeFirst() は配列の先頭要素を取り除き、残りを 1 つずつ前へ詰めます。配列自身が変化するため、対象は var で宣言されている必要があります。
- コードの流れ: 初期状態は ["A", "B", "C"]。
- コードの流れ: removeFirst() が先頭の "A" を取り除く。
- コードの流れ: 残りが前へ詰まり ["B", "C"] になる。
- 正解になる理由: 取り除かれるのは先頭の 1 要素だけなので、B と C が順序を保ったまま残ります。
- 他の選択肢 [A,B]: 末尾が削除された場合の結果です。それを行うのは removeLast() です。
- 他の選択肢 [A,C]: 真ん中が削除された場合の結果です。位置を指定して消すなら remove(at: 1) です。
- 他の選択肢 []: すべて削除した場合の結果です。それを行うのは removeAll() です。
- 覚えておくこと: removeFirst は先頭 1 つ。removeLast は末尾 1 つ。

## 16. Set・集合演算 [Basic]

概要: 重複を許さないCollectionと集合演算を理解する。
考え方: 順番ではなく『含まれているか』が重要なデータにSetを使う。

重要ポイント:
- Set要素はHashable。
- insert/remove/containsが基本。
- union/intersection/subtractingで集合演算。
- 順序を前提にしない。

コード:
```swift
let a:Set=[1,2,3]
let b:Set=[3,4]
let common=a.intersection(b)
```

なぜ重要か: 選択済みID、権限、tag、重複排除に自然に使える。
注意: 表示順が必要ならArrayなど別構造を使う。

確認問題:
Q1. intersection結果は？ [Basic]
```swift
let a:Set=[1,2,3]
let b:Set=[3,4]
let c=a.intersection(b)
```
A. 1だけ
B. 3だけ
C. 3と4
D. 1,2,3,4
正解: B
解説: 共通要素3だけ。

詳しい解説:
- 用語・考え方: Set は重複を持たない集合で、順序を保ちません。intersection は 2 つの集合の「両方に含まれる要素だけ」を取り出す集合演算です。ほかに union（どちらかに含まれる）、subtracting（片方から取り除く）があります。
- コードの流れ: a は {1, 2, 3}、b は {3, 4}。
- コードの流れ: 両方に含まれる要素を探すと 3 だけが該当する。
- コードの流れ: c は {3} になる。
- 正解になる理由: 1 と 2 は a にしかなく、4 は b にしかありません。共通しているのは 3 だけです。
- 他の選択肢 1だけ: 1 は a にしか存在しないため共通要素ではありません。
- 他の選択肢 3と4: 4 は b にしかありません。両方に含まれる必要があります。
- 他の選択肢 1,2,3,4: これは union（和集合）の結果です。intersection は共通部分だけを返します。
- 関連例:
```swift
let a: Set = [1, 2, 3]
let b: Set = [3, 4]
print(a.intersection(b).sorted())
print(a.union(b).sorted())
print(a.subtracting(b).sorted())
```
- 関連例の出力: [3]
[1, 2, 3, 4]
[1, 2]
- 関連例の説明: Set は順序を持たないため、表示の順を安定させるには sorted() を挟みます。3 つの集合演算の違いがこれで比較できます。
- 覚えておくこと: intersection は共通部分、union は全体、subtracting は差。

Q2. Set要素に必要な代表Protocolは？ [Basic]
```swift
Set<MyType>()
```
A. Codable
B. Hashable
C. Observable
D. Sendableだけ
正解: B
解説: Setはhash値で要素を管理する。

詳しい解説:
- 用語・考え方: Set は同じ要素を重複して保持しない Collection です。新しい要素を追加するとき「すでに同じ値が存在するか」を毎回調べる必要があり、要素を 1 つずつ全部比較していては効率が悪くなります。Hashable に準拠した型は値から hash 値（値を要約した整数）を作れるため、まず hash 値で候補を絞り込めます。Hashable は Equatable も継承しているので、絞り込んだ候補を == で比較して同一かどうかを確定できます。
- コードの流れ: 要素を追加するとき、まずその値の hash 値を計算して格納先の候補を絞る。
- コードの流れ: hash 値が同じだったものだけを == で比較する。
- コードの流れ: 同じ値が既にあれば追加せず、無ければ追加する。
- コードの流れ: この 2 段構えのために、要素型には hash 計算と等価比較の両方が要る。
- 正解になる理由: Hashable がその 2 つの能力をまとめて要求する契約です。Int や String など標準の型は既に準拠しているため、そのまま Set に入れられます。
- 他の選択肢 Codable: Encodable と Decodable をまとめた別名で、JSON などの外部表現との相互変換のための契約です。保存や通信で使うものであり、重複判定には関与しません。
- 他の選択肢 Observable: 値の変化を観測して UI を更新するための仕組みで、主に SwiftUI の状態管理で使います。集合の要素条件とは無関係です。
- 他の選択肢 Sendableだけ: Sendable は「並行処理の境界を越えて安全に受け渡せる」ことを表す契約です。スレッド安全性の話であり、これだけでは重複判定ができないため Set の要素条件は満たしません。
- 関連例:
```swift
struct Member: Hashable {
    let id: Int
    let name: String
}

var members: Set<Member> = []
members.insert(Member(id: 1, name: "Yuki"))
members.insert(Member(id: 1, name: "Yuki"))
print(members.count)
```
- 関連例の出力: 1
- 関連例の説明: すべての stored property が Hashable なら、struct は Hashable への準拠を自動合成でき、== と hash(into:) が生成されます。同じ内容を 2 回入れても重複と判定されるため要素数は 1 のままです。
- 覚えておくこと: Set の要素と Dictionary の Key は Hashable。hash で絞り、== で確定する。

## 17. Dictionary・Key / Value [Basic]

概要: KeyからValueへ効率よくアクセスする辞書型を理解する。
考え方: Dictionaryは『ID→データ』『名前→設定』の検索表。

重要ポイント:
- KeyはHashable。
- 添字アクセスはOptional。
- default subscriptで初期値付き更新ができる。
- keys / values / mergeなどを使える。

コード:
```swift
var counts:[String:Int]=[:]
counts["Swift", default: 0] += 1
```

なぜ重要か: ID検索、集計、cacheなど実務で頻出。
注意: `dictionary[key] = nil` は通常そのKey削除になる。

確認問題:
Q1. default: 0 の利点は？ [Basic]
```swift
var c:[String:Int]=[:]
c["A", default:0]+=1
```
A. Aが無い場合0から開始
B. 必ずnil
C. Array化
D. Key削除
正解: A
解説: Keyが無ければdefault値から更新できる。

詳しい解説:
- 用語・考え方: `c["A", default: 0]` は「キーが無ければ 0 があるものとして扱う」という添字の書き方です。これにより Optional を経由せずに読み書きでき、`+= 1` のような更新をそのまま書けます。集計処理で頻出のパターンです。
- コードの流れ: c は空の Dictionary。"A" というキーはまだ無い。
- コードの流れ: default: 0 により、無い場合は 0 とみなされる。
- コードの流れ: 0 + 1 = 1 が計算され、c["A"] に 1 が設定される。
- 正解になる理由: 既定値があるおかげで「最初の 1 回」を特別扱いする分岐が不要になります。default が無ければ Optional のままなので `+= 1` は直接書けません。
- 他の選択肢 必ずnil: むしろ nil を避けるための書き方です。default 付きの添字は Optional ではない値を返します。
- 他の選択肢 Array化: Dictionary は Dictionary のままです。配列へ変換するわけではありません。
- 他の選択肢 Key削除: キーを削除するのは `c["A"] = nil` や removeValue(forKey:) です。default は削除とは無関係です。
- 関連例:
```swift
var counts: [String: Int] = [:]
for name in ["A", "B", "A"] {
    counts[name, default: 0] += 1
}
print(counts["A"] ?? 0, counts["B"] ?? 0)
```
- 関連例の出力: 2 1
- 関連例の説明: 初回はキーが無いので 0 から始まり、2 回目以降は既存の値に足されます。出現回数の集計がこれだけで書けます。
- 覚えておくこと: `[key, default: 値]` で「無ければこの値」から更新できる。

Q2. Dictionary Keyに必要なのは？ [Basic]
```swift
var d:[Key:Value]
```
A. Hashable
B. View
C. Actor
D. Error
正解: A
解説: Dictionary KeyはHashable。

詳しい解説:
- 用語・考え方: Dictionary は「キーから値を素早く探す」ための型です。探す仕組みは Set と同じで、キーの hash 値で候補を絞り、== で一致を確定します。そのため Key の型は Hashable に準拠している必要があります。Value 側には制約がありません。
- 正解になる理由: Hashable が hash 値の生成と等価比較の両方を保証するため、キーの高速な検索が成り立ちます。String や Int が Key によく使われるのは、これらが標準で Hashable だからです。
- 他の選択肢 View: 画面の見た目を表す SwiftUI の契約で、辞書のキー条件とは無関係です。
- 他の選択肢 Actor: 並行処理で状態を保護する型の種類であり、キーの条件ではありません。
- 他の選択肢 Error: エラーとして投げられる値が満たす契約です。キーの検索とは関係ありません。
- 覚えておくこと: Dictionary の Key は Hashable。Value に制約はない。

## 18. map・compactMap・flatMap・filter・reduce・sorted [Intermediate]

概要: Collection変換を用途ごとに正しく選ぶ。
考え方: 『各要素を変える』『一部を残す』『nilを捨てる』『1つへ集約』を分けて考える。

重要ポイント:
- map:全要素を変換。
- compactMap:nilを除きながら変換。
- filter:条件に合う要素を残す。
- reduce:複数要素を1つへ畳み込む。

コード:
```swift
let texts=["1","x","3"]
let numbers=texts.compactMap(Int.init)
let sum=numbers.reduce(0,+)
```

なぜ重要か: API変換、表示model作成、集計処理で頻出。
注意: 高階関数を1行に連結しすぎて読みにくくしない。

確認問題:
Q1. numbers は？ [Intermediate]
```swift
let v=["1","x","3"]
let numbers=v.compactMap(Int.init)
```
A. [1,nil,3]
B. [1,3]
C. [1,0,3]
D. ["1","3"]
正解: B
解説: 変換失敗のnilをcompactMapが除去する。

詳しい解説:
- 用語・考え方: `Int.init` は「String から Int を作る初期化」を関数値として渡した書き方で、`{ Int($0) }` と同じ意味です。この変換は数値に見えない文字列では失敗して nil を返します。compactMap は変換結果のうち nil を取り除き、中身だけを取り出した配列を返します。
- コードの流れ: "1" → 変換成功で 1。
- コードの流れ: "x" → 数値として読めないので nil。
- コードの流れ: "3" → 変換成功で 3。
- コードの流れ: compactMap が nil を除去し、[1, 3] が残る。
- 正解になる理由: map なら [1, nil, 3]（型は [Int?]）になりますが、compactMap は nil を落として [Int] にします。
- 他の選択肢 [1,nil,3]: map を使った場合の結果です。compactMap の役割はこの nil を取り除くことです。
- 他の選択肢 [1,0,3]: 失敗を 0 で埋めた場合の結果です。compactMap は既定値を補うのではなく要素ごと取り除きます。0 を入れたいなら `map { Int($0) ?? 0 }` と書きます。
- 他の選択肢 ["1","3"]: 変換されず文字列のまま残った場合の結果です。Int.init により中身は Int になります。
- 覚えておくこと: compactMap = map してから nil を除去。

Q2. reduce(0,+) の役割は？ [Intermediate]
```swift
let total=[1,2,3].reduce(0,+)
```
A. 並べ替え
B. 合計して1つにする
C. nil除去
D. 重複排除
正解: B
解説: 0から+で畳み込み6になる。

詳しい解説:
- 用語・考え方: reduce は「初期値から始めて、要素を 1 つずつ取り込みながら 1 つの値にまとめる」操作です。`reduce(0, +)` は初期値 0 に対して要素を順に + で結合していきます。`+` は演算子ですが関数としても渡せます。
- コードの流れ: 初期値 0。
- コードの流れ: 0 + 1 = 1。
- コードの流れ: 1 + 2 = 3。
- コードの流れ: 3 + 3 = 6。最終結果は 6。
- 正解になる理由: map や filter が配列を返すのに対し、reduce は配列を 1 つの値へ畳み込みます。合計・最大・連結など「まとめる」処理全般に使えます。
- 他の選択肢 並べ替え: 並べ替えは sorted() の役割です。reduce は順に取り込むだけで並べ替えません。
- 他の選択肢 nil除去: nil の除去は compactMap の役割です。
- 他の選択肢 重複排除: 重複排除は Set への変換などで行います。reduce の役割ではありません。
- 関連例:
```swift
let exercises = ["squat", "bench"]
let total = [1, 2, 3].reduce(0, +)
let joined = exercises.reduce("") { $0 + $1 + "/" }
print(total)
print(joined)
```
- 関連例の出力: 6
squat/bench/
- 関連例の説明: reduce は数値の合計だけでなく、文字列の連結など「1 つにまとめる」処理全般に使えます。$0 が途中経過、$1 が今回の要素です。
- 覚えておくこと: reduce は配列を 1 つの値に畳み込む。

## 19. Optional・if let・guard let [Basic]

概要: 「値がある / ない」を型として安全に扱う。
考え方: Optional は空っぽになれる箱ではなく、`.some(value)` または `.none` の2状態を持つ型と考える。

重要ポイント:
- `String?` は String または nil。
- if let / guard let で安全にアンラップする。
- nil-coalescing `??` で nil のときの既定値を指定できる。
- 強制アンラップ `!` は nil ならクラッシュするため慎重に使う。

コード:
```swift
let nickname: String? = nil
let displayName = nickname ?? "Guest"
print(displayName)
```

なぜ重要か: API、ユーザー入力、検索結果など「存在しない可能性」は現実のアプリで必ず発生する。Optional はその可能性を型で表現する。
注意: `!` を「Optionalを消す記号」と覚えない。nil の可能性を無視して値を強制取得する操作。

確認問題:
Q1. 出力は？ [Basic]
```swift
let name: String? = nil
print(name ?? "Guest")
```
A. nil
B. Optional(nil)
C. Guest
D. クラッシュ
正解: C
解説: `??` は左側が nil の場合に右側を返す。したがって Guest。

詳しい解説:
- 用語・考え方: String? は「String が入っているか、nil か」を表す Optional 型です。`??` は nil 合体演算子（nil-coalescing operator）で、「左が nil ならば右の既定値を使う」という意味になります。結果は Optional が外れた値になるため、そのまま文字列として扱えます。
- コードの流れ: name は String? 型で、中身は nil。
- コードの流れ: print に渡す前に `name ?? "Guest"` が先に評価される。
- コードの流れ: `??` は左の name を確認し、nil なので右側の "Guest" を採用する。
- コードの流れ: 結果は Optional ではない String の "Guest" になり、そのまま出力される。
- 正解になる理由: `??` の結果は Optional が外れた String なので Optional(...) の形にはならず、nil だったため既定値の Guest が表示されます。表示名が未設定のときに既定名を出す、といった実務でよく使う形です。
- 他の選択肢 nil: `??` を書かずに `print(name)` とした場合は nil と出力されます。ここでは既定値に置き換えられるため nil にはなりません。
- 他の選択肢 Optional(nil): そのような値は存在しません。Optional をそのまま print すると Optional("Yuki") のように包まれた形で表示されますが、`??` で置き換えた後は包みが外れています。
- 他の選択肢 クラッシュ: クラッシュするのは `name!` のように強制アンラップした場合です。`??` は nil でも安全に既定値へ切り替わるため停止しません。
- 関連例:
```swift
let nickname: String? = "Yuki"
let missing: String? = nil
print(nickname ?? "Guest")
print(missing ?? "Guest")
```
- 関連例の出力: Yuki
Guest
- 関連例の説明: `??` は左に値があればその中身を、nil なら右の既定値を返します。どちらの場合も結果は Optional ではない String になります。
- 覚えておくこと: `??` は「無ければこれ」。`!` と違ってクラッシュしない。

Q2. 最も安全な書き方は？ [Basic]
```swift
let text: String? = getText()
// text を表示したい
```
A. print(text!)
B. if let text { print(text) }
C. print(text as String)
D. text = nil
正解: B
解説: if let は値がある場合だけ安全にアンラップする。`!` は nil の場合クラッシュする。

詳しい解説:
- 用語・考え方: Optional の中身を使うには、値があるかどうかを確認してから取り出す必要があります。`if let text { ... }` は Optional を取り出し、中身があるときだけブロックを実行する短縮記法（shorthand）で、`if let text = text` と同じ意味です。
- 正解になる理由: if let は nil の場合にブロックを実行しないだけで、プログラムは停止しません。値の有無に関わらず安全に動くため、最も安全な書き方です。
- 他の選択肢 print(text!): `!` は強制アンラップで、「必ず値が入っている」と断言する書き方です。実際に nil だった場合、プログラムは実行中に停止します。値の有無が不明な場面では危険です。
- 他の選択肢 print(text as String): `as` は型変換の構文で、Optional を外す用途には使えません。String? を String へ無条件に変換することはできず、この書き方はコンパイルエラーになります。
- 他の選択肢 text = nil: text に nil を代入しているだけで、表示にはなりません。そもそも text は let 宣言なので再代入自体できません。
- 覚えておくこと: 取り出してから使う。`!` は「絶対にある」と言い切る宣言。

## 20. Optional Chaining・Optional map / flatMap [Basic]

概要: Optionalの中へ安全にアクセスし、存在しない場合を連鎖的に扱う。
考え方: 途中がnilなら、その先を実行せず連鎖全体がnilになる。

重要ポイント:
- user?.profile?.nameのように連鎖できる。
- 結果はOptional。
- Optional.mapは値がある時だけ変換。
- flatMapはOptionalの二重化を避ける。

コード:
```swift
struct User{let name:String}
let user:User?=User(name:"Yuki")
let length=user?.name.count
```

なぜ重要か: APIや画面状態でOptionalが連鎖する場面を安全に扱える。
注意: nilが隠れすぎるならguardで明示的に検証する。

確認問題:
Q1. length の型は？ [Basic]
```swift
struct User{let name:String}
let user:User?=nil
let length=user?.name.count
```
A. Int
B. Int?
C. String?
D. Bool
正解: B
解説: 途中がnilかもしれないので結果はInt?。

詳しい解説:
- 用語・考え方: `?.` は Optional Chaining で、「左が nil でなければ続きを評価し、nil ならその場で全体を nil にする」という書き方です。途中で打ち切られる可能性があるため、結果は必ず Optional になります。
- コードの流れ: user は User? で、中身は nil。
- コードの流れ: `user?.name` の時点で nil と判明し、以降の `.count` は評価されない。
- コードの流れ: 全体の結果は nil になる。
- コードの流れ: ただし成功時には Int が得られるため、型としては Int? になる。
- 正解になる理由: name は String、count は Int ですが、途中が nil になり得るので結果は「Int か nil」つまり Int? です。型は実際の値ではなく、起こり得る可能性で決まります。
- 他の選択肢 Int: 途中で nil になる可能性がある限り、結果を非 Optional にはできません。`user?.name.count ?? 0` のように既定値を与えれば Int になります。
- 他の選択肢 String?: count が返すのは文字数、つまり Int です。String? になるのは `user?.name` までの部分です。
- 他の選択肢 Bool: 文字数は数であり、真偽値ではありません。
- 覚えておくこと: `?.` の結果は必ず Optional になる。

Q2. 途中がnilなら？ [Basic]
```swift
a?.b?.c
```
A. 必ずcrash
B. 連鎖結果はnil
C. 0
D. 空文字
正解: B
解説: 以降を評価せずnilになる。

詳しい解説:
- 用語・考え方: `a?.b?.c` のように `?.` をつなげると、どこか 1 か所でも nil になった時点で残りの評価が打ち切られ、全体の結果が nil になります。これを短絡評価と呼びます。途中でクラッシュするのではなく、安全に nil を返す点が重要です。
- 正解になる理由: nil になった段階で以降のプロパティやメソッドは呼ばれません。だからこそ深い階層でも安全に書けます。
- 他の選択肢 必ずcrash: クラッシュするのは `!` を使った強制アンラップです。`?.` は安全側に倒れます。
- 他の選択肢 0: 数値の 0 が補われることはありません。既定値が欲しい場合は `?? 0` を明示的に書きます。
- 他の選択肢 空文字: 空文字列が補われることもありません。結果は nil です。
- 関連例:
```swift
struct Gym { let name: String }
let gym: Gym? = nil
let length = gym?.name.count
print(length as Any)
print(gym?.name.count ?? 0)
```
- 関連例の出力: nil
0
- 関連例の説明: チェーンの途中が nil なら結果も nil です。`?? 0` を添えれば、そのまま数として扱える値に変換できます。
- 覚えておくこと: チェーンの途中が nil なら、以降は評価されず全体が nil。

## 21. struct・値セマンティクス入門 [Intermediate]

概要: 関連データを独自型にまとめ、値型として扱う基本を理解する。
考え方: structは『独自の値』を定義する設計図。代入や引数渡しでは値セマンティクスを持つ。

重要ポイント:
- structは値型。
- stored propertyとmethodを持てる。
- memberwise initializerが自動生成される場合がある。
- データモデルではstructが自然な場面が多い。

コード:
```swift
enum LoadState {
    case idle
    case loading
    case loaded([String])
    case failed(Error)
}
```

なぜ重要か: DTO、View用model、設定値など、多くのSwift型設計で中心になる。
注意: structはclassの簡易版ではない。共有同一性が不要なら値型が自然なことが多い。

確認問題:
Q1. 出力は？ [Intermediate]
```swift
struct User { var score: Int }
var a = User(score: 10)
var b = a
b.score = 20
print(a.score)
```
A. 10
B. 20
C. nil
D. コンパイルエラー
正解: A
解説: struct は値型。b は a の値を受け取り、b.score の変更は a に影響しない。

詳しい解説:
- 用語・考え方: struct は値型です。値型は代入や引数渡しのときに中身がコピーされ、コピー後は互いに独立します。片方を書き換えても、もう片方には影響しません。
- コードの流れ: a は score = 10 の User。
- コードの流れ: `var b = a` で a の中身がコピーされ、b は独立した別の値になる。
- コードの流れ: b.score = 20 は b 側だけを書き換える。
- コードの流れ: print(a.score) は元のまま 10 を表示する。
- 正解になる理由: コピーされた時点で 2 つは別物です。値型では「どこかで勝手に書き換わっていた」という事態が起きにくく、状態を追いやすくなります。
- 他の選択肢 20: b 側の値です。class（参照型）であれば a と b が同じ実体を指すため、こちらが正解になります。struct と class の最も大きな違いがここです。
- 他の選択肢 nil: score は Int で Optional ではないため、nil にはなりません。
- 他の選択肢 コンパイルエラー: struct のコピーもプロパティの書き換えも正しい操作です。b が var なので変更もできます。
- 覚えておくこと: struct は代入でコピー。書き換えは互いに影響しない。

Q2. enum を使う主な利点は？ [Intermediate]
```swift
enum NetworkState {
    case idle, loading, loaded, failed
}
```
A. すべて参照型になる
B. 取り得る状態を型で限定できる
C. 必ず rawValue が必要
D. 継承できる
正解: B
解説: 状態の候補を型レベルで限定できる。switch と組み合わせると状態漏れも検出しやすい。

詳しい解説:
- 用語・考え方: enum は「取り得る値の候補」を型として列挙する仕組みです。NetworkState を enum にすると、状態は idle / loading / loaded / failed の 4 つだけに限定され、それ以外の値は作れません。
- 正解になる理由: 文字列や Int で状態を表すと、想定外の値が入り込む余地が残ります。enum なら候補が型で固定され、switch で分岐したとき case の書き漏れをコンパイル時に指摘してもらえます。
- 他の選択肢 すべて参照型になる: enum は値型です。参照型になるのは class です。
- 他の選択肢 必ず rawValue が必要: rawValue は必要なときだけ指定します。`enum NetworkState { case idle }` のように rawValue 無しでも定義できます。
- 他の選択肢 継承できる: enum は他の型を継承できません。継承ができるのは class です。ただし protocol への準拠は可能です。
- 覚えておくこと: enum は状態の候補を型で限定する。

## 22. Enum・Raw Value・Associated Value [Intermediate]

概要: 取り得る状態を型で限定し、状態ごとに異なるデータを保持する。
考え方: enumは『文字列定数の集まり』ではなく、状態を安全に表現する強力な型。

重要ポイント:
- raw valueで固定値と対応。
- associated valueでcaseごとに異なる値を持てる。
- switchで全caseを網羅。
- recursive enumも表現可能。

コード:
```swift
enum LoadState {
 case idle
 case loading
 case loaded([String])
 case failed(message:String)
}
```

なぜ重要か: 画面状態、network状態、routing、error種別を不正状態なく表せる。
注意: 複数Boolで状態を表すと矛盾状態を作りやすい。

確認問題:
Q1. associated value の利点は？ [Intermediate]
```swift
enum State{case success(Int);case failure(String)}
```
A. caseごとに関連dataを持てる
B. 必ずrawValue
C. 継承可能
D. 参照型
正解: A
解説: caseごとに異なる型の関連dataを保持できる。

詳しい解説:
- 用語・考え方: associated value は「case ごとに異なる付随データを持たせる」機能です。`case success(Int)` は成功時に Int を、`case failure(String)` は失敗時に String を一緒に運びます。case ごとに型も個数も変えられる点が特徴です。
- 正解になる理由: 状態とそのときだけ必要なデータを 1 つの値にまとめられます。成功のときだけ件数、失敗のときだけメッセージ、というように無関係なデータを持ち回らずに済みます。
- 他の選択肢 必ずrawValue: rawValue は「case に対応する固定の生の値」を与える別の機能です。全 case が同じ型の値を 1 つ持つ形で、case ごとに型を変えることはできません。associated value とは用途が異なります。
- 他の選択肢 継承可能: enum は継承できません。継承は class の機能です。
- 他の選択肢 参照型: enum は値型です。参照型になるのは class です。
- 関連例:
```swift
enum LoadState {
    case success(Int)
    case failure(String)
}
let state = LoadState.success(3)
switch state {
case .success(let count):
    print("loaded \(count)")
case .failure(let message):
    print("error \(message)")
}
```
- 関連例の出力: loaded 3
- 関連例の説明: switch のパターンで `let count` と書くと、その case に付随する値を取り出せます。success のときだけ件数を扱える構造になります。
- 覚えておくこと: associated value は case ごとの付随データ。rawValue とは別物。

Q2. 状態管理にenumが向く理由は？ [Intermediate]
```swift
enum State{case idle,loading,loaded,failed}
```
A. 同時に複数case
B. 取り得る状態を限定
C. 必ずDB保存
D. UI自動生成
正解: B
解説: 不正な組み合わせを作りにくい。

詳しい解説:
- 用語・考え方: 画面の状態を Bool の組み合わせ（isLoading、hasError など）で表すと、「読み込み中かつエラー」のような、実際には起こり得ない組み合わせも表現できてしまいます。enum は候補を 1 つに絞るため、そうした矛盾した状態を作れなくなります。
- 正解になる理由: enum の値は常にどれか 1 つの case です。ありえない組み合わせが型の時点で排除されるため、分岐の抜けや矛盾を減らせます。
- 他の選択肢 同時に複数case: むしろ逆で、同時に複数の case にはなれません。1 つに定まることが利点です。
- 他の選択肢 必ずDB保存: enum は保存とは無関係です。保存するかどうかは別の設計判断です。
- 他の選択肢 UI自動生成: enum を定義しただけで画面が作られることはありません。UI は別途組み立てます。
- 覚えておくこと: enum は「ありえない状態」を作れなくする。

## 23. class・参照型・継承 [Intermediate]

概要: 同じインスタンスを複数箇所から共有する参照セマンティクスを理解する。
考え方: struct の代入は『値を渡す』、class の代入は『同じ対象を指す参照を渡す』と考える。

重要ポイント:
- class は参照型。
- 継承、deinit、同一性比較 `===` は class 固有。
- ARC が参照カウントを管理する。
- 強参照循環を避けるため weak / unowned を使う場合がある。

コード:
```swift
final class Counter {
    var value = 0
}
let a = Counter()
let b = a
b.value = 5
print(a.value)
```

なぜ重要か: UIKit の UIViewController などは class。Delegate やクロージャで参照循環を作らないためにも必要。
注意: class を代入しても複製されない。同じインスタンスへの参照が増える。

確認問題:
Q1. 出力は？ [Intermediate]
```swift
final class Box { var value = 1 }
let a = Box()
let b = a
b.value = 9
print(a.value)
```
A. 1
B. 9
C. nil
D. コンパイルエラー
正解: B
解説: class は参照型。a と b は同じ Box インスタンスを参照しているため、変更が共有される。

詳しい解説:
- 用語・考え方: class は参照型です。代入しても中身はコピーされず、同じ実体を指す参照が増えるだけです。そのため一方を通じた変更が、もう一方からも見えます。`final` は「これ以上継承させない」という指定です。
- コードの流れ: `let a = Box()` で Box の実体が 1 つ作られる。
- コードの流れ: `let b = a` は実体をコピーせず、同じ実体への参照を b にも持たせる。
- コードの流れ: b.value = 9 は共有している実体を書き換える。
- コードの流れ: print(a.value) は同じ実体を見るため 9 を表示する。
- 正解になる理由: a と b は同じ Box を指しているからです。なお a は let ですが、これは「a が別の実体を指し直せない」という意味であり、指している実体のプロパティ（var value）は変更できます。
- 他の選択肢 1: struct（値型）であればコピーされるため、こちらが正解になります。class と struct の最大の違いです。
- 他の選択肢 nil: value は Int で Optional ではないため nil にはなりません。
- 他の選択肢 コンパイルエラー: let で宣言した class の参照でも、参照先のプロパティ変更は許されます。エラーにはなりません。
- 覚えておくこと: class は代入しても同じ実体を共有する。

Q2. weak がよく使われる理由は？ [Intermediate]
```swift
weak var delegate: SomeDelegate?
```
A. 値型に変換するため
B. 強参照循環を避けるため
C. 速度を必ず上げるため
D. Optional を禁止するため
正解: B
解説: weak 参照は参照カウントを増やさないため、delegate などの双方向参照で強参照循環を避けやすい。

詳しい解説:
- 用語・考え方: Swift は参照カウント（ARC）でメモリを管理し、参照が 0 になった時点で解放します。2 つのオブジェクトが互いを強く参照し合うと、カウントが 0 にならず両方とも解放されません。これが強参照循環です。weak は参照カウントを増やさないため、この輪を断ち切れます。
- 正解になる理由: delegate は「呼び出し元が呼び出し先を持ち、呼び出し先も呼び出し元を delegate として持つ」という双方向の関係になりがちです。片方を weak にすることで循環を防ぎます。
- 他の選択肢 値型に変換するため: weak にしても class は class のままで、値型にはなりません。
- 他の選択肢 速度を必ず上げるため: weak はメモリ管理のための指定であり、速度改善を目的とした機能ではありません。
- 他の選択肢 Optional を禁止するため: むしろ逆です。weak な参照は対象が解放されると自動的に nil になるため、必ず Optional として宣言します。
- 覚えておくこと: weak は参照カウントを増やさず、対象が消えると nil になる。

## 24. Stored / Computed / lazy / Property Observer [Intermediate]

概要: 型の状態を表すPropertyの種類と、計算・監視の仕組みを理解する。
考え方: 保存する値と、他の値から計算できる値を分ける。

重要ポイント:
- stored propertyは値を保存。
- computed propertyはgetter/setterで計算。
- lazyは初回accessまで初期化を遅延。
- willSet/didSetで変更を観測。

コード:
```swift
struct Rect{
 var width:Double
 var height:Double
 var area:Double { width * height }
}
```

なぜ重要か: 状態重複を避け、modelを一貫した状態に保つ。
注意: 計算で導ける値を二重保存すると同期漏れが起きやすい。

確認問題:
Q1. area の種類は？ [Intermediate]
```swift
var area:Double { width * height }
```
A. stored
B. computed
C. lazy stored
D. global
正解: B
解説: access時に計算するcomputed property。

詳しい解説:
- 用語・考え方: プロパティには、値を実際に保持する stored property と、アクセスされるたびに計算して値を返す computed property があります。`var area: Double { width * height }` のように本体が { } で書かれているものは computed property で、値そのものは保存されません。
- 正解になる理由: area は width と height から毎回計算されます。元になる値が変われば area も自動的に新しい結果になるため、値の食い違いが起きません。
- 他の選択肢 stored: stored property は `var width: Double` のように値を保持する形で書きます。area は保持していません。
- 他の選択肢 lazy stored: lazy stored property は `lazy var` と書き、初回アクセス時に一度だけ計算して保存します。area は毎回計算し直す点が異なります。
- 他の選択肢 global: 型の中で宣言されているためグローバルではありません。
- 覚えておくこと: { } で値を返すプロパティは、毎回計算される computed property。

Q2. lazy の特徴は？ [Intermediate]
```swift
lazy var cache=makeCache()
```
A. 即作成
B. 最初のaccessまで初期化を遅らせる
C. letだけ
D. Optional専用
正解: B
解説: 初回access時まで初期化を延期。

詳しい解説:
- 用語・考え方: lazy var は「最初にアクセスされるまで初期化を行わない」プロパティです。生成コストの高い値を、実際に使うときまで作らずに済ませられます。一度作られた後はその値が保持されます。
- 正解になる理由: 初期化が初回アクセスまで遅延されるため、使われなければ makeCache() は一度も呼ばれません。起動時の負荷を減らす目的でよく使われます。
- 他の選択肢 即作成: 即座に作られるのは通常の stored property です。lazy はそれを避けるための指定です。
- 他の選択肢 letだけ: lazy は var にしか付けられません。初回アクセス時に値を書き込む必要があるためです。
- 他の選択肢 Optional専用: Optional 専用の機能ではありません。どの型のプロパティにも使えます。
- 覚えておくこと: lazy は初回アクセスまで初期化を先送りする（var 限定）。

## 25. Method・mutating・Subscript [Intermediate]

概要: 型に紐づく処理と、[]による独自accessを理解する。
考え方: Methodは『その型にできること』、Subscriptは『[]でaccessする窓口』。

重要ポイント:
- instance/type methodがある。
- struct/enumで自身を変更するmethodにはmutating。
- static/classでtype method。
- subscriptで独自[] access。

コード:
```swift
struct Counter{
 var value=0
 mutating func increment(){value+=1}
}
```

なぜ重要か: 標準libraryやframework APIを読むとき、変更性と所有者を理解できる。
注意: 値型のmethodからstored propertyを変える場合はmutatingが必要。

確認問題:
Q1. structでselfを変更するmethodに必要なのは？ [Intermediate]
```swift
struct C{var n=0; /* ? */ func up(){n+=1}}
```
A. weak
B. mutating
C. override
D. async
正解: B
解説: 値型の自身を変更するmethodはmutating。

詳しい解説:
- 用語・考え方: struct は値型で、その中のメソッドは既定では自分自身のプロパティを変更できません。自身を書き換えるメソッドには `mutating` を付けて、「このメソッドは値を変更する」ことを明示します。呼び出せるのは var で保持している場合だけです。
- 正解になる理由: `n += 1` は自身のプロパティの変更にあたるため、mutating が必要です。付けないとコンパイルエラーになります。class は参照型なのでこの指定は不要です。
- 他の選択肢 weak: weak は参照カウントを増やさない参照の指定で、class の参照に対して使います。メソッドには付けられません。
- 他の選択肢 override: override は継承したメソッドを上書きする指定で、class で使います。struct は継承できません。
- 他の選択肢 async: async は非同期メソッドの指定で、値の変更可否とは無関係です。
- 関連例:
```swift
struct Counter {
    var n = 0
    mutating func up() { n += 1 }
}
var counter = Counter()
counter.up()
counter.up()
print(counter.n)
```
- 関連例の出力: 2
- 関連例の説明: mutating を付けることで自身を書き換えられます。counter が let だと up() を呼べず、コンパイル時にエラーになります。
- 覚えておくこと: struct で自身を変えるメソッドには mutating。

Q2. subscriptの目的は？ [Intermediate]
```swift
value[index]
```
A. []形式の独自access API
B. 継承禁止
C. 非同期化
D. ARC停止
正解: A
解説: []で値へaccessするAPIを定義できる。

詳しい解説:
- 用語・考え方: subscript は `value[index]` という角括弧の記法を自分の型にも定義できる仕組みです。Array や Dictionary の `[...]` も subscript として実装されています。引数の型や個数は自由に決められます。
- 正解になる理由: メソッド名を書かずに角括弧でアクセスできるため、コレクションのように「位置やキーで要素を取り出す」型を自然に表現できます。
- 他の選択肢 継承禁止: 継承の可否は final や class の設計で決まります。subscript とは無関係です。
- 他の選択肢 非同期化: 非同期処理は async / await で表します。subscript はアクセスの記法を提供するだけです。
- 他の選択肢 ARC停止: ARC はメモリ管理の仕組みで、subscript から制御するものではありません。
- 覚えておくこと: subscript は `[ ]` でアクセスできる API を自作する仕組み。

## 26. Initialization・Failable init・deinit [Intermediate]

概要: instanceが有効な状態で生成され、必要な後処理が行われる仕組みを理解する。
考え方: initは有効なinstanceを完成させる責任を持つ。

重要ポイント:
- stored propertyは初期化完了までに値を持つ。
- init?は失敗してnilを返せる。
- classではdesignated/convenience initializerがある。
- deinitはclass破棄時のcleanup。

コード:
```swift
struct Age{
 let value:Int
 init?(_ value:Int){guard value>=0 else{return nil}; self.value=value}
}
```

なぜ重要か: 不正状態を生成時点で防ぐ設計に使える。
注意: class継承時の初期化規則は厳密。

確認問題:
Q1. Age(-1) の結果は？ [Intermediate]
```swift
struct Age{let v:Int;init?(_ v:Int){guard v>=0 else{return nil};self.v=v}}
let age=Age(-1)
```
A. Age
B. Age?のnil
C. Int -1
D. エラー
正解: B
解説: failable initializerがnilを返す。

詳しい解説:
- 用語・考え方: `init?` は failable initializer（失敗しうる初期化）です。条件を満たさない場合に `return nil` を返せます。その結果、`Age(-1)` の型は Age ではなく Age? になります。
- コードの流れ: Age(-1) が呼ばれ、init? の中に入る。
- コードの流れ: guard v >= 0 の条件が -1 で満たされない。
- コードの流れ: else の return nil が実行され、初期化が失敗する。
- コードの流れ: age には Age? の nil が入る。
- 正解になる理由: 不正な値を弾いて「作れなかった」ことを nil で表せます。呼び出し側は if let などで確認してから使います。
- 他の選択肢 Age: 初期化に成功した場合の型です。init? を使うと戻り値は必ず Optional になります。
- 他の選択肢 Int -1: Age は struct であって Int ではありません。渡した引数そのものが返ることもありません。
- 他の選択肢 エラー: init? による nil の返却は正しい仕組みで、コンパイルエラーにも実行時停止にもなりません。
- 覚えておくこと: init? の結果は Optional。作れなければ nil。

Q2. deinitを持てる代表型は？ [Intermediate]
```swift
deinit { }
```
A. class
B. structだけ
C. enumだけ
D. Tuple
正解: A
解説: deinitはclass instance破棄時。

詳しい解説:
- 用語・考え方: deinit はインスタンスが破棄される直前に呼ばれる後始末の処理です。参照カウントが 0 になった時点で解放される class にのみ存在します。値型はコピーされて使われ、明確な「破棄の瞬間」を持たないため deinit を定義できません。
- 正解になる理由: 解放のタイミングが定まるのは参照型である class だけだからです。通知の解除やファイルのクローズなどに使います。
- 他の選択肢 structだけ: struct は値型で、コピーごとに独立するため deinit を持てません。
- 他の選択肢 enumだけ: enum も値型なので同様に deinit を定義できません。
- 他の選択肢 Tuple: Tuple は複数の値の組で、deinit のような機能は持ちません。
- 覚えておくこと: deinit は class 専用。

## 27. Extension [Intermediate]

概要: 既存型へ機能やProtocol準拠を追加する。
考え方: 元の型定義を巨大化させず、責務や準拠ごとに分けられる。

重要ポイント:
- computed property/method/initializerなどを追加。
- Protocol準拠を分離。
- stored propertyは追加不可。
- 標準型にも機能追加できる。

コード:
```swift
extension String{
 var isBlank:Bool{trimmingCharacters(in:.whitespacesAndNewlines).isEmpty}
}
```

なぜ重要か: UIKit delegate準拠の分離やmodel機能整理で非常によく使う。
注意: 便利Extensionを無制限に増やすとAPIが乱立する。

確認問題:
Q1. Extensionで追加できないものは？ [Intermediate]
```swift
extension User { /* ? */ }
```
A. method
B. computed property
C. Protocol準拠
D. 新しいstored property
正解: D
解説: stored propertyは追加できない。

詳しい解説:
- 用語・考え方: extension は既存の型に後から機能を足す仕組みです。メソッド、computed property、イニシャライザ、protocol への準拠などを追加できます。ただし新しい stored property は追加できません。型のメモリ上の大きさが後から変わってしまうためです。
- 正解になる理由: 値を保持する領域を後付けで増やすことはできません。値を持たせたい場合は元の型定義に加えるか、別の型でラップします。computed property なら計算して返すだけなので追加できます。
- 他の選択肢 method: メソッドは追加できます。既存の型に便利な操作を足す代表的な使い方です。
- 他の選択肢 computed property: computed property は値を保持しないため追加できます。
- 他の選択肢 Protocol準拠: protocol への準拠を extension で書くのは一般的な書き方です。
- 関連例:
```swift
struct User { let name: String }
extension User {
    var greeting: String { "Hello, \(name)" }
    func shout() -> String { greeting.uppercased() }
}
print(User(name: "Yuki").shout())
```
- 関連例の出力: HELLO, YUKI
- 関連例の説明: computed property とメソッドは後から足せます。一方 `var age: Int` のような stored property を書くとコンパイルエラーになります。
- 覚えておくこと: extension で stored property は足せない。計算とメソッドは足せる。

Q2. 準拠をExtensionに分ける利点は？ [Intermediate]
```swift
extension Screen:UITableViewDelegate { }
```
A. 責務ごとに整理
B. 必ず高速
C. 継承不要確定
D. Optional化
正解: A
解説: 関連実装をまとまりとして分けられる。

詳しい解説:
- 用語・考え方: 1 つの型が複数の役割を持つとき、protocol への準拠ごとに extension を分けると、どのメソッドがどの役割のものかが一目で分かります。ファイル内の並びが責務ごとにまとまり、変更時に読む範囲を絞れます。
- 正解になる理由: 分割の目的はコードの整理です。準拠に必要なメソッド群が 1 か所に集まるため、後から読む人が役割の境界を追いやすくなります。
- 他の選択肢 必ず高速: extension に分けても実行時の速度は基本的に変わりません。目的は可読性です。
- 他の選択肢 継承不要確定: 継承の要否は別の設計判断であり、extension の分割とは関係ありません。
- 他の選択肢 Optional化: Optional 化とは無関係です。
- 覚えておくこと: 準拠ごとに extension を分けると責務が見える。

## 28. Protocol・Protocol Extension [Intermediate]

概要: 具体型ではなく『満たすべき能力・契約』でコードを組み立てる。
考え方: Protocolは『何者か』より『何ができるか』を表す契約。

重要ポイント:
- property/method要件を定義。
- struct/class/enumが準拠できる。
- Protocol Extensionで共通実装。
- 複数Protocolを合成できる。

コード:
```swift
protocol IdentifiableItem{var id:String{get}}
struct Item:IdentifiableItem{let id:String}
```

なぜ重要か: DI、Repository、test doubleなど実アプリ設計の基礎。
注意: 何でもProtocol化すると複雑になる。変更境界がある場所で使う。

確認問題:
Q1. Protocol準拠できる型は？ [Intermediate]
```swift
protocol Named{var name:String{get}}
```
A. classだけ
B. structだけ
C. struct/class/enumなど
D. Tupleだけ
正解: C
解説: 複数種類の型が準拠できる。

詳しい解説:
- 用語・考え方: protocol は「この型はこれができる」という要求の一覧です。継承と違い、特定の親型を持つ必要がないため、struct・class・enum のいずれでも準拠できます。1 つの型が複数の protocol に準拠することもできます。
- 正解になる理由: Named は「name という読み取り可能なプロパティを持つこと」だけを要求しています。この条件さえ満たせば型の種類は問いません。値型でも参照型でも共通の扱いができるのが protocol の強みです。
- 他の選択肢 classだけ: class 限定にしたい場合は `protocol Named: AnyObject` と明示する必要があります。既定では限定されません。
- 他の選択肢 structだけ: struct 限定という指定は存在しません。
- 他の選択肢 Tupleだけ: Tuple は protocol に準拠できません。準拠できるのは名前付きの型（struct / class / enum など）です。
- 覚えておくこと: protocol は struct / class / enum のどれでも準拠できる。

Q2. Protocolの主目的は？ [Intermediate]
```swift
protocol Loading{func load()}
```
A. 必要な能力/要件を定義
B. instanceを保存
C. JSON化
D. UI描画
正解: A
解説: 準拠型が満たす契約を表す。

詳しい解説:
- 用語・考え方: protocol は実装そのものではなく「満たすべき要件（契約）」を表します。`protocol Loading { func load() }` は「load() を持つこと」だけを定め、どう実装するかは各型に任せます。呼び出す側は具体的な型を知らなくても load() を呼べます。
- 正解になる理由: 契約として抽象化することで、本物の通信を行う型とテスト用の型を差し替えられます。依存性注入やテスト容易性の土台になる考え方です。
- 他の選択肢 instanceを保存: 値を保持するのは型のプロパティの役割です。protocol は要件を定めるだけで、自身が値を保存するわけではありません。
- 他の選択肢 JSON化: JSON 変換は Codable という別の protocol が担当します。protocol 一般の目的ではありません。
- 他の選択肢 UI描画: 画面描画は SwiftUI や UIKit の役割です。
- 覚えておくこと: protocol は「何ができるか」の契約。実装は各型に任せる。

## 29. Generics・Constraint・where [Intermediate]

概要: 具体型を固定せず、型安全な再利用コードを書く。
考え方: 『何型でも』ではなく『必要条件を満たす型なら』使える設計。

重要ポイント:
- 型Parameter Tを使う。
- Protocol constraintで必要能力を要求。
- where句で型関係を表現。
- Array/Dictionaryもgeneric型。

コード:
```swift
func maximum<T:Comparable>(_ a:T,_ b:T)->T{a>b ? a:b}
```

なぜ重要か: 標準library、SwiftUI、Repository抽象化の型を読むために必須。
注意: generic化しすぎるとsignatureが難しくなる。

確認問題:
Q1. T: Comparable の意味は？ [Intermediate]
```swift
func maxValue<T:Comparable>(_ a:T,_ b:T)->T
```
A. TはInt
B. TはComparable準拠
C. Tはclass
D. TはOptional
正解: B
解説: 比較可能な型というconstraint。

詳しい解説:
- 用語・考え方: `<T: Comparable>` の T は型を後から当てはめるための placeholder（型引数）です。`: Comparable` の部分は制約で、「T に入れられるのは Comparable に準拠した型だけ」という条件を表します。Comparable は `<` や `>` で大小比較できる能力を意味します。
- 正解になる理由: 制約があるおかげで、関数の中で `a > b` のような比較を安全に書けます。制約が無ければ、比較できない型が渡される可能性があるためコンパイルできません。
- 他の選択肢 TはInt: T は Int に固定されません。Int も String も Double も、Comparable に準拠していれば渡せます。
- 他の選択肢 Tはclass: class への限定は `T: AnyObject` と書きます。Comparable は class かどうかとは無関係です。
- 他の選択肢 TはOptional: Optional への限定ではありません。Optional 自体は条件付きでしか Comparable になりません。
- 関連例:
```swift
func maxValue<T: Comparable>(_ a: T, _ b: T) -> T { a > b ? a : b }
print(maxValue(3, 8))
print(maxValue("apple", "banana"))
```
- 関連例の出力: 8
banana
- 関連例の説明: 同じ関数が Int でも String でも使えます。Comparable に準拠していることが保証されているため、中で大小比較ができます。
- 覚えておくこと: T は型の placeholder、`: Protocol` はその型に課す条件。

Q2. Array<Int> の Int は？ [Intermediate]
```swift
Array<Int>
```
A. generic型引数
B. Protocol名
C. 関数名
D. access level
正解: A
解説: Arrayへ要素型Intを指定している。

詳しい解説:
- 用語・考え方: Array は「何の要素を入れるか」を後から決められる generic な型です。`Array<Int>` の Int はその型引数で、「この配列の要素は Int」という指定になります。普段書く `[Int]` は `Array<Int>` の短縮記法です。
- 正解になる理由: 型引数を与えることで、要素の型が決まった具体的な配列型になります。これにより取り出した要素も Int として安全に扱えます。
- 他の選択肢 Protocol名: Int は protocol ではなく具体的な型（struct）です。
- 他の選択肢 関数名: 関数ではありません。`Int("3")` のように書けば初期化の呼び出しになりますが、ここでは型として使われています。
- 他の選択肢 access level: アクセス制御は private や internal などのキーワードで指定します。型引数とは別の概念です。
- 覚えておくこと: `Array<Int>` の Int は要素の型を決める型引数。`[Int]` と同じ。

## 30. associatedtype・any・some [Intermediate]

概要: Protocolを値として扱うexistentialと、具体型を隠すopaque typeを区別する。
考え方: `any P`はP準拠値を入れる箱、`some P`は具体型を1つに固定し外から隠す。

重要ポイント:
- associatedtypeで関連型を抽象化。
- any Protocolはexistential。
- some Protocolはopaque result type。
- some Viewは代表例。

コード:
```swift
protocol Store{associatedtype Item;func load()->Item}
func makeView()->some View{Text("Hello")}
```

なぜ重要か: SwiftUIやmodern Swift APIで頻出。
注意: anyとsomeは型情報の扱いが異なる。

確認問題:
Q1. some View の説明は？ [Intermediate]
```swift
func makeView()->some View{Text("A")}
```
A. 毎回異なる型可
B. 具体型を隠しつつ1つの具体型
C. Anyと同じ
D. Optional
正解: B
解説: opaque typeは実装側で具体型が固定。

詳しい解説:
- 用語・考え方: `some View` は opaque type（不透明型）です。「View に準拠した何か 1 つの具体的な型を返すが、その型名は呼び出し側に公開しない」という意味になります。実装側では具体型が 1 つに固定されている点が重要です。
- 正解になる理由: 呼び出し側は「View である」ことだけを知り、内部の複雑な型名を意識しなくて済みます。一方コンパイラは具体型を把握しているため、最適化や型チェックが効きます。
- 他の選択肢 毎回異なる型可: 呼び出しごとに違う型を返すことはできません。すべての return が同じ具体型である必要があります。異なる型を返したい場合は `any View` を使います。
- 他の選択肢 Anyと同じ: Any は何でも入る型で、型情報がほぼ失われます。some は具体型が 1 つに定まっている点で大きく異なります。
- 他の選択肢 Optional: 値の有無を表す Optional とは無関係です。
- 覚えておくこと: some は「型名は隠すが、中身は 1 つの具体型」。

Q2. any P の意味は？ [Intermediate]
```swift
let value:any P
```
A. P準拠値を保持できるexistential
B. Pを継承するclassだけ
C. Macro
D. static member
正解: A
解説: 準拠する具体型を包んで扱う。

詳しい解説:
- 用語・考え方: `any P` は existential type と呼ばれ、「P に準拠した何らかの型の値」を包んで保持できる型です。中身の具体型は実行時まで決まらなくてよいため、異なる型を同じ配列に混ぜて入れるといった使い方ができます。
- 正解になる理由: any は具体型を隠したまま protocol の要件だけを使えるようにします。柔軟な代わりに、包む処理の分だけ some より実行時のコストがかかる場合があります。
- 他の選択肢 Pを継承するclassだけ: P に準拠していれば struct でも enum でも保持できます。class への限定ではありません。
- 他の選択肢 Macro: Macro はコンパイル時にコードを生成する別の仕組みです。
- 他の選択肢 static member: 型自身に属するメンバーを指す static とは無関係です。
- 覚えておくこと: any は「P に準拠した何か」を包む。some は具体型 1 つに固定。

## 31. Type Casting・is / as? / as!・Any [Intermediate]

概要: 実行時の型を確認し、より具体的な型へ安全に変換する。
考え方: 静的型だけでは分からない値をruntimeで確認する操作。

重要ポイント:
- isで型判定。
- as?は失敗時nil。
- as!は失敗時crash。
- Anyは多様な値を保持するが型安全性が下がる。

コード:
```swift
let value:Any="Swift"
if let text=value as? String{print(text.count)}
```

なぜ重要か: UIKitやObjective-C連携、汎用dataで遭遇する。
注意: as!を安易に使わない。

確認問題:
Q1. 安全なdowncastは？ [Intermediate]
```swift
let value:Any="Swift"
```
A. value as! Int
B. value as? String
C. value is String!
D. value -> String
正解: B
解説: as?は失敗時nil。

詳しい解説:
- 用語・考え方: downcast は「より抽象的な型で持っている値を、具体的な型として扱い直す」操作です。`as?` は失敗する可能性を考慮し、成功すれば値、失敗すれば nil を返します。`as!` は失敗した場合に実行時に停止します。
- 正解になる理由: value の中身は実行時にしか分からないため、失敗を nil で受け取れる `as?` が安全です。if let と組み合わせて使うのが定石です。
- 他の選択肢 value as! Int: 中身は String なので Int への変換は失敗し、`as!` では実行時にプログラムが停止します。確実に成功すると分かっている場合以外は避けます。
- 他の選択肢 value is String!: `is` は型を判定して Bool を返す演算子で、後ろに `!` は付けません。この書き方はコンパイルエラーです。
- 他の選択肢 value -> String: `->` は関数型を書くための記号で、型変換には使いません。
- 関連例:
```swift
let value: Any = "Swift"
if let text = value as? String {
    print(text.count)
}
print((value as? Int) == nil)
```
- 関連例の出力: 5
true
- 関連例の説明: 成功すれば中身が取り出され、失敗すれば nil になります。停止せずに分岐できるため、型が不確かな値を安全に扱えます。
- 覚えておくこと: downcast は `as?` + if let が基本。`as!` は失敗時に停止する。

Q2. is の結果型は？ [Intermediate]
```swift
let r=value is String
```
A. String
B. Bool
C. String?
D. Any
正解: B
解説: 型判定結果はBool。

詳しい解説:
- 用語・考え方: `is` は「この値はその型か？」を判定する演算子です。判定の結果なので、返るのは値そのものではなく true / false の Bool です。
- 正解になる理由: 型を確認するだけで値は取り出しません。値も使いたい場合は `as?` と if let を使うほうが、判定と取り出しを 1 度で済ませられます。
- 他の選択肢 String: 判定の対象になっている型であって、結果の型ではありません。
- 他の選択肢 String?: Optional を返すのは `as?` です。`is` は判定結果だけを返します。
- 他の選択肢 Any: Any は「何でも入る型」で、判定結果の型ではありません。
- 覚えておくこと: `is` は Bool を返す。値が欲しいなら `as?`。

## 32. Access Control・Module・File [Intermediate]

概要: 型やAPIをどこから見えるようにするか設計する。
考え方: Access Controlは変更可能な境界を小さくし、安全にする。

重要ポイント:
- private/fileprivate/internal/public/open。
- internalが通常の既定。
- publicは他Moduleから利用可能。
- openは他Moduleからsubclass/overrideも許可。

コード:
```swift
public struct APIClient{
 public init(){}
 private let token="..."
}
```

なぜ重要か: Package分割、SDK、test、アプリ内部境界に重要。
注意: 全部publicにしない。最小限の公開を基本にする。

確認問題:
Q1. 既定access levelは？ [Intermediate]
```swift
struct User{}
```
A. private
B. fileprivate
C. internal
D. public
正解: C
解説: 通常internal。

詳しい解説:
- 用語・考え方: アクセスレベルは「どこからその型やメンバーを使えるか」を決めます。指定を省略した場合は internal になり、同じモジュール（アプリ本体やライブラリ 1 つ分）の中からは使えますが、外部のモジュールからは見えません。
- 正解になる理由: アプリを 1 つのモジュールとして作っている限り、既定の internal のままでもアプリ内では自由に使えます。外部に公開したいときだけ public を明示します。
- 他の選択肢 private: private は同じ宣言と同じファイル内の extension からのみ使える最も狭い範囲です。既定ではありません。
- 他の選択肢 fileprivate: fileprivate は同じファイル内に限定するレベルです。これも明示的に指定する必要があります。
- 他の選択肢 public: public は他モジュールからも使えるレベルで、ライブラリを公開するときに明示します。既定ではありません。
- 覚えておくこと: 書かなければ internal（同じモジュール内で利用可）。

Q2. openとpublicの違いの1つは？ [Intermediate]
```swift
open class Base{}
```
A. openは他Moduleからsubclass/override可能
B. openはprivateより狭い
C. publicはclass不可
D. 違いなし
正解: A
解説: openは継承/overrideまで許可。

詳しい解説:
- 用語・考え方: public は「他のモジュールから使える」ことを表しますが、class の場合は継承やメソッドの override までは許しません。open はさらに一歩進んで、他モジュールからの継承と override も許可します。ライブラリ設計における拡張ポイントの宣言です。
- 正解になる理由: public と open の差は「外部モジュールが継承・override できるかどうか」です。ライブラリ側が想定していない上書きを防ぐため、既定では public に留めるという設計になっています。
- 他の選択肢 openはprivateより狭い: open は最も広いアクセスレベルで、private より狭いということはありません。
- 他の選択肢 publicはclass不可: public は class にも付けられます。制限があるのは他モジュールからの継承だけです。
- 他の選択肢 違いなし: 同じモジュール内では差が見えにくいものの、他モジュールから見たときに明確な違いがあります。
- 覚えておくこと: open は他モジュールからの継承・override まで許可する。

## 33. KeyPath・Property Wrapper・Result Builder [Intermediate]

概要: SwiftUI周辺で頻出する高度な言語機能の役割を理解する。
考え方: 繰り返しpatternを型安全に表現する仕組み。

重要ポイント:
- KeyPathはpropertyへの参照。
- Property Wrapperは保存/取得ruleを再利用。
- @State等はWrapper構文。
- Result Builderは複数式からDSL構造を作る。

コード:
```swift
let kp=\User.name
let name=user[keyPath:kp]
```

なぜ重要か: SwiftUIの@State/@ViewBuilderを魔法ではなくSwiftの仕組みとして理解できる。
注意: wrappedValueとprojectedValue($)を混同しない。

確認問題:
Q1. \User.name は？ [Intermediate]
```swift
let kp=\User.name
```
A. KeyPath
B. Closure
C. Macro
D. Protocol
正解: A
解説: propertyを指すKeyPath。

詳しい解説:
- 用語・考え方: `\User.name` は KeyPath で、「User 型の name というプロパティ」そのものを値として表します。値を読み出した結果ではなく、「どのプロパティか」という情報を持ち運べる点が特徴です。sorted(by:) や map で `\.name` のように使われます。
- 正解になる理由: `\型.プロパティ` という記法が KeyPath の書き方です。後から `user[keyPath: kp]` のようにして実際の値を取り出せます。
- 他の選択肢 Closure: クロージャは処理のかたまりです。KeyPath はプロパティの指定であり、処理は含みません。
- 他の選択肢 Macro: Macro は `#` や `@` を使ったコード生成の仕組みで、記法が異なります。
- 他の選択肢 Protocol: protocol は要件の定義であり、プロパティを指す値ではありません。
- 関連例:
```swift
struct User { let name: String }
let users = [User(name: "Yuki"), User(name: "Aki")]
print(users.map(\.name).sorted())
```
- 関連例の出力: ["Aki", "Yuki"]
- 関連例の説明: `\.name` は「name プロパティを取り出す」ことを表す KeyPath です。クロージャを書かずに簡潔に指定できます。
- 覚えておくこと: KeyPath は「どのプロパティか」を値として渡す仕組み。

Q2. $value がWrapperで表すことがあるものは？ [Intermediate]
```swift
@State var value=0
```
A. projectedValue
B. 必ずInt
C. deinit
D. subscript
正解: A
解説: $はprojectedValueへのaccess。

詳しい解説:
- 用語・考え方: Property Wrapper は、プロパティに共通の振る舞いを付け加える仕組みです。`@State` などがこれにあたります。ラッパーは wrappedValue（本来の値）に加えて projectedValue という別の値を公開でき、`$value` と書くとその projectedValue にアクセスできます。
- 正解になる理由: `$` は projectedValue を取り出す記号です。SwiftUI では `@State var value` の `$value` が Binding を返し、子ビューへ読み書き両方の権限を渡す用途で使われます。
- 他の選択肢 必ずInt: projectedValue の型はラッパーの設計次第で、Int とは限りません。@State の場合は Binding です。
- 他の選択肢 deinit: deinit はインスタンス破棄時の処理で、`$` とは無関係です。
- 他の選択肢 subscript: subscript は `[ ]` によるアクセスの仕組みで、`$` とは別です。
- 覚えておくこと: `$value` は Property Wrapper の projectedValue。

## 34. Macro [Intermediate]

概要: コンパイル時にSwiftコードを生成するMacroを理解する。
考え方: Macroはcompile前に展開され、繰り返しcodeを生成する。

重要ポイント:
- #で始まるfreestanding Macro。
- @で付けるattached Macro。
- @Modelや#expectで遭遇する。
- 展開結果もSwiftとして型check。

コード:
```swift
@Model
final class Item{var name:String;init(name:String){self.name=name}}
```

なぜ重要か: 現代のApple開発ではMacroを使うAPIが増えている。
注意: runtime reflectionではなくcompile-time code generation。

確認問題:
Q1. Macroが動作する主なtimingは？ [Intermediate]
```swift
@Model final class Item{}
```
A. compile時
B. app終了後
C. Git push時だけ
D. tap時だけ
正解: A
解説: compile時に展開される。

詳しい解説:
- 用語・考え方: Macro はコンパイル時にコードを検査・生成する仕組みです。`@Model` のような attached macro は、コンパイルの過程で必要なプロパティやメソッドを自動的に展開します。生成された結果は通常の Swift コードとして型チェックを受けます。
- 正解になる理由: 実行前のコンパイル時に展開が終わるため、実行時の追加コストがほとんどありません。手書きの定型コードを減らしつつ、型安全性も保てます。
- 他の選択肢 app終了後: アプリ終了後に何かを展開することはありません。展開はビルド時に完了しています。
- 他の選択肢 Git push時だけ: Git の操作とは無関係です。バージョン管理の外側の話です。
- 他の選択肢 tap時だけ: ユーザー操作のタイミングではありません。実行時ではなくビルド時の仕組みです。
- 覚えておくこと: Macro はコンパイル時に展開される。

Q2. Swift TestingのMacro例は？ [Intermediate]
```swift
#expect(value == 3)
```
A. #expect
B. print
C. if
D. import
正解: A
解説: #expectはMacro。

詳しい解説:
- 用語・考え方: Swift Testing では `#expect(...)` を使って条件を検証します。`#` で始まる記法は freestanding macro（式マクロ）で、書いた式そのものをコンパイル時に解析し、失敗時にどの値がどうだったかを report できるコードへ展開します。
- 正解になる理由: `#expect` は macro なので、単に true / false を受け取るだけでなく、式の中身を分解して失敗内容を詳しく示せます。これが従来の assert 系との違いです。
- 他の選択肢 print: print は標準ライブラリの通常の関数で、macro ではありません。
- 他の選択肢 if: if は言語の制御構文です。macro ではありません。
- 他の選択肢 import: import はモジュールを取り込む宣言で、macro ではありません。
- 覚えておくこと: `#` で始まる呼び出しは freestanding macro。

## 35. Bitwise・Overflow・Custom Operator [Intermediate]

概要: 低levelやlibraryで出会う演算子機能を理解する。
考え方: 演算子も型に対して定義でき、bit演算では整数の各bitを直接扱う。

重要ポイント:
- & | ^ ~ << >>はbitwise。
- &+ &- &*はoverflow演算。
- 独自operatorを定義可能。
- precedence groupで優先順位定義。

コード:
```swift
let flags=0b0011
let mask=0b0101
let result=flags & mask
```

なぜ重要か: flag、binary形式、低level APIで遭遇する。
注意: 独自operatorの乱用は可読性を落とす。

確認問題:
Q1. & の役割は？ [Intermediate]
```swift
let r=0b0011 & 0b0101
```
A. 論理ANDと同じ
B. bitwise AND
C. 文字列結合
D. unwrap
正解: B
解説: bitごとのAND。

詳しい解説:
- 用語・考え方: `&` を数値どうしに使うと bitwise AND（ビットごとの論理積）になります。2 進数の各桁を突き合わせ、両方が 1 の桁だけが 1 になります。0b0011 と 0b0101 では最下位の桁だけが両方 1 なので、結果は 0b0001 の 1 です。
- 正解になる理由: Bool どうしの「かつ」ではなく、整数の各ビットに対する演算です。フラグの組み合わせを 1 つの整数で管理する場面などで使われます。
- 他の選択肢 論理ANDと同じ: Bool の論理積は `&&` です。`&` は整数のビット単位の演算で、対象も結果も異なります。
- 他の選択肢 文字列結合: 文字列の結合は `+` です。
- 他の選択肢 unwrap: Optional を外すのは `!` や `??` です。なお `&` は inout 引数を渡すときの記号としても使われますが、それは関数呼び出しの文脈での役割です。
- 関連例:
```swift
print(0b0011 & 0b0101)
print(0b0011 | 0b0101)
print(true && false)
```
- 関連例の出力: 1
7
false
- 関連例の説明: `&` と `|` は整数のビット演算、`&&` と `||` は Bool の論理演算です。記号が似ていても対象が違います。
- 覚えておくこと: `&` はビット演算、`&&` は Bool の論理演算。

Q2. 独自operatorで最優先は？ [Intermediate]
```swift
infix operator <+>
```
A. 短さ
B. 意味が明確で読みやすいこと
C. 必ずpublic
D. 常に使う
正解: B
解説: 標準的な関数より分かりやすい場合に限る。

詳しい解説:
- 用語・考え方: Swift では `infix operator <+>` のように独自の演算子を定義できます。ただし記号は名前と違って意味を説明しないため、読み手が推測に頼ることになります。定義するかどうかは可読性を基準に判断します。
- 正解になる理由: 独自演算子は、その記号の意味がチーム内で明確に共有され、関数呼び出しより読みやすくなる場合にだけ価値があります。判断基準は「短く書けるか」ではなく「意図が伝わるか」です。
- 他の選択肢 短さ: 短さ自体は目的になりません。短くても意味が伝わらなければ、読み手の負担が増えます。
- 他の選択肢 必ずpublic: アクセスレベルは公開範囲の設計で決めるもので、独自演算子の必須条件ではありません。
- 他の選択肢 常に使う: 常用すべきものではありません。多用すると、コードを読むのに独自ルールの学習が必要になります。
- 覚えておくこと: 独自演算子は「読みやすくなるとき」だけ。

## 36. Memory Safety・Exclusive Access [Intermediate]

概要: Swiftが不正なmemory accessや重複変更を防ぐ仕組みを理解する。
考え方: 自動memory管理でも、同じ値を同時にどう触るかには安全ruleがある。

重要ポイント:
- 未初期化/範囲外/解放後accessを防ぐ。
- inoutは長時間のwrite accessになり得る。
- 重複write accessを制限。
- 並行data race対策とも関連。

コード:
```swift
func balance(_ x:inout Int,_ y:inout Int){
 let total=x+y
 x=total/2
 y=total-x
}
```

なぜ重要か: Swiftの安全性の根本。inoutやConcurrency error理解につながる。
注意: 同じ変数を複数inoutへ同時に渡す等は許可されない。

確認問題:
Q1. Memory Safetyの目的は？ [Intermediate]
```swift
var values=[1,2,3]
```
A. 無効/競合memory accessを防ぐ
B. UI自動配置
C. 通信暗号化
D. Git conflict防止
正解: A
解説: Swiftはmemory accessの安全性を保証する。

詳しい解説:
- 用語・考え方: Memory Safety とは、解放済みの領域や範囲外の領域にアクセスしたり、同じ領域へ同時に矛盾した書き込みを行ったりすることを防ぐ、という保証です。Swift は ARC や排他的アクセスの規則によって、こうした問題の多くをコンパイル時または実行時に検出します。
- 正解になる理由: 無効なアクセスや競合するアクセスは、原因の追いにくい不具合やセキュリティ上の弱点につながります。Swift はこれを言語の仕組みとして防ぐ設計になっています。
- 他の選択肢 UI自動配置: 画面の配置は Auto Layout や SwiftUI のレイアウトの話です。
- 他の選択肢 通信暗号化: 通信の暗号化は TLS など別の領域の話です。
- 他の選択肢 Git conflict防止: Git の競合はバージョン管理上の話で、メモリとは無関係です。
- 覚えておくこと: Memory Safety は無効・競合するメモリアクセスを防ぐ保証。

Q2. swapLike(&x,&x) の問題は？ [Intermediate]
```swift
swapLike(&x,&x)
```
A. 重複した排他的accessになり得る
B. 必ず高速
C. Optional化
D. 問題なし
正解: A
解説: 同じmemoryへのoverlapping write accessになる。

詳しい解説:
- 用語・考え方: Swift は「同じメモリ領域への書き込みアクセスが重ならないこと」を要求します。これを排他的アクセス（exclusive access）と呼びます。inout 引数は書き込みアクセスにあたるため、同じ変数を 2 か所の inout 引数に同時に渡すと、重複した書き込みアクセスになります。
- コードの流れ: 1 つ目の引数として x への書き込みアクセスが始まる。
- コードの流れ: 2 つ目の引数としても同じ x への書き込みアクセスが始まる。
- コードの流れ: 同じ領域への書き込みが重なるため、排他的アクセスの規則に反する。
- コードの流れ: Swift はこれを検出して拒否する（同一変数と静的に分かる場合はコンパイル時に指摘される）。
- 正解になる理由: 重なった書き込みは結果が予測できなくなるため、言語仕様として禁止されています。値を入れ替えたい場合は標準の swap(&a, &b) を異なる変数に対して使います。
- 他の選択肢 必ず高速: 速度の話ではありません。安全性の規則の話です。
- 他の選択肢 Optional化: Optional 化とは無関係です。
- 他の選択肢 問題なし: 問題ないどころか、この書き方は許可されません。
- 覚えておくこと: 同じ変数を 2 つの inout 引数に同時に渡せない。
